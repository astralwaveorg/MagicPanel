# 节点命名与服务分流验收

## 节点名称

NAS 用固定摘要的 Subconverter 0.9.0 镜像，在无网络、只读容器内处理合成订阅。五条输入分别使用 SS、VLESS Reality Vision、VLESS XHTTP、Hysteria2 端口跳跃和 TUIC。官方镜像的 `target=clashmeta` 返回 HTTP 400；用 `target=clash&list=true` 只输出了 SS。该镜像不能充当正式构建的节点来源，未部署常驻服务。

MagicPanel 在构建时直接使用机场快照中保留的节点定义。只有订阅节点按地区编号。本地节点保留用户设置的名字（例如「🇺🇸 美国NTT 01」），不占用订阅编号。订阅地区名来自来源目录，不代表已验证的实际出口。跨来源统一编号，节点退役后保留号码。单个节点只显示地区，同地区多个节点时加序号。启用统一命名的构建冻结订阅节点快照，由面板重新构建更新；历史产物及其 provider 地址继续兼容。网络体检和导出使用同一套名称，检测记录仍按原有节点身份查询。已有策略组继续按原来的名称和顺序筛选成员，避免仅改名字就改变选路。

「构建发布 → 预览统一节点名」只生成构建。核对节点、组成员顺序和规则后可发布到测试环境。确认真实设备使用后，再启用「系统设置 → 统一节点名」让后续构建沿用。在部分客户端上，选中过的旧节点可能需要重新选择。

## 按业务确认候选

审计 ProxySoru 源码 `58a06c7`：README 的启动说明以 Windows 为主，内置 Windows Mihomo。Netflix 代码请求两个标题页，根据 HTTP 200 的数量生成片库结论，再用重定向路径和返回的地址推断地区及出口类型。HTTP 200 可能是提示页，非 200 也可能是临时限流，不能作为切换依据。此版未找到 Claude 或 Perplexity 的独立检测。可以参考其多样本取证思路；不引用其结论，也不引入另一套后台测速进程。

| 服务 | 进入候选的条件 | 回退条件 |
| --- | --- | --- |
| Google（含 Gemini、YouTube） | 该业务已有通过记录。美国自建优先，其次美国其他节点。普通延迟或 204 不代表整个 Google 业务可用。 | 保留原定美国 → 新加坡 → 日本；高档全部有新鲜失败证据才越级。 |
| 海外 AI | 逐服务确认。美国及日本自建为首选，按本服务响应速度择优，不拿其他 AI 结果补缺。 | 没有确认通过的节点时保留当前配置，标注证据不足。校验页、限流和过期记录不参与自动切换。 |
| Netflix 日本 | 漏斗前两关达标、Netflix 探测识别为 JP、自制剧和非自制剧样本均通过，记录还在有效期内。 | 地区未知、仅自制剧、校验页及过期结果均不入组。公开目录样本不证明实际播放。 |

「网络体检 → 节点质量 → 分流候选」显示近期确认的节点。构建会按当前方案和设备筛选候选。有合格的日本节点时，「Netflix」优先列出「Netflix 日本」，仍保留原地区组供手动切换。

生产构建 #327 的默认和移动方案中，Gemini 先命中谷歌服务，Claude 先命中 Claude；Perplexity 仍使用通用 AI 组。Disney+ 为新加坡 → 台湾 → 日本；Hulu 和 HBO Max 的美国集合排在通用影音集合前。Prime Video 主站走独立组，Amazon 商城仍走跨境电商。Bilibili 海外站走独立组，国内主站、京东和微信支付继续直连。上述结果来自订阅与规则缓存的域名匹配审计；路由器是否已经加载新版及账号登录或播放，需单独确认。

服务别名与基础节点共用代理参数。比如 `🇯🇵 日本 01 - Netflix` 仅表示检测过的非自制剧样本可见，播放和账号权限仍需客户端确认。生成别名需要近期的正向证据、性能达标和当前节点参数匹配；地区支持、HTTP 200 页面、人机校验或过期记录均不满足。构建输出对应的「已验证 · 服务」组，并保留基础节点和现有规则。没有证据的服务不生成空组。普通构建需要同时开启「统一节点名」和「构建时生成服务别名」；预览使用同一门槛。
