## 1. 已确认的产品约束

1. 海外 AI 保留一个通用前台策略；Gemini 复用既有 Google 入口，按美国→新加坡→日本回退，后台仍保留产品证据，不新增供应商前台组。
2. 所有**已获授权、协议受目标客户端支持**的来源参与能力评估。机场可以成为第一名，也可以作降级候选；自建、住宅、品牌或来源类型不自带永久加分。
3. 海外 AI 的比较顺序为：**服务可用性 → 信誉证据 → 稳定性与会话连续性 → 性能**。**AI 排名完全不使用价格、流量成本、免费额度或成本等级**，包括同分决胜。授权与供应商硬限额属于可执行约束，不是价格评分。
4. 当前没有住宅节点。只预留节点属性、设备授权和探测预算接口，不创建假住宅节点，不订购，不默认把未来住宅加入通配来源、下载、MATCH 或通用健康检查。
5. 全面检测、分类和排名默认**一周一次**。订阅抓取建议同步为每周一次，沿用未变化节点的有效证据；抓取不应暗中触发全量复测。
6. 最终模式**auto_stable_v1**：每周全量、地区日检、300秒当前路径哨兵，可信故障确认后有界复核备用并自动切换；健康不因排名变化换出口。具体频率/阈值/预算以共同策略为准。实施/灰度前仍关闭生产自动化，验收后启用本地受管恢复；自动整包生产发布独立默认off。核心外守护/DNS救援不依赖节点检测，禁隐形600秒全源递归测速。
7. 国内业务隔离为P0：单节点/全部节点失败或极慢、核心与DNS故障分别验收；国内DNS/bootstrap/DIRECT不等待代理队列。用户已选择核心整体故障时BASIC_WAN全屋原生WAN（含海外尝试）并告警；普通节点或Google耗尽不触发该模式。
8. 本轮保留现有方案的组/规则相对顺序及 `sort`，保留默认方案行为和订阅兼容。新功能先提供影子结果和可审查差异，不自动重排生产。
9. **Google 全业务严格按美国 → 新加坡 → 日本回退**；所有授权资源共同评估，任一美国可用即留美国，档内按业务可用性、IP 质量和稳定性排序；未知/未测/预算跳过不算整档失败。

### 1.1 家庭/外出运行目标与已知边界

家庭为杭州中国电信（CT），签约下行1000Mbit/s，上行用户观察常见60–80Mbit/s、峰值100；不能把峰值当稳定整形带宽。家庭R6S统一透明接管，NAS/Mac mini/Apple TV等不叠第二套日常代理；NAS检测临时核心仅供隔离worker。外出主用中国移动（CM）上的Android/MacBook/iOS实际客户端，MacBook按实际外网/移动热点单列；VPS不能代替CT/CM观察点。历史其他设备保留兼容，不强制重新启用代理。

WireGuard只访问家庭内网与明确家庭域，不是全流量出海出口；不加0/0或::/0，不抢默认WAN。首版透明方案为TCP redirect、UDP TPROXY及双栈，禁宽泛CN-IP提前旁路抢过域名规则；具体固定OpenClash能力、owner/mark/路由及SQM校准以家庭契约封包，不能在此另选架构。

DNS目标为AGH服务LAN/WG、dnsmasq负责本地/国内应急；大陆条件走独立国内上游原生WAN，其他/未知域走独立可信HK/KR加密DNS控制端点，全部不经Mihomo业务节点。HK/KR DNS角色不属于业务代理pool，待隔离部署、证书/鉴权和CT/CM真实可达验收，不能写成现有已运行能力。两个端点不合格则保旧并阻塞家庭迁移，不偷换成经core公共DoH。移动客户端按实际平台验证DNS控制面直达、条件解析和本机恢复能力，不能照搬家庭loopback或宣称所有客户端等价。

### 3.1 凭据和版本的事实源

`sources/local_nodes` 继续作为当前凭据编辑入口。节点清单保存身份和安全属性，不无约束复制密码字段。为了完整回滚，冻结的旧资源必须保存历史私密内容；这是受权限、留存和撤销状态管理的历史版本，不是第二套可独立编辑的当前凭据。

来源节点可以引用冻结来源版本和条目位置；本地节点修改产生新 revision。节点配置、传输参数、SNI、凭据发生变化后，旧检测不能自动证明新 revision 合格。仅展示名变化不得产生新的物理节点身份。

出口 IP、接入端点和故障域分开表达：同 IP 多账号/协议可以是多个 node_uid，但不是多条独立落地或独立带宽。中转入口不能被当成业务出口国家。轮换住宅未来需记录会话出口变化，不能只检测一次 IP 就标记“固定”。

### 3.2 元数据优先级

人工声明、自动观测和派生结论分别保存。人工锁定不篡改探测结果；探测与人工声明冲突时两者都可见。业务是否可用以对应范围的有效证据判断，不能让“家宽/自建”标签覆盖失败事实。名称推断只用于待确认分类，不能提升到已验证资格。

## 4. 稳定身份、typed refs 和命名兼容

### 4.1 身份对账

- node_uid 随机生成并持久保存，不取名称、入口 IP 或完整配置 hash。
- 本地数字 ID 一对一关联新 UID；现有数字 ID 继续有效。
- 来源优先使用可信上游稳定 ID。缺少时，结合来源 ID、规范化接入特征和受保护配置指纹对账；不能只按名字或 IP 合并。
- 凭据相关指纹使用服务端受保护摘要，不在公开 API 暴露可被用于猜测凭据的材料。
- 对账歧义形成候选清单，保留旧身份或建立新身份并要求审查；禁止随机挑一个继承旧检测、固定出口或设备授权。
- 暂时消失的来源节点退役并保留 tombstone；重现时按证据对账，不立即复用已分配给别人的名称。

### 4.2 引用格式

建议最小规范：

```json
[
  {"kind": "group", "ref": "同方案组ID"},
  {"kind": "node", "ref": "稳定node_uid"},
  {"kind": "builtin", "ref": "DIRECT"}
]
```

这是契约示例，不是可提交生产的配置。group ref 必须属于同一 variant；node UID 全局共享但受目标/设备/池授权约束；builtin 使用白名单。实际 API 可用数字 group ID，不能退回按全局名称解释。

旧 `proxies` 中的本地展示名，按迁移开始时的权威 `display_index()` 唯一解析；组名按同方案解析；无法唯一解析的行不猜测。保留原数组位置、去重结果和 `local_first` 的既有展开语义。旧来源 `use_sources` 与 filter 可以先由适配器生成等价输入，无需同期把所有历史组转换为自动池。

旧 API 的写入经服务层转换到新权威格式；若不能无损表达，返回明确的版本/兼容错误。新旧格式不能各自接受写入再“最终同步”。rename/delete/ref lookup/build validation 复用同一套解析器。

### 4.3 三个名字

| 字段 | 用途 | 自动变化规则 |
| --- | --- | --- |
| raw_name | 上游原名，帮助对账与排障 | 随上游记录，不改 node_uid |
| display_name | 面板展示和检索 | 可按经确认的分类规则生成，人工可锁定 |
| emit_name | 客户端出站标识、成员引用和记忆选择 | 首次迁移保留现名，之后只在显式命名变更中修改 |

重命名预演至少报告旧→新、冲突、引用组、受影响原名/后缀正则、inline 展开排序、客户端记忆选择和资源变化。preview 返回输入版本及 digest；apply 遇到期间数据变化返回 409，不能把过期预演直接应用到现状。

provider 与 inline 必须共用命名/资格转换流水线，明确“来源 filter 原名 → emit_name 分配 → 组过滤”的兼容位置。若新版 provider 已写入 emit_name，不能再让客户端重复追加 suffix。人工指定成员顺序不能因自动名称排序变化而改变。

### 4.4 幂等和保序验收

迁移执行两次，node_uid、引用、组/规则/方案顺序、sort、名称映射和输出均一致。启动迁移不得联网、测速、构建、发布、批量改展示名或重排用户行。需要人工解决的歧义可见并阻断受影响的新能力，不能改坏旧模式。

变更其他方案前后逐项比较默认方案的 ID、组/规则顺序和 sort。新增元数据不应改变既有默认方案产物；除脱敏接口或明确缺陷修复外，任何非预期字节变化都需要解释。

## 5. 检测证据、周调度和预算

### 5.1 证据不是一个布尔值

每项结果至少包含：node_uid/revision、服务项目和 detector_version、视角、路径指纹、目标目录版本、状态、reason_code、开始/完成/失效时间、请求/字节消耗、有限 evidence 摘要。执行器保存核心版本及二进制摘要。

业务结果区分 `pass/fail/unknown/inconclusive/stale`；任务取消、执行器失败和核心启动失败归任务错误，不自动记为该节点业务失败。403、429、验证码、未登录、付费墙与地区限制分别解释；匿名入口可达不能标成账号/API 付费能力完整可用。

AI 后台按产品留矩阵，UI 显示已验证覆盖、明确失败、未知比例和证据时效。新产品只有登记明确入口、检测范围和版本后才能加入；一个未定义产品不能继承其他 AI 的通过状态。若没有候选覆盖全部所需产品，输出最佳可用覆盖和缺口，不清空所有来源，也不静默直连或新建多组。

### 5.2 检测层级

| 层级 | 内容 | 自动范围 |
| --- | --- | --- |
| 本地结构 | schema、协议能力、名字冲突、引用 | 数据变化时运行，不联网 |
| 基础连通 | 有界冷连接、握手、204/有限请求 | 周批次或明确单节点事件，不额外频繁全扫 |
| 出口身份 | IP/国家/ASN、稳定出口和故障域关联 | 周批次，可在 revision/路径变化时受控失效 |
| 服务能力 | AI/流媒体/开发社交的有限检查 | 周批次；每服务有预算和有效期 |
| 有界性能 | 小体积持续传输、失败/恢复样本 | 按需/获授权；未来住宅默认不做大流量测试 |
| 真实体验 | 手机蜂窝、Apple TV 播放、路由器运行 | 明确验收或授权采集；NAS 结果不能替代 |

以上周批次是完整资格/信誉评估；地区日检、当前路径与事件恢复仅做受影响服务的必要连接/阶段复核，不把每个轻检查都升级成全产品深检。CT/CM、worker与客户端各自保留path/observer，不把同一请求免费复制到多个视角。

### 5.3 每周全评估与分级调度

- UI 明示执行时区、每周时间、下次运行、预计节点/请求/字节上限、最近结果与错过执行的处理。
- 一个周批次覆盖已授权来源和本地节点，允许小并发、分批和错峰；不能因此让同一批节点每小时重新入队。进程重启不会重置成“从未检测”后立即全扫。
- 重试属于同一 job，受同一预算和次数限制；目标故障、限流、断网时退避，不能造成多个来源同步重试风暴。
- 订阅建议每周抓取。若用户保留其他周期，需明确显示与检测周期的关系；相同内容不清空有效证据，变化节点标记待新证据，不能偷偷触发全池复测。
- 周期性分类/排名在周批次后更新；用户编辑策略可基于已有证据做本地 preview，零网络请求。手动检测、异常复核和额外排名明确记录触发者/原因，不伪装为正常周任务。
- 使用中的证据须有适配周周期的时效策略，避免默认一天 TTL 迫使每天全测。过期显示 stale，不能靠自动抬高频率偷偷解决。
- 本轮不改生产现有周期。开发时要区分已有用户值、软件新默认值与用户审定后的迁移目标，不能无提示覆盖数据库里的当前开关。

**周任务与客户端相位**：受管 R6S 在当轮新构建发布成功后同步一次配置和相应 revision，输入无有效变化不拉取。手机/Stash 默认 604800 秒内容更新，与中心错相可额外延迟近一周，计划证据年龄近 14 天；休眠更久必须显示未知。下载/加载陈旧状态与 §5.8 的证据时效分别显示。更快同步可独立开启建议 24 小时版本检查，默认 off；实际客户端缺少 HEAD/304 时可能是完整拉取，不标为已实现轻量协议。不得以中心周发布证明设备本周已加载。

上述off仅指额外内容版本同步，不是当前路径哨兵/故障恢复默认；本机已安装候选的恢复不等待下一次周订阅或NAS反向连接。

### 5.4 地区日检、当前路径哨兵与有界自动恢复

最终默认按共同策略§1–4：地区日检抽样，不以样本比例证明全地区/Google整档耗尽；当前路径哨兵只覆盖使用中或设备声明的有限常用路径，健康不测备用。可信事件一次异常先确认，同视角重试/退避/地区扩大及全局扩大阈值、限次、游标全部持久；控制目标/执行器/WAN异常为measurement_degraded，不淘汰全库。revision/出口冲突立即失效受影响证明，进入该scope有界复核，不等用户点测，也不全量重扫。

普通硬故障确认后先复核当前与最多两个备用，找到合格备用即停止扩大；按共同策略的退避、保持与防抖执行，健康不抢回，Google上档恢复例外按§4。手动锁/暂停保护明确scope，UI说明会暂停恢复；普通节点全部失败仍保持国内DIRECT/DNS独立。人工点测继续probe权限与预算预演；自动恢复使用已授权预留，不每批等额外人工批准。

纯planner只输出建议。04受管执行器重验selection revision、当前ref、scope、资格和锁，CAS后通过实际控制器应用并GET读回；失败不能标已切换。常规选择切换不重建/发布规则、DNS或核心，不批量终止既有连接。NAS失联时本地有效候选/预算可继续恢复，中心周发布不能代替手机本机执行。

现有600秒provider/组递归检查必须显式收敛，不能在auto_stable_v1之外另起全来源测试。核心外守护与DNS外部状态机独立持续运行，不能因节点预算耗尽、暂停自动选路或M5未完成而停掉国内救援；本轮仍不启用生产自动化。

### 5.5 探测路径与预算

`trust_env=False` 和 `direct_env()` 只排除环境代理，不能排除路由器透明代理。路径未知时结果可用于排障，但不能无条件作为 NAS 直连节点资格。保存 NAS/路由器/手机各自视角，不混合延迟分母。

全局、来源、出口故障域共享并发和速率管理；预算包括请求数、实际读取字节、总时间和核心进程数。job 完成、失败、取消均结算。未来住宅没有预算授权时标记“未授权跳过”，不发外部请求；这不产生 AI 成本扣分，也不能伪造通过/失败。

### 5.6 建议初始预算：供审查，不是实测结论

以下建议值为当前 **188 条来源记录 + 18 条本地记录 = 206 条节点记录**提供可估算的起点；不是独立 IP 数，也不表示已经对 206 节点实施检测。实际服务目录和检测器需在 preview 展示准确请求上界。后续调大参数必须有预算差异与理由，不让开发者自行恢复现有 16 并发或逐分钟全扫。

| 参数 | 建议初始值 | 约束与解释 |
| --- | --- | --- |
| 周批次与窗口 | 每周一 04:00，Asia/Shanghai；本轮墙钟上限 4 小时 | 到期未完成置 paused/incomplete，记录覆盖缺口；不翌日自动从头全扫 |
| 全局并行节点任务 | 4 | 同一节点同时最多 1 个外部请求；最多 2 个临时核心会话，共享节点集合，不是每节点启动核心 |
| 同出口/故障域并发 | 1；未知故障域先按来源限 2 | 同 IP 多账号不同时打同一服务；不得借别名绕过 |
| 全局 HTTP 速率 | 1 request/s，burst 2 | 跨执行器共享；这是上限，不要求不断发满 |
| 单服务与单目标 hostname 速率 | 各 0.2 request/s，burst 1 | 取更严格的桶；多域名同服务、同域名多适配器不能叠加绕过 |
| 基础连接预算 | 每节点最多 2 次；单次总时限 6 秒 | 包含一次失败重试；基础明确失败后跳过其后服务检查 |
| 服务 HTTP 时限 | 日检/哨兵/恢复按共同策略§6：connect≤4秒、单次≤6秒；深检大响应按adapter声明 | 总时限含TLS/读取，不按每次read无限续命 |
| 单服务节点请求数 | 默认每节点每服务最多 2 个 HTTP 请求 | 包含重试和重定向；需要更多的检测器必须在 preview 声明，不能截断后伪称完整能力已测 |
| 单请求小响应 | 日检/哨兵/恢复≤8KiB；例行深检原始/解码各≤64KiB、上传≤8KiB | worker流式硬限，Stash仅小端点/超时估算；超限不是节点失败 |
| 核心启动等待 | 最多 10 秒；同一会话启动失败最多再建 1 次 | 属执行器错误，不淘汰整批节点；会话失败计入任务墙钟/资源预算 |
| 深检周预算 | ≤8000 HTTP 请求、≤768 MiB 应用层读写 | 按连续 7 天计数，不因重启/删 job/新建批次清零；所有请求与重复读取均结算 |
| NAS/共享受管worker总池 | 30000请求 / 2.5GiB，连续7天；以共同策略§6为准 | 所有worker观察点共用，不按observer免费乘；子池均受总池，正常深检与扩大预留受保护 |
| 故障扩大检查预留 | 8000请求 / 768MiB，见共同策略§6 | 地区与全局共用，按已授权确认事件自动预约；不用人工点按钮才能救援 |
| 持续传输候选 | 所有业务/视角合计最多 12 个唯一候选；每候选 1 次，≤8 MiB、≤10 秒 | 全节点有限业务检查后选 top 候选，不给 206 节点全做下载；8 MiB 样本不宣称视频/带宽已完整验证 |
| 未来住宅未授权 | **0 请求、0 字节** | 授权后单独登记用途、供应商硬配额与探测子预算；没有暗含默认额度 |
| 地区日检 | 512请求 / 16MiB，见共同策略§1–2/6 | 独立故障域抽样、持久轮换；异常确认再扩受影响地区 |
| 当前路径哨兵 | 子限10000请求 / 96MiB，见共同策略§1/6 | 300秒，当前使用/声明路径；Google上档恢复附带请求亦计入，不叠加绕总池 |
| 定向事件恢复 | 512请求 / 32MiB，见共同策略§3/6 | 合并故障窗口，扩大scope改记扩大池，不能伪装普通事件 |
| 每台Stash本地执行器 | 10000请求 / 96MiB估算，见共同策略§6 | 与NAS分账并家庭汇总；无已核实流式截断能力，字节不是硬配额 |
| 手动点测 | 默认复用深检与总预算，不另开无限额度 | 若预算已耗尽，需要显式追加批准或缩 scope；按钮不能绕过预算 |

应用层字节是本系统可以测量和限制的 HTTP 读写，并非供应商账单的硬封顶。DNS、TLS、隧道和内核重传的实际链路开销另外报告；preview 对可测读写预留 **1.5 倍估算余量**，并标明这仍是估计。将来住宅的账单硬上限依赖供应商配额/独立凭据，不以此估算替代。

### 5.7 206 节点的容量模型与预算准入

为便于审查，假设服务目录暂有 **12 个适用检测项目**，每项目每节点上界 2 请求；基础最多 2 请求，出口信息最多 2 请求。该模型只含默认隔离 worker 的**一个视角**；额外视角、人工验收或额外服务另行预算，不能免费乘到全矩阵。12 是容量假设，不是已安装服务数量；Muse 等入口未确认的项目不计为已配置，更不发猜测请求。实际适配器需逐一声明请求和响应上界。

- 有限检查上界：`206 × (2 + 2 + 12 × 2) = 5768` 个 HTTP 请求；若都读满 64 KiB，响应体约 **360.5 MiB**。
- 最多 12 个持续传输候选再增加 12 请求、96 MiB，合计 **5780 请求、456.5 MiB 响应体**；按 1.5 倍预留，约 **684.75 MiB**，另核对请求/头部余量。基础失败会短路、同一事实可以安全复用时可能减少消耗，但不能预先假设全能去重。
- 该模型在建议的 8000 请求/768 MiB 深检预算中留有余量；它不证明实际检测器都能在两次请求内完成，也不保证 4 小时内完成。并发、速率限制、失败和目标 `Retry-After` 都会影响完成时间。
- 若目录扩大到 20 项且其余条件不变，仅有限检查即 `206 × 44 = 9064` 请求，超过默认深检请求预算；preview 必须阻塞整批准入或要求明确减少服务/节点/持续传输 scope、调整时间窗口或批准增加预算。不能边跑边在最后偷偷漏掉某个来源，然后称“全来源已检”。

准入预演展示总节点数/适用矩阵、每适配器最大请求与字节、剩余周预算、预计墙钟范围、必测/可选项、预算不足的具体项目。若单个适配器请求次数不可预知，按硬限额与“不完整”结果设计，不允许无限导航/下载。任何降 scope 都写入覆盖清单；本轮未覆盖的行保持 unknown/stale，不归入失败或降低来源信誉。

常规来源/规则抓取流量单独展示并受 fetcher 的限时/体积约束，不冒充节点深检；探测器不能经“抓取”入口发请求绕过上述探测预算。原始源文件超过准入大小时保留旧版本并报超限，不把内容截断后作为新节点/规则事实。

预算以来源/故障域/服务公平分批，避免“先来的机场测完，最后自建全跳过”形成系统性偏差。持续传输只用于已通过更高优先级条件的 top 候选；缺这项证据标记未测，不把其他候选直接判慢。硬预算触及时停止新请求、结算正在退出的请求并形成 incomplete 报告；不能自动借下周额度继续。

### 5.8 证据时效、故障确认与稳定切换

| 证据/状态 | 约束 | 不允许的推论 |
| --- | --- | --- |
| 例行周资格 | 完成7天内fresh、7–14天stale、超过14天expired；只保留未有反证的既有计划 | 周资格不等于当前路径健康，不用过期证据新晋升 |

## 6. 纯 planner 与指纹

### 6.1 输入和输出

planner 输入是一次冻结读取：指定 variant、target/device scope、节点 UID/revision、安全元数据、明确授权、有效证据集合、人工锁定、服务要求、runtime profile/version、上次已接受计划和显式 `evaluation_at`。需要判断 stale 时使用输入时间，禁止内部读取当前时钟产生不可重放结果。

planner 不查实时网络、不抓订阅、不测速、不调用 controller、不直接写组/规则/构建或发布指针。输入中不需要明文密码；渲染阶段凭 revision 读取私密配置。

输出至少包含主备节点 UID、最终出口/故障域、确定顺序、证据引用、被排除候选及原因、覆盖缺口、授权不足、空池行为、人工覆盖情况、plan_sha。不能只输出一个难解释总分。

### 6.2 AI 排名规则

先做授权、协议/平台支持、明确地区要求和服务证据约束，再按服务可用覆盖、信誉信号、稳定与会话连续性、性能比较。来源类别、名字中的“IEPL/家宽/原生”、价格和成本字段均不作为 AI 排名因子。

完全同等候选采用稳定 UID 等中性次序，不能用价格打破平局。人工固定持续生效，但已明确不可用时必须显示“固定项当前不可用”，按用户审定的保留/告警/降级策略处理，不能把失败改写为成功。

未来资源被供应商硬停机或额度耗尽属于当前不可用；平台不得以“价格高”为由降低正常可用节点的 AI 排名。授权/硬限额拒绝与评分解释应在 UI 分开。

Google/Gemini 在统一主题排序前应用严格地区档位：美国→新加坡→日本。只在当前应使用地区内按质量择优；YouTube 成本也不能让系统越过仍可用美国。Gemini 证据按实际 Google 路径记录。

### 6.3 四类指纹

| 指纹 | 纳入 | 不纳入 |
| --- | --- | --- |
| observation revision | 原始证据、执行时间、detector/core/path 版本 | 不直接用作自动发布开关 |
| eligibility_sha | 指定评价时刻下的稳定业务资格、必要来源版本、资格规则版本 | 原始延迟小幅变化、任务 ID、无关审计时间 |
| plan_sha | 实际主备/候选、emit_name、顺序、固定出口、作用域、空池与降级决定 | 不改变计划的观测明细、无关方案元数据 |
| build_input_sha | 冻结策略/计划/资源、有效源码默认值、renderer/schema/profile/兼容版本 | 构建创建时间、设备下载时间、随机任务号 |

原始观测变化而资格/计划不变，不创建构建。全局某节点变化但没有进入本方案计划，不应使其产物无故改变。renderer/defaults 变化必须改变构建输入，解决当前仅改代码自动构建不感知的问题。

设备实时 overlay 与 UA/base_url/feed URL 替换归分发 envelope，另算最终摘要；必须在 manifest 明确它们未冻结。若要提供完全冻结的设备配置，需选择冻结 overlay 模式，不能继续实时叠加却声称完整可重现。

相同输入得到相同计划及 YAML 字节；并列候选顺序显式确定。状态滞回、最小保持、冷却、连续失败/恢复采用 §5.8 的可审查初值及明确版本，并通过影子结果校正；它们是防抖策略，不是“连续 N 次即可证明任何服务健康”的结论。

### 6.4 Google 地区优先的编译与运行门禁

共同契约见[Google 选路策略](../../reference/Google选路策略.md)。注册 `google_family`、`country_order=["US","SG","JP"]`、覆盖 revision、候选全集、各档耗尽证据和当前档位。不能把单一 required_country=US 写死为用户要求，也不以最低跨区延迟选路。

递归展开 select/fallback/url-test、provider/inline 和代理链，保存每个候选实际地区、业务状态、视角、时效与拒绝原因。只有当前档全部适用候选明确失败才下移；unknown/stale/skipped、适配器故障或只测当前主备不足以证明耗尽。人工锁定和协议支持/授权约束显式处理，不能用“机场较脏”过滤全部美国后谎称已失败。

Google 规则优先于宽泛 AI/媒体；检查直接域、进程/端口、CN 快路、IPv6/UDP、FCM/邮件/Meet 与国家域/静态/CDN。第三方云客户作为负例，不能只看整个 ASN。国家基于目的范围出口；名称、入口和页面语言不是证明。

普通检测推荐非 Google 目标；美国、新加坡、日本均可执行有界 Google 专项。中心持久化地区计划，客户端仅检查小池时只作档内恢复；若要自主跨区 fallback，必须证明完整适用候选和服务可用性语义，不直接串三个地区自动组冒充整档判断。所有模式的实际限制如实显示，网关基础联网与普通业务降级分开验收。

测试至少覆盖：美国一个可用而新加坡更快仍美国；美国主备失败但另有美国未测不能跳档；美国全部失败才新加坡；前两档全失败才日本；三档全失败明确不可用而非普通 DIRECT。

## 7. runtime profile 不构成第四覆盖层

现有三层命名保持：引擎默认配置 → 引擎平台配置 → 设备独立配置。profile 是**运行职责与能力契约**，例如终端 Fake-IP 与 OpenClash 管理环境；不是用户可任意填写、最后深度合并的又一份 YAML。

profile 应规定哪些项由面板生成、哪些由客户端接管、哪些差异允许、哪些组合不支持。编译在建立既有基线时选择受控 profile 对应默认值，并让 UI 的 inherited/effective 采用同一 resolver；不能一边预览旧默认值，一边渲染另外一套 profile。结构键保护、DNS 写入范围、列表语义仍统一校验。

| 范围 | profile 应表达 | 禁止的简化 |
| --- | --- | --- |
| 终端 | 引擎/平台支持、DNS 模式、必要设备个性化、可用原生能力 | 把路由器 loopback DNS 复制到手机 |
| OpenClash | LuCI 管监听/透明接管等职责；DNS/嗅探最终 owner 和预期覆写 | 默认面板 Fake-IP 就是运行 Fake-IP |
| 混合所有权 | 每一组关键键的 owner、可接受转换和观测方式 | 任意递归 merge 后只看最终 YAML 有没有语法错误 |

保留 `(engine, platform)` 唯一。设备可引用 profile，目标提供默认；若 profile 改变渲染结果，构建必须生成该设备的专属产物，即使它没有显式组/规则 devices scope。构建矩阵、缓存键、manifest 和校验都纳入 profile ID/version。

若设计审查最终允许不同 profile 使用不同 DNS 源码基线，需要同步更新 `base_config_service` 的 resolver/schema、保存差异校验、preview、renderer、官方默认值核对和文档；不能通过 snippet/平台扩展绕过现有 DNS 硬约束。

### 7.1 基础联网模式与业务空池是正交状态

`gateway_state`与`pool_state`原契约保持，分别保存展示；DNS外部状态机另由owner回执/安全摘要表达，不把DNS_DEGRADED塞成节点失败或修改既有API字段含义。不能用一个fail-open/closed布尔值代替：

| 网关/业务状态 | 本规范的行为契约 | 必须留存的证据 |
| --- | --- | --- |
| 核心健康，业务池 READY | 按已接受计划和 MATCH 代理意图执行 | 实际加载与最终叶节点 |
| 核心健康，某业务池 EMPTY/EXPIRED | 该业务使用受控失败/最近可信保留政策，不静默退 DIRECT | 空池原因、保留时限与 UI 告警；不能触发全屋基础联网模式 |
| 核心挂起/退出且故障已确认 | 外部守护进入BASIC_WAN，全屋原生WAN含海外尝试并告警；DNS独立 | 按家庭契约/共同策略的撤接管与国内冷连接deadline；不是Google业务降档 |
| 核心恢复但尚未验明路径 | 处于 RECOVERING；按网络契约完成健康/规则检查后再恢复透明接管 | 防止反复接管/撤销的冷却与成功条件；不能借恢复启动节点全扫 |

用户已明确BASIC_WAN允许海外原生尝试，不再保留“海外绝不直出”的未定候选；该救援仅针对核心整体故障。普通业务空池、全部节点坏/慢或Google三档失败仍不静默DIRECT，不更改国内DNS。

### 7.2 版本化 DNS 意图与运行 owner 部署 bundle

家庭DNS目标已固定于家庭运行契约：AGH53→本地/PTR的dnsmasq、独立原生大陆条件上游，default/未知→HK/KR专用可信加密DNS；全部不经core/业务代理pool。首版real-IP，不向家庭终端发Fake-IP。HK/KR隔离DNS服务、证书/鉴权尚待部署与CT/CM验收，不把现有机器等同已部署端点。明确禁止旧“海外域→核心7874”目标回流。所有分派由同一类型化intent编译，不能手抄无版本清单。

家庭有独立于core/AGH进程的DNS外部状态机：单可信端点坏切另一；双端点坏进入DNS_DEGRADED，保留CN/本地分支，default临时国内应急并告警海外解析可信性降级；AGH坏把本owner DNS入口转dnsmasq国内应急，不靠AGH API自救。恢复确认、DNS epoch和缓存清理归同owner，不把失败缓存成长期NXDOMAIN。移动端必须按实际客户端验证可表达的条件解析、控制面直达与恢复，不能承诺路由器状态机已在终端存在。

这是交给受控运行 owner 的版本化部署资源，**不是第四配置覆盖层**。`runtime_profile` 声明 AGH/LuCI 的职责和 adapter 能力，现有基线 resolver 与业务编译器生成双方所需结果；禁止通过 `extra_yaml` 合并一段新 `dns:` 绕过统一约束。

| bundle 字段/对象 | 最小契约 |
| --- | --- |
| policy_sha / dns_intent_version | 规范化语义输入摘要、规则/集合实际内容 revision、模型版本；摘要计算不包含自身 hash 或部署时间，避免循环/随机输入 |
| 类型化 DNS intent | 精确域名与后缀分别表示，显式优先级、境外/国内/家庭例外、resolver/owner 引用；保留业务归属与审定理由 |
| Google 地区顺序 | country_order、当前档与完整耗尽证据、覆盖/资格版本、DNS/路由冲突；与客户端计划同版 |
| profile 与 adapter 能力 | profile ID/version、AGH 版本/能力集、adapter_version、条数/大小上限、支持与拒绝项 |
| owner 输出 | 受管 AGH 配置片段及必要 OpenClash 运行契约/检测样本；每份原始输出与规范化输出摘要；resolver 凭据只用私密引用 |
| 发布 bundle manifest | 同版客户端 artifact、DNS owner 输出、冻结规则/provider、目标设备与期望 predecessor revision 的关联 |
| 回执 | owner、expected/applied/verified revision、实际输出 hash、应用时间、有限自检结果/错误；未回执不得标成已加载 |

adapter 必须按其实际表达能力接受/拒绝 intent：`DOMAIN` 不能自动放宽成 `DOMAIN-SUFFIX`；具体子域例外的优先级不能被父域后缀吞掉。正则、关键词、进程、端口、IP/ASN 或无法等价转换的 classical 混合语义，不能冒充普通 DNS 后缀；需精化为经过审定的域名子集，或明确拒绝/报告未覆盖。IDN、尾点、通配符、本地域与解析回环也有确定的规范化与反例测试。

**共享 DNS 的方案冲突必须在编译期显式处理。** 同一 AGH 实例向多台设备/方案服务，不会因配置文件带 `?variant=` 就自动按方案返回不同答案。每份 owner 输出必须绑定 `owner_target + dns_scope`；同时启用的方案若对同一精确域/后缀有不兼容解析意图，禁止“最后发布者覆盖”。首期优先使用经审定的家庭共享 DNS 意图；确需设备差异时，只有已验证的 AGH client scope/独立客户端 DNS 能力才允许分域，否则阻塞部署。preview 列出对所有使用该共享 owner 的设备及未纳管 LAN 的影响，不能只报告本次选中的方案。

从 MRS/外部集合派生 intent 时使用**已冻结版本的实际内容**，必要时用固定版本转换器读取；不能临时下载“同名当前 YAML”充当历史等价物。大陆条件/本地、default未知的独立可信解析与bootstrap DAG必须无环；DNS端点必须直达且脱离业务pool，adapter不能把能力不足回落成整个域或核心上游。

跨面板/NAS/路由器的应用不是 SQLite 事务。bundle 生命周期至少区分 prepared、partially_applied、verified、rollback_required；部署前核对各 owner 当前 revision，应用后按输出 hash 和功能样本取回执。中途失败按已审定的安全模式保持或恢复，不能把“面板发布指针切成功”当作 AGH/LuCI 也成功。网络变更仍由生产迁移窗口与职责顺序控制，本规范不指定未经验证的跨机器原子切换。

共享 DNS 先于所有客户端完成更新时，还要验证保留窗口内旧/新客户端 bundle 与该 DNS 输出兼容；不兼容时阻塞无差别全屋下发，改用审定的范围/维护窗口。离线设备没有回执就显示未确认，不能为得到“整包完成”状态伪造成功。

回滚需要恢复同一旧 bundle 的客户端资源与 DNS owner 输出，并处理受影响缓存；不能只回退 YAML 却让 AGH 留在新语义。保留相关 owner 版本/adapter 兼容信息、回执和回滚所需私密输出，GC 保护范围与构建资源一致。

## 8. 客户端选择能力与中心自动化边界

| 类型/路径 | 能做到 | 不能据此承诺 |
| --- | --- | --- |
| select | 用户选择某个成员；可提供稳定推荐分支 | 成员换序会覆盖已记忆选择、服务失败自动换出口 |
| fallback | 按成员顺序选择健康检查认为可用的候选 | 204 活着就说明 AI/视频可用，或所有版本都会以完全相同方式恢复首项 |
| url-test | 按测试 URL 的延迟和容差选择候选 | 理解 AI 信誉/账号状态/解锁，也不能保证固定 IP |
| 中心周计划 | 周期性生成新主备并发布给后续拉取的客户端 | 手机离线、未刷新或后台受限时即时生效 |
| 受控 controller | 对支持且明确授权的在线设备读取/应用选择 | 自动拥有手机控制通道，或可随意连接全屋任何 controller |

Mihomo 的 [select](https://wiki.metacubex.one/config/proxy-groups/select/)、[fallback](https://wiki.metacubex.one/config/proxy-groups/fallback/)、[url-test](https://wiki.metacubex.one/config/proxy-groups/url-test/) 和 [Stash 策略组](https://stash.wiki/proxy-protocols/proxy-groups)给出了这些原生类型的边界。实际恢复、缓存选择和嵌套组行为仍需按使用中的核心版本验收，不能只靠字面类型名。

客户端前台可以保留一个可见 AI select，并提供稳定名称的“推荐”分支及手动主备；辅助分支可隐藏，规则仍指向可见组。推荐分支若代表中心计划，应落实到明确叶节点，不能再嵌入跨出口 url-test 把稳定性意图消解。改变内层单成员或受管映射后是否按计划加载，需要真实客户端测试；仅重排最外层数组不算实现自动应用。

auto_stable_v1通过本地受管执行器在面板不可达时使用有效候选/预算确认故障并切换，不能用固定叶select+中心周订阅冒充恢复。Stash逐平台要求cron、本机鉴权、指定叶复核、PUT后GET读回；不足先升级经测版本再验，仍不足保旧并阻塞该设备推广，不把手动fallback标完成。状态/冷却本机持久，secret不进公开脚本/订阅；脚本与私密恢复输入分别版本化，含完整Google scope。HTTP轻探针不证明任意视频分段/DRM或账号状态，保留一键报障入口；现有连接不承诺无缝迁移。家庭终端无日常Stash时由R6S承担恢复，不能强制加装客户端来绕过验收。

## 9. 资源 manifest、设备 ACL 与真正冻结

### 9.1 manifest 最小内容

每个构建包含按 artifact 分列的 target/device/variant/profile、规范化策略摘要、plan_sha、node UID→revision→emit_name 映射、provider/rule-provider 内容 revision 与实际内容摘要、有效默认值、renderer/schema/core 版本、校验结果、所需设备授权、允许实时叠加项。有受管 DNS owner 时，同时引用 §7.2 的 dns_intent 与部署 bundle、输出 hash/回执状态；资源冻结范围不能停在客户端 YAML。

公共 DTO 只暴露安全元数据和摘要；内部私密 manifest/资源容器可保存渲染必需的凭据引用。凭据不得进入公开 Git、审计 detail 或错误消息。构建详情不再无条件返回解密 snapshot；产物原文预览属于 reveal 能力。

### 9.2 冻结的定义

- provider：冻结**实际下发节点内容**、名称映射、资格筛选结果及必要 schema。不能只存 source 配置后在请求时读取最新 `snapshot_enc/test_results`。
- rule-provider：冻结原始 YAML/text/MRS 实际字节、format/behavior 和摘要。只保存 content_sha、等以后重新抓取并不保证可恢复。
- inline：节点定义和成员展开已固化，仍需记录 UID/revision 供解释与审计。
- 旧构建资源 URL 指向旧 revision；来源更新、停用、重命名不改变旧资源字节。主动撤销的授权/凭据是独立安全事件，不用“不可变”阻止撤销。
- ETag 基于最终返回内容/编码，而不是每次变化的延迟明细。相同正文不因为 80→82 ms 被迫重传。

资源采用私密临时写入、完整性确认后建立引用；发布前核对摘要与可读性。短事务管理数据库状态，慢渲染/校验/写大文件不持有长写锁。失败构建不成为可用发布包。

### 9.3 ACL 判定

新资源请求同时满足：设备 token 有效；设备允许请求方案/资源类别；该资源属于该设备可用的已发布或允许保留构建 artifact manifest；必要的昂贵资源许可仍有效。资源 ID/摘要难猜不构成授权。

ACL 在 config、provider、rule 资源入口一致执行。改变 `?variant=`、直接拼资源名、猜另一个 build/revision、访问旧别名均不能绕过。未来住宅不进入 legacy 按来源名任取路径；所有旧路径的兼容策略需要明确历史引用范围，不能继续给新昂贵资源开放全局下载。

测试/生产资源与旧客户端保留窗要有清晰规则：处于保留范围且仍获授权的旧客户端继续取得旧资源，避免 404 使客户端整份更新失败。授权撤销后，后续请求受控拒绝；已经缓存的节点密码无法被 feed 远程抹掉，必要时由供应商撤销专用凭据。

### 9.4 整包门禁与回滚

本轮保留全局一份生产、一份测试构建的状态机。新方案失效虽不阻止其他方案渲染，仍使整体失败；试验使用离线 preview/shadow 或经过审定的启用控制。若以后要逐方案独立发布，另立 release bundle/指针设计。

手动、自动、保存并构建发布和一键发布共用门禁，不能只在 scheduler 检测资格。门禁包含：完整产物矩阵、结构/引擎/资源语义、授权、计划质量、缺池行为、摘要和保留资源完整性。质量暂缺应给出明确阻塞/降级结果。

回滚必须选择能读到旧资源字节的 manifest；同时列出设备 overlay、profile 外部 owner 配置、OpenClash/AdGuard 变更和 provider/Fake-IP 缓存的独立恢复要求。回滚构建不等于撤销这些状态。已被供应商撤销的凭据不能通过恢复 YAML 复活。

GC 保留 live/test、允许回滚构建及客户端过渡窗需要的 revision；不因停用源删资源。新代码回退须验证旧代码读取新增表/列时安全，不用破坏性 down migration 删除身份/证据来“回滚”。

建议旧资源最低保留 28 天，并保护活跃设备实际引用；休眠客户端先更新 config 再读取新 revision。资源过期后的错误、旧配置缓存与刷新顺序需验证，不承诺已休眠数月的设备无需更新仍能读取所有历史资源。最低天数不替代凭据撤销与当前 ACL。

## 10. API、权限与安全 DTO

以下是接口契约方向，不是承诺的最终 URL 清单。沿用 `/api/v1`、会话和 CSRF；旧接口通过服务层适配。

| 接口族 | 返回/操作 | 安全与副作用要求 |
| --- | --- | --- |
| nodes list/detail | UID、三种名字、安全元数据、证据摘要、引用和版本 | 分页；不返回 params、完整 URI、订阅地址、任意 extra_yaml |
| nodes metadata patch | 人工分类、锁定、用途许可 | 乐观 revision；审计有限变更；不能篡改原始证据 |
| rename preview/apply | 冲突、引用、正则/客户端影响、计划版本 | preview 零写入；apply 拒绝过期输入；不自动发布 |
| probe-jobs create/status/cancel | 202 任务 ID、触发原因、范围、预算、结果摘要 | probe 权限；默认周计划；取消/重启行为明确 |
| pools/service-policies | variant 内策略与引用 | 按 ID 验证归属，不信任前端传来的 variant_id |
| routing preview | 冻结输入上的计划、缺口、拒绝理由 | 无外部请求、无构建/发布/节点选择修改 |
| build manifest/quality | 安全 manifest、业务变化、闸门 | 不嵌套返回私密 snapshot；原文另走 reveal |
| secrets reveal | 被授权对象的必要凭据/产物 | 明确动作、审计、no-store；普通 GET 不暗中 reveal |
| runtime read/import | 受限 schema 的运行摘要 | 限大小/字段/来源/时间；默认只读，拒绝任意 URL 代请求 |
| runtime apply | 明确设备和有限 controller 操作 | 与 read 分权、审计、版本前置条件；默认无权 |

最小能力集合建议：`view`、`edit`、`probe`、`reveal`、`publish_test`、`publish_prod`、`runtime_read`、`runtime_write`。现有维护者兼容映射应在迁移审查中说明；不能只把 role 文案放前端而不在接口和内部服务检查。

安全 DTO 包括：

- `NodeSummary/Detail`：has_credentials、参数名/schema、受控 server 展示与能力证据，不携带值；修改凭据采用明确 replace/keep/clear 语义，避免列表不再回显后编辑表单误清空。
- `SourceSummary`：复用当前 URL/request-header 脱敏模式；来源节点列表不嵌入原始定义。
- `BuildPublic/ManifestPublic`：安全摘要、资源版本、计划与验证；完整私密 snapshot 和 YAML 使用 reveal。
- `ProbeResultPublic`：reason_code、HTTP 状态/经过审查的字段、时间和有限摘要；不保留登录 Cookie、Authorization、完整响应网页或含 token 的跳转 URL。
- `RuntimeObservationPublic`：关键配置摘要、owner 差异、当前选择映射与时效；不把完整带密码运行配置、controller token 或全量连接历史发给浏览器。

供应商请求、自定义检测目标和 runtime 采集均需目标白名单、逐跳/解析限制、限时限体积、安全错误映射。现有 fetcher 可复用，但不能用“允许访问内网”开关把新 controller API 变成任意 SSRF。凭据揭示、生产发布和高成本探测都需要服务端授权与审计，浏览器按钮隐藏不构成保护。

## 11. 备份与恢复

完整归档另须认证加密：构建YAML可能含明文节点参数，排除主密钥与manifest MAC不提供保密性。01/Task3明确流式AES-GCM外层与独立派生密钥、先认证再解包、WebDAV只上传加密归档；主密钥独立保存。错key/篡改/截断和明文标记测试为必过。

公共策略快照与完整运行备份分开：

| 类型 | 目的 | 内容边界 |
| --- | --- | --- |
| 可入 Git 的策略快照 | 审查、保序比对、重现非秘密策略 | variants、组/规则、池/服务策略和必要安全 ID；列白名单；不含节点定义/凭据/令牌/私密资源 |
| 私密完整备份 | 灾难恢复和完整回滚 | 当前与历史私密资源、身份/别名、方案与授权、profile、manifest、必要证据/任务状态及所有引用；主密钥另按既有要求保管 |

必须补 `routers/misc.py:BACKUP_TABLES/RESTORE_TABLES` 的 variants 缺口，并检查 WebDAV 调用链及所有新增表/文件。恢复顺序包含逻辑父表 variants→组/规则/池/策略、节点→别名/证据/引用、build→resources/manifest/发布指针。不能只靠 SQLite 未声明外键就忽略逻辑关系。

备份记录 schema/version/table/file manifest 和摘要。新版本恢复旧备份须有受测兼容路径；缺少 variants 或新身份信息时报告可恢复范围，不按展示名猜测重新绑定。完整恢复验收必须在空测试数据目录完成，包括 secret key 可解密性、两方案引用、资源内容、ACL 和旧 URL；不能只验证 JSON 能解析。

## 12. 分层运行观测

必须分开显示“期望构建”“最后下发”“已确认加载”“业务验证”。现有 `last_config_at` 只代表配置本体下载，不证明加载；`last_pull_at` 还会被子资源更新，不能提升为生效证明。

| 层级 | 最小证据 | 未取得时的文案含义 |
| --- | --- | --- |
| 构建 | build/artifact/variant/profile、plan 与资源摘要 | 尚未构建/当前计划待发布 |
| 分发 | envelope digest、overlay revision、时间、客户端 UA | 未拉取/分发陈旧 |
| 加载 | 被验证来源报告的内核版本、运行配置摘要、资源 revision、选择值 | 加载状态未知，不写已生效 |
| 业务 | 时间/视角/服务样本、协议、规则命中、实际出口 | 未验证/有限样本通过 |

OpenClash 比较链是面板构建→订阅原件→LuCI 覆写运行文件→controller 实际状态。预期 owner 差异与未知漂移分开展示，DNS、sniffer、监听和 UDP 接管各自归因。报告原始配置前先脱敏；默认采集只读，不顺手改选择、刷新 provider 或重启核心。

## 13. M0–M5 验收规范

这些是审查后的质量关卡，不是本文件授权执行的生产操作。涉及 core 停机、DNS 故障和网络隔离的破坏性实验，先在隔离环境演练；生产验证须有明确窗口、恢复通道和当前授权。

### M0：基线、恢复与 P0 国内故障隔离

**必须证据**：当前各方案组/规则 ID、顺序、sort；目标/设备/profile 与外部 owner；生产/测试构建和资源引用；完整私密备份在空目录恢复；普通 DTO 不含明文凭据；探测路径是否可信。

**P0 故障矩阵**：

| 故障 | 必测内容 | 通过要求 |
| --- | --- | --- |
| 海外代理节点全部失效，核心仍运行 | 国内关键域名/API/CDN、家庭服务、国内 DNS、直连下载/支付样本 | 国内业务不被海外 DNS/代理依赖拖垮；海外失败可解释，无暗中直连 |
| 核心仍活，所有业务节点极慢/TLS或UDP黑洞 | 在代理请求/检测队列积压时持续发国内冷DNS、新源端口TCP/API/图片及本地请求 | 国内不等待海外超时、控制器或NAS；不能只测热缓存；不触发BASIC_WAN掩盖正常态缺陷 |
| 代理核心停止 | LAN DHCP/DNS、国内冷/热请求、残留接管 | 国内独立恢复，明确整体基础联网边界；不能靠核心内 DIRECT 声称通过 |
| Google 地区档位回退 | 美国仍可用/主备失败但其他美国未知/各档全部失败/跨区更低延迟 | 严格美→新→日，地区内择优；未知不算失败，不因普通节点失败触发全屋放行 |
| 境外 DNS 超时 | 国内首次解析和缓存解析分别测；正常家庭并发 | 国内答案不依赖境外上游成功，不进入循环/长串失败重试 |
| HK/KR可信DNS单失效/双失效，core与全部业务节点状态分别组合 | 实际TLS/答案对照、CN条件原生分支、default降级与告警 | 单端点切备；双端点DNS_DEGRADED且CN/本地照常，国内应急答案不冒充可信海外解析 |
| AGH故障/挂起或dnsmasq故障 | 独立owner状态机、DNS入口转移、DHCP/PTR单独恢复；不依赖死服务API | AGH故障有本地国内应急；dnsmasq故障不拖停AGH独立上游；恢复epoch/缓存与bundle一致 |
| WG连入/断开与双栈/MTU边界 | 家庭内网可达、AllowedIPs/mark/路由、外出客户端VPN槽与域名DNS | 只内网变化，不抢默认WAN，不把全部外出流量经家中代理；不强迫叠第二套家庭代理 |
| 代理双向满载与SQM | CT原生WAN/代理对照、qdisc/CPU/丢包、国内DNS和新连接 | 按家庭契约单独校准；国内不持续饥饿，报告差值，不承诺共享物理带宽满载时零延迟变化 |
| 重启/模式切换/旧 Fake-IP 缓存 | 客户端旧缓存、AdGuard 缓存、核心映射丢失后的新连接 | 旧合成地址不形成国内黑洞；模式/缓存恢复办法明确且实测 |
| 国内集合与宽泛 AI/ASN/媒体冲突 | 真实 payload 首命中样本，精确/后缀语义分开 | 审定国内样本落在预期直连；境外例外保持代理，不能整体提 cn 掩盖冲突 |
| QUIC/UDP 入口不一致 | 真实路由器 UDP 接管、应用 QUIC、节点 HY2 隧道分开看 | 处理发生在真实路径；不把拦应用 UDP443误作封死隧道/语音/游戏 |

记录冷/热DNS、新源端口成功率、足够样本下的延迟分位数、从同一注入时钟起算的撤接管/国内恢复、首命中与actual egress；门槛以家庭契约/共同策略为准，不把计划值写成测量值。核心停机、core alive但全部节点失败/极慢、DNS控制面失效三类都必须真实通过国内矩阵；任一失败即阻塞推广，不能靠一次切全屋DIRECT掩盖普通态缺陷。

### M1：身份、命名与迁移

覆盖上游仅改名、同名跨源/同源、相同 IP 不同协议/账号、凭据轮换、消失重现、对账歧义、人工锁定和节点改类型。实际通过 API 改本地名称/类型后检查 ID 数组与直接成员两种旧引用，删除也覆盖两条路径。

两次迁移结果一致；默认方案及其他未编辑方案 ID/排序/sort 不变；provider/inline 过滤和 suffix 语义一致；重命名 preview 与 apply 的版本冲突受测。无效引用不能被静默剔除后声称迁移成功。

### M2：检测、分类和 UI

验证auto_stable_v1周批次/地区日检/300秒当前路径哨兵、确认/退避/扩大范围的持久化；重启/重复事件不全扫，控制目标坏不淘汰全库。先staged无真实自动请求，04完成能力/网络验收后启用；自动整包生产仍off。材料/出口变化仅重评受影响scope；模拟429/challenge/unknown/取消/重启/预算耗尽和adapter失效，不靠改失败票凑阈值。

预算测试按 §5.6–5.8 初值验证：206×12 矩阵可预演、206×20 触发预算准入阻塞、降低 scope 必须确认且留下覆盖清单；时限/体积/解压上限/流式停止有效，重启/改 job 不重置周计数；7/14 天与 revision/path 立即失效行为可离线时间旅行重放，不为过期补一次隐形全扫。

上述scope确认指全量评估承诺的人工缩减；自动故障恢复在已授权scope内按预算分批，不每批等待人工批准。额外测试总池30000/2.5GiB与全部子池/未结算预约共享，Stash字节估算与worker硬截断分开展示；额度不足不影响国内DNS或核心外救援。Google完整耗尽与恢复证明单独按共同策略时效测试，不套周资格7/14日。

结果不混淆网络视角，unknown/stale 不当 pass；执行器故障不当节点失败。AI 一前台策略、后台产品矩阵清楚；未来住宅无授权零请求。普通 UI/导出/日志/审计不泄漏节点参数和响应凭据。

### M3：选路、产物、ACL 与冻结

同冻结输入重复运行，planner 与 YAML 字节一致。AI 测例要证明机场可胜过自建；改变价格/成本元数据不会改变 AI 排名或同分次序；明确不可用候选不因“自建/住宅”标签胜出。

验证固定出口递归到叶节点、合格机场降级、无全产品覆盖时缺口说明、空池不变 DIRECT、规则目标可见、有效 no-resolve 和 cn-ip 例外、payload behavior/format、关键国内/境外例外样本。

Google 专门矩阵覆盖全部资源类型、产品族与 FCM/Meet/邮件等依赖；验证美→新→日整档回退，只有美国小池失败不能跳档，三档全失败不变普通 DIRECT。Google 专项允许各档执行，通用与专项指标分开；第三方 GCP 为负例。

所有启用 variant×target×必要 device/profile 都校验；一份失败整包拒绝有清晰明细。构建后更新来源/测速/规则集，旧构建资源字节不变；回滚能读取旧内容。A 设备 token 不能通过改 variant/build/resource/name 取 B 未授权住宅；HEAD、304、preview 和旧资源保留均不绕过授权。

有受管 DNS owner 时，验证 policy_sha→intent→AGH adapter→输出 hash 的重放一致性；精确/后缀与子域例外的正反例、拒绝项、回环检查和输出大小门禁都必须通过。模拟一端应用成功另一端失败，不能显示整包已生效；回滚恢复同一旧 bundle，资源与缓存处理边界可追溯。

同一共享 AGH 上两个方案声明冲突时必须可复现地拒绝或使用经审定的共享语义；不能因构建顺序不同产生不同 owner 输出。设备 ACL 或 variant query 不得被误用为 DNS 上游的自动隔离机制。

### M4：真实设备与生产迁移证据

按家庭契约实际主用矩阵：家庭R6S透明的NAS/Mac mini/Apple TV，不叠代理；外出CM的Android/MacBook/iOS逐平台验DNS与本机恢复，家庭CT与移动CM分别记录。历史启用客户端仍验证兼容，不强迫重新安装。加载摘要/provider/叶节点/出口/owner可对应；GitHub分HTML/动态片段/raw/clone，媒体验证连续播放/续段/CDN/鉴权与冷连接，不能只测入口200。

在离线测试中复现 core/DNS/Fake-IP 故障矩阵；小范围真实迁移时完成受影响路径的相应验收。手机断开面板时，不得显示中心已经切换成功。验证旧构建+冻结资源+设备 overlay/外部 owner+缓存的完整恢复说明，并实际演练可执行的恢复路径。

### M5：有界自动化

在影子记录中证明延迟小抖动不创建构建，单个事件不全扫，重复事件去重，取消/重启不补发风暴；每次建议都解释节点/出口/国家/影响设备和证据。人工固定和暂停持续有效，自动化不会下一轮覆盖。

auto_stable_v1为用户已定最终默认，M5验证地区日检/哨兵/故障确认/自动切换和读回的实际闭环，不再等待另一次选择是否自动恢复。生产实施前仍staged，验收后启用；自动整包生产发布独立默认off，规则/DNS/core改动走整包门禁。核对总池与子池共享、保留深检/扩大额度、健康不换、主备连续故障仍可救援、Google完整scope及上档恢复。核心与DNS外部守护独立验证，不受节点预算或开关牵连。AI不计成本；P0国内隔离/ACL/完整回滚不满足则阻塞推广。
