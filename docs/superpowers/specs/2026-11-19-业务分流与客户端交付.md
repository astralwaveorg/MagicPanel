# 节点质量、业务分流与客户端交付

整理日期：2026-11-20。本文合并节点质量、命名、服务验收和 ZCode 交接中仍有用的内容。实现以代码为准，线上开关、发布指针和设备状态须实际读回。待改进项和未核实的风险见 [全域体检与优化建议](2026-11-20-MagicPanel-全域体检与优化建议.md)。

## 探测口径

- 节点从已保存的来源快照和本地节点进入候选池。公告、到期和流量提示不参与测速或构建；刷新失败保留最近一次有效快照。内联节点随构建下发，动态 provider 由资源入口下发，两者按各自作用域与配置验证。
- [节点质量漏斗](../../../server/app/services/quality_funnel.py)先查延迟，再测完整样本的下载速度，最后检测服务。早期草案的 600 ms 后续按用户要求放宽为 **低于 3000 ms**，与 [源码默认值](../../../server/app/config.py)一致；吞吐默认至少 **2 MB/s（16 Mbps）**。不完整样本单独记录，不能判为持续限速；生产实际阈值须读回。
- 同一批次用一个隔离 Mihomo 核心逐节点切换；同节点的平台请求可有限并发。网络错误、超时或 5xx 可有限重试，429、人机校验、地区拒绝不追加同类请求。周期质量漏斗默认关闭；启用后优先于旧版自动解锁。两者共用工作位，并与节点来源自动测速互斥；每类任务成功后至少间隔 5 分钟，连续 3 次执行报错后冷却 30 分钟。全量任务总预算与取消仍是[待办](2026-11-20-MagicPanel-全域体检与优化建议.md#优先修复的风险和验收条件)。
- 质量测速、服务证据和周期恢复是不同层。基础连通或吞吐通过不证明登录、对话、播放或账号权益；人机校验和不明 403 保留未知。对协议仅声称通过安装核心和真实样本验证的范围。旧证据必须核对节点版本与时效，参数变更后重新取证。
- 「当前网络」是浏览器视角；「服务器网络」从 NAS 侧测。只有可归属的控制器连接或同域诊断才能作为该服务的路径证据，通用出口另列参考。关闭进程代理变量仅排除显式代理，不能证明网关没有再次接管；无证据时报告「从 NAS 当前网络测得」或「出口无法确认」。

## 身份与名称

[节点命名实现](../../../server/app/services/node_rename.py)保留本地节点的自定义名称；订阅节点可按「旗帜 [机场代码] 国名 关键信息 序号」展示，序号按机场和地区编排。地区标签不是已验证的出口位置。组过滤保留兼容标签，因此改名须比较组员、顺序、引用和客户端旧选择。动态 provider 命名有独立开关，改动后可能在下次拉取直接生效；不要用正式开关代替预览。

服务别名与基础节点使用同一份代理参数，只消费近期、与当前节点版本匹配、符合业务判据的证据。构建时还检查节点属于当前方案和设备；普通构建依赖统一命名与服务别名开关。先预览再发测试，核对名称、成员、规则和终端选择。通用质量分类主要供面板诊断；不要把测试组当成默认客户端订阅的产品组。

## 业务路由验收

| 业务 | 需要保留或验证的条件 |
| --- | --- |
| Google、Gemini、Gmail、YouTube | 专项在宽泛 AI 和影音前。按 [Google 选路策略](../../reference/Google选路策略.md)走美国 → 新加坡 → 日本；上档完整、可信、未过期的失败证据才允许降档，未知不能当失败。构建报告只用于审核，运行切换另验。 |
| Claude、ChatGPT、Perplexity、TikTok 等 | 逐服务取证；限流、人机校验、消费级 IP 评分不支持自动改路。没有合格候选时保留原路线或用户手选。 |
| Netflix、日本片库 | 吞吐和延迟达标、当前版本有近期 JP 目录证据，且自制剧和非自制剧样本均通过，才进入 Netflix 日本候选。地区未知或只有自制剧不进入；公开目录不能代替账号实际播放。 |
| Disney+、Prime Video、Amazon | 默认和移动方案的 Disney+ 交付口径为新加坡 → 台湾 → 日本。Prime Video 核对入口、API、播放域及原有手选备选；商城、AmazonCN 直连与用户显式规则保持各自路径。 |
| 其他地区、国内和独立策略 | 核对既有备用、Telegram、国内 Apple/Microsoft、家内 DNS、国内直连、移动方案、游戏 UDP 与设备作用域。媒体证据不应更改无关策略。 |

验收顺序：对齐镜像与发布指针 → 比对实际产物和对应版本的规则集 → 核对主要业务首命中、DNS、组员与作用域 → 用适用核心验证 → 测试发布 → 生产发布 → 客户端读回。服务端拉取记录与核心语法通过，均不能代替服务实际播放、登录或客户端加载证据。
