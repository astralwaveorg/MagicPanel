# 业务分流与客户端交付

Disney+ 已在生产构建 #319 独立分流。默认与移动网络方案都按新加坡、台湾、日本切换。把原生产和新版本的 40 份产物逐份对照，只有 Disney+ 的目标和专用组变化。R6S 从原订阅更新并校验配置，运行中的 OpenClash 读回「新加坡自动」。国内京东 HTTPS 和本地 DNS 抽样通过。策略快照见 `policy/snapshots/2026-11-19-disney-before.json` 和 `2026-11-19-disney-after.json`。

## 后续构建规则

- 通用的测速分类只在「网络体检 → 节点测速与解锁」显示，不向客户端生成「质量 · 达标节点」等组。
- 只调整已经存在的单服务规则，保持原有顺序、覆盖范围和其他目标。Netflix、Prime Video、Spotify、Twitch、BBC、Bilibili 海外版从通用「国际影音」拆出。缺少业务证据时沿用国际影音线路，用户仍可按服务手选已有地区线路。
- Netflix 日本只收有近期日本片库证据、通过测速且参数未变的节点。没有证据时保留普通 Netflix 分流；不会生成名为「Netflix 日本」的空组。
- ChatGPT 和已有 Claude、TikTok 专组有合格业务证据才使用该服务的节点。美日自建 AI 候选同档按业务响应时间排序。规则不为未知结果、限流或人机校验改路。Google（含 Gemini）、国内直连和 DNS 仍沿用现有规则；不能把连通测速称作 Google 整档业务耗尽证明。
- 基础节点保留短名称；服务别名共享代理参数。下载通过、网页有响应、IP 地区合适均不能单独生成别名。Netflix 片库样本也不能代替登录后试播。
- 「当前网络」检测由浏览器发起。仅当同域诊断支持跨域读取时显示该域名对应的出口 IP。点服务名可实际登录或播放。无法读取同域结果时，参考出口不能代替单项出口。

## 策略组检查口径

| 项目 | 判定 |
| --- | --- |
| 默认代理、自建优先、各地区与自动测速 | 保留用户的首选与后备；复查统一名称后成员、节点来源与隐私范围是否相同。 |
| 谷歌服务、人工智能、Claude、TikTok | 检查精确规则先于通用规则。谷歌现有美国主档及新加坡、日本备用按原配置保留；没有整档负证据时不得自动迁移。各 AI 平台独立取证。 |
| 国际影音、Disney+ 及其他单媒体组 | 检查只改相应集合目标。Disney+ 固定新加坡 → 台湾 → 日本。通过实际业务验证后才能对其他平台调整地区优先级。 |
| Telegram、即时通讯、海外社交 | 保留用户明确配置的 Telegram 独立线路及其他通讯选择。 |
| 开发工具、海外游戏、跨境电商、加密货币 | 保留各自策略和移动网络差异。游戏 UDP 后备不受媒体探测影响。 |
| 苹果服务、微软服务、路由回家 | 保留原策略，核对国内 Apple/Microsoft、内网和国内 DNS 仍按原顺序直连。 |

## 验收

一次运行后端测试、前端测试和构建。部署后先发测试，逐目标核对所有 DIRECT 规则、DNS 和其余规则，并用 Mihomo 核心校验。比较无法取得业务证据时的回退，再用真实设备读回配置。真实客户端播放、登录、连续复测的结果分别记录，测试脚本或合成结果都不能代替这些回执。
