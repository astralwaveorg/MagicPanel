## 1. 本次真正要交付的产品

将 MagicPanel 从“收集订阅、测速、拼接配置”迭代为**理解节点用途、保留检测证据、按业务生成可解释配置并核对真实生效结果的管理系统**。

目标体验是：加入一个来源后，系统能识别节点身份、规范名称、测量适合哪些业务、生成候选次序，并说明为什么这样选；来源更新、检测端点故障和轻微延迟变化不会让全家配置反复变动。用户仍可锁定节点、地区与预算，且可以回退。

这次设计包括代码、UI、数据库、基础配置、分流规则、探测网络、生产配置、VPS 传输与发布流程。**按阶段完成同一个闭环，不采用一次性替换所有配置的大爆炸上线。**

### 1.1 已确认的用户决策

1. **全屋透明代理与国内业务故障隔离是首要目标**：代理节点、海外 DNS 或代理核心异常时，已覆盖的大陆服务仍能通过独立的国内 DNS 与直连路径正常访问；海外按用途代理，未分类流量保留代理兜底。
2. 当前资源是自建机房与多个机场；住宅 IP 尚未采购，设计支持将来加入，但不依赖它才能运行。
3. **海外 AI 在前台保留一个通用策略**，包括 Claude、GPT、Grok 及后续产品，不按供应商拆出一排组；Google/Gemini 复用既有 Google 入口并遵守同一地区回退政策。
4. 所有已授权来源的节点都纳入轮转观测与排序。**先可用、再择优**，合适的机场可以成为 AI 主力或降级候选，不把“自建”当作永久高分证书。
5. 系统需要自动分类、重命名、解锁/能力检测、稳定选择和完整的体验解释。
6. 允许后续在必要时登录 VPS 优化；具体改动仍先经过本设计审查，再按阶段实施。
7. NAS 位于透明代理路由器之后，测速路径必须验证，不能仅凭清空环境变量宣称直连。
8. **最终目标为`auto_stable_v1`：周全量、每日地区少样本、当前路径哨兵、异常逐级扩大检测与合格自动切换，健康不换IP。** 所有频率、样本、扩大判据、预算和防抖以[自动恢复与检测策略](../../reference/自动恢复与检测策略.md)为唯一合同；实施/灰度前off，G7通过后默认启用日检和有界事件恢复，不藏600秒全量检测。规则/DNS/核心变更及整包自动生产发布仍独立off。
9. **AI 排名不考虑成本**，顺序为服务可用性、信誉信号、稳定性与性能。流媒体再考虑地区、持续质量和流量成本；住宅资源的用途授权与检测预算单独管理。
10. **Google 全业务按美国 → 新加坡 → 日本严格回退**。适用于家宽/住宅、机房、机场；任一合格美国候选可用就留美国，各档内再按 IP 质量、业务能力和稳定性择优。未知/未测不是整档失败，不能只因新加坡/日本更快而越级。

11. **成套网络切换最后进行**；前期只开放手册/备份/不执行的救援脚本/冻结更新调度等固定安全准备，其余用离线fixtures/独立observer验证。NAS升级前仍冻结R6S既有配置和全部资源，避免间接生效。

### 1.2 如何定义“基本完善”

验收以“关键业务覆盖、错误率、切换次数、检测开销、可恢复性”判断，不以规则数量或漂亮的节点总分判断：

- 国内服务有厂商域名族、API/CDN 与典型操作的回归样本；冲突可以自动发现并交给人审定。
- 海外 AI、流媒体、开发与社交各有适合其需求的候选池，而不是都交给一个延迟最低的节点。
- 测试结果记录执行位置、路径、协议、真实出口、时效，错误不会无声传播为错误选路。
- 不把 HTTP 200 写成“账号可用”，不把首页可达写成“视频完全解锁”，不把 ASN 写成“纯净住宅认证”。
- 候选全部失效时表现明确，不悄悄直连、不偷用昂贵住宅、不把检测器故障当全网节点故障。
- 发布与回滚覆盖产物、引用的资源和运行环境；能知道设备下载了什么、是否已确认加载。
- 核心退出/挂起、core健康但全部代理失效/变慢、海外DoH超时、OpenClash重启与防火墙残留均有大陆业务故障注入验收，不以“配置了 DIRECT”代替证明。

“全球所有服务永远畅通”无法由任何配置系统保证。这里将其落实为最大化可验证覆盖、发现变化、稳定降级和可解释修复，避免用无法兑现的标签替代真实体验。

### 实际拓扑与验收主次

家庭由R6S统一透明代理；NAS、Mac mini及Apple TV走家庭透明路径，不安装日常终端代理。NAS为检测临时启动的core仅限隔离worker，不接管NAS常态流量。外出主用现有device 1 `iPhone-Stash`（target ios）、device 2 `MacBook-Stash`（macos）、device 5 `Android-Stash`（android）。Android target是实际数据；各平台版本/API/cron/脚本/本机鉴权/强制叶/选择读回由04分别预检，不能把iOS能力套给Android/macOS，也不能因印象否认Android。

G7首要真实验收为家庭R6S透明路径（含Apple TV）及上述外出终端的本地自动恢复。脚本/本地控制器等最低能力不足时先升级/适配再验收，不能以不支持或逐次手动切换标为交付。Apple TV不以安装Stash tvOS为家庭联网前提。旧Mac mini/TV与Windows等他人兼容target保留，不按久未拉取删除；按实际用途维护兼容，不误当主用外出设备。

WireGuard只用于外出回家访问NAS/路由器等内网，保留明确内网AllowedIPs；不是全流量出口，不承担普通海外代理或蜂窝恢复。回家可达与本地代理恢复分别验收。国内故障全矩阵含core健康但所有代理节点失效/变慢，国内DNS、本地服务与DIRECT不得等待海外恢复；只有核心整体故障触发已批准的原生WAN模式。

## 2. 当前项目的能力与主要缺口

同日诊断清单中有 3 个来源、188 条来源节点记录、18 个本地节点、9 个引擎平台和 14 台设备；这是过滤前的记录规模，不是 206 个独立出口。默认方案 34 组，自建美日方案 7 组，不以旧文档的静态组数覆盖现状。

| 现有能力，应保留 | 缺口，必须补齐 |
| --- | --- |
| FastAPI + SQLite + Vue，部署规模合适 | 不需要换技术栈；需要清晰的节点资产、探测、计划与发布边界 |
| 多来源、本地节点、provider/inline 两种分发 | 来源节点缺乏稳定 ID；名字参与测速和引用，自动改名容易破坏现有数据 |
| 方案隔离、平台/设备作用域、基础配置三层 | 只有组/规则分方案；能力事实可共享，选路意图与结果必须按方案隔离 |
| 临时 Mihomo 测速、抓取失败保留旧数据 | 主要测 NAS 的 204 延迟；本地节点没有同等的周期检测，不能证明解锁、信誉和持续播放 |
| 构建校验、测试/生产发布、资源停用保护 | 发布仍是全矩阵整包；规则/provider 内容会变化，回滚 YAML 不等于完整回滚 |
| 用户精心维护的组/规则顺序 | 当前顺序中存在语义冲突，需要局部修复；不能自动整体重排 |
| 加密存储、登录/CSRF、审计 | 普通本地节点列表和构建详情有解密字段返回；新住宅资源还缺设备/资源授权边界 |
| 配置时效与拉取记录 | 下载不等于加载，缺少 OpenClash 覆写、真实候选和业务路径的对照 |

当前 JSON 备份清单还遗漏 `variants`。身份与自动化落地前，先验证完整恢复；策略快照不包含凭据，不能替代运行备份。

## 3. 路线选择

| 路线 | 收益 | 代价与局限 | 结论 |
| --- | --- | --- | --- |
| 只重写 YAML/增加正则与节点后缀 | 可以较快修正眼前错误 | 仍无稳定身份、业务证据、成本和回滚，来源变化后继续漂移 | 作为第一阶段修复手段，不作为最终架构 |
| **保留现有系统，补统一资产、检测、策略计划与生效闭环** | 复用已有编译/发布，兼容 Stash，能力与决策可解释 | 需要分阶段迁移，先解决身份和探测可信度 | **推荐** |
| 整套换成上游 YAML、Sub-Store 或 Smart 内核自动决定 | 可快速得到更多处理器或动态选择 | 引入另一套状态；无法自动理解住宅成本、账号会话、国内例外，也无法统一 Stash | 借鉴组件；Smart 留作可选实验，非生产基础依赖 |

## 4. 三类节点怎样分工

### 4.1 分类不能只有“住宅 / 机房 / 机场”一个字段

三类是运营资源视角；实际选路至少需要这些独立维度：

| 维度 | 例子 | 谁提供事实 |
| --- | --- | --- |
| 管理来源 | 自建、机场订阅、文件、未来住宅供应商 | 管理员与来源 |
| IP 属性声明 | hosting/ISP/疑似住宅、共享/独享声明 | 数据商和管理员，保留出处与置信度 |
| 接入能力 | VLESS、HY2、Trojan、SOCKS、HTTP；UDP/TCP | 协议配置与路径实测 |
| 真实出口 | IPv4/IPv6、地区、ASN、随目的站/时间变化 | 指定节点上的出口和服务观测 |
| 服务能力 | AI 入口、挑战、地区信号、Netflix 目录、GitHub API | 带版本的检测器与人工体验确认 |
| 稳定性 | 冷连接失败、持续传输、抖动、连续故障 | 时间序列，按执行位置区分 |
| 成本约束 | 月流量、来源共享额度、计量方式、允许用途 | 供应商/管理员，估计值须标记 |

“机场”不等于不可用于 AI，“机房”不等于一定干净，“住宅”也不等于不会被识别或能登录。检测到的事实与人工分类同时保留，有冲突时显示分歧。

### 4.2 推荐业务分工矩阵

| 用途 | 默认选择原则 | 自建机房 | 机场 | 未来住宅 |
| --- | --- | --- | --- | --- |
| Google 全业务，含 Gemini/Gmail/YouTube | **美国 → 新加坡 → 日本**，整档确认失败才下移，档内按可用性/信誉/稳定性选择 | 在各地区档内按事实参与 | 与自建同标准参与，不按来源永久降权 | 按用途授权后参与；大流量仍单独控制 |
| 海外 AI，统一策略 | 可用覆盖优先，其次信誉信号、稳定性、地区与会话、性能 | 重点测试与运维；通过实际能力参与排名 | 通过检测即可参与，不永久排在自建之后 | 显式授权后按需补位，不自动承接全部 AI |
| Netflix/Disney+/其他大流量播放 | 具体服务与版权地区合格，再看持续吞吐、稳定与费用 | 解锁且稳定即可主用 | 适合高流量，只要该服务的地区能力合格 | 默认禁用于大流量播放 |
| TikTok/Reddit/社交 | 服务可达、挑战信号、地区与会话稳定 | 经验证的稳定出口适用 | 合格即可选择，避免随机跨国跳动 | 仅管理员明确允许的用途，不默认上传/直播大流量 |
| GitHub 网页/API、开发工具 | 域名族完整可达、少挑战、稳定 | 合格则参与主备 | 合格则参与主备 | 默认排除大文件、LFS、包下载 |
| 大型下载、包源、普通视频 | 可用、持续速度、额度与成本 | 可参与，但考虑自建共享配额 | 通常是主力候选 | 默认排除 |
| 一般出海/MATCH | 可靠的低成本机房/机场池 | 合格参与 | 合格参与 | 默认排除 |
| 国内业务 | DIRECT 与国内 DNS，保留少量明确的境外版本例外 | 不消耗代理 | 不消耗代理 | 不消耗代理 |

这里的“通常”不是硬编码的品牌优先级。例如机场 A 对统一 AI 的覆盖、挑战率和稳定性都比某个自建好，它应该排到前面；某个住宅出口失败，也不能靠“住宅”标签继续占据首位。

### 4.3 住宅接入与费用保护

未来可使用现有 HTTP/SOCKS/其他支持协议，不预设购买渠道；支持独立来源与单节点。先填写计量方式、地区、授权用途、检测上限与凭据撤销方式，再启用。

默认不进入通配来源、普通 MATCH、带宽测速、客户端通用 url-test 或 provider 健康检查；授权一个设备使用 AI，不等于授权整屋用它下载和播放。住宅节点可轮转参与低流量能力核对，但没有预算授权时显示“待授权/跳过”，不自动发外部请求。

MagicPanel 不承载业务流量，能硬限制自己的检测开销，能控制后续资源分发，**不能对离线客户端已获得的凭据实现真实费用硬封顶**。需要硬配额时，使用供应商限额/专用凭据，或另行设计受控网关；不把“从组里移除”宣传成即时撤销。

## 5. 节点资产与自动命名

### 5.1 三个名字、一个稳定身份

- `node_uid`：持久随机 ID，供引用、检测、人工锁定和候选计划使用。
- `raw_name`：来源原名，保留溯源；不因展示优化反写机场。
- `display_name`：面板友好名，允许跟随已确认地区/属性更新。
- `emit_name`：客户端实际识别名称，迁移初期保持原样；只在用户确认重命名计划后更新。

自动重命名模板建议为“地区 · 来源简称 · 线路/协议 · 序号”，碰撞时增加稳定短 ID。不把“刚测到 90ms”“今天解锁 NF”“信誉 92”写进持久节点名；这些信息显示成独立标签，避免每轮检测都让客户端失去记忆选择。

例：`🇺🇸 US · 自建NTT · VLESS · 01` 与 `🇺🇸 US · 机场A · HY2 · 07`。地区未确认时写“地区待核对”，不通过名字包含 US 就盖章“美国出口”。

重命名前显示原名→新名、撞名、受影响正则、组成员与客户端选择；apply 使用预览 revision，来源更新使预览过期则拒绝执行。来源与组的过滤顺序保持 provider/inline 等价。显式成员顺序和组/规则 sort 不因改名而重排。

### 5.2 同 IP 不合并为同节点

同一 NTT 服务器的 10 个账号/协议接入有不同身份和健康；可关联共享物理故障域与观测出口，但不算 10 个独立落地或 10 倍带宽。入口地址、服务端默认出口、特定目的站的实际出口分开保存；服务器可能有 WARP、转发或目的站分流，不能仅凭 server 地址推算业务出口。

## 6. 自动检测与可解释排序

### 6.1 检测分层

```text
配置/身份校验（零外部流量）
→ 路径可信度与基础连通
→ 真实出口、ASN/地区与稳定性
→ AI/流媒体/开发/社交的有限能力观测
→ 仅对有必要的候选做有界持续质量检查
→ 客户端加载和实际业务验收
```

全部现有已授权节点进入每周检测队列；每周对全部节点执行有界的身份、基础路径和适用业务检测，基础失败后停止该节点的后续请求。持续传输仅抽取有望进入主备的候选，住宅另受明确授权和检测预算约束。任务在维护窗口分批执行，不要求所有节点同时请求第三方服务，也不因任务拆批变成日常高频全扫。

“纯净度”在 UI 中改为**信誉信号**：住宅/hosting 推断、代理/VPN 检出、地区分歧、服务挑战、证据来源和时间。单个网站的匿名 403 不自动判“脏 IP”；单个 200 也不自动判“解锁”。

### 6.2 海外 AI 保留一个前台策略

后台检测矩阵按产品保留，是为了评估同一个 AI 策略的覆盖，不新增前台供应商组。新增产品通过服务目录登记域名、检测范围与适配器版本，仍进入同一个 AI 策略。用户提到的 Muse 尚未明确具体域名，实施时先确认产品入口再启用对应探测；不猜测为某个同名站点，也不让未知站点继承“AI 已通过”。

**Google 地区顺序优先于 AI 主题**：Gemini 在后台 AI 矩阵保留，但实际走 Google 的美国→新加坡→日本路径；其他海外 AI 仍为一个通用前台策略。各地区的证据按真实路径记录，不用通用 AI 组的任意地区覆盖 Google 顺序。

排序采用分层比较，不用一个无法解释的综合“纯净度分”：

1. 排除未授权、已停用、凭据无效、路径证据无效和基础连接连续失败的节点。
2. 比较已配置 AI 检测项的覆盖、明确限制、未知比例和新鲜度。入口、API 认证、实际账号能力的证据范围必须分开。
3. 在覆盖相当时比较近时成功率、挑战信号、出口/地区稳定、连接恢复表现。
4. 再比较性能；**成本不进入 AI 资格与排序**。来源类别用于解释和运维，不给自建无条件加分。未来住宅的用途授权在进入候选前检查，不把预算包装成 AI 质量得分。
5. 当前节点仍满足条件且差距不显著时保持，不因几毫秒变化切换。

结果显示“所选入口检测均通过”“部分入口可达”“证据不足”等，不能显示“全球 AI 完全解锁”。若没有同时覆盖所有已配置产品的节点，仍按可用覆盖给出最佳主备，并明确缺口；不因一个探测失败清空全部来源，也不悄悄直连。

统一策略通常选择一个稳定出口。它不能在不拆分具体目的站策略的前提下，让一个只支持甲服务的 IP 同时支持乙；本期接受这个真实边界，先提高覆盖和主备质量，不隐藏拆出多个模型专属用户组。

### 6.3 流媒体与 Apple TV

Apple TV 是设备，不是一个“解锁能力”。后台分别保存 Netflix、Disney+、YouTube、Apple TV 服务及用户实际使用应用的地区/入口/目录/播放证据。

Google 旗下媒体如 YouTube/YouTube Music/TV 也遵循美国→新加坡→日本，不为费用/吞吐提前跳过可用美国。其他媒体继续按自身版权地区选路。

- 先选服务与所需内容地区，再在地区内按可用、持续质量和成本选主备。
- 同一应用的 API、认证、静态、视频 CDN 尽量保持已审定的相同出口，不把整个共享云平台全部划入媒体组。
- 候选应含真正不同故障域的自建/机场；没有合格同区备选时明确提示，跨地区降级需符合该服务的设置。
- 不因住宅更“干净”而默认让电视流量走住宅。
- 无账号检测给出地区/目录线索；4K/HDR、DRM、登录权益和连续播放用 tvOS 实机验收，不用首页 200 代替。

首期保持已有国际影音入口；只有实际使用且地区差异需要时才增加服务入口，避免自动生成几十个无人使用的组。

### 6.4 社交、开发与一般访问

Reddit、TikTok 等采用稳定地区与出口；在发生明确故障时自动切换合格主备，正常时不为微小延迟变动而跳 IP。GitHub 的页面、API、脚本、头像与认证作为完整体验核对；只有确认可以独立处理的大文件下载才使用大流量池，不笼统地按 `githubusercontent.com` 拆下载。

一般出海可以使用更灵活的地区内自动测速与跨地区兜底；AI、媒体和账号服务的选择规则不套用到所有普通流量。

### 6.5 检测器不是永远正确的裁判

状态至少区分正常证据、明确拒绝、认证所需、挑战、限流、未知、过期、跳过和用户确认。HTTP 401/429、页面改版、任务被取消、测试核心退出不能都写成节点失败。

如果同一适配器在多个独立出口同时异常，优先怀疑探测器/服务整体变化，熔断这一类自动淘汰，保留上次有效计划并报警。没有验证码破解、挑战 cookie 收集或真实用户会话复用。

## 7. NAS 测速路径：作为资格排序的前置条件

**去掉 HTTP_PROXY 并不等于避开 R6S 透明代理。** 既有代码已经去掉显式环境代理，但不能替代路由器层的验证；查看一个出口查询站也不够，因为该站本身可能被业务规则强制代理。

推荐设置一个独立的 NAS 探测 worker：管理流量走内部 Docker 网络；探测出站使用路由器可识别的独立源 IP/受控 VLAN，由 R6S 在透明代理接管之前明确旁路。普通 NAS 仍可通过原来的透明代理抓取订阅与依赖。

此为最终目标，按新增“路由器最后”要求，前期不添加R6S旁路。使用离线/独立VPS observer并明确视角，NAS家庭路径保持待验证；实际旁路与路径资格在最后网络阶段验收。NAS前期只独立staging，不升级原生产feeds来间接改变路由器。

不以“只把当前节点 IP 加旁路”作为唯一方案：机场换节点/域名换 IP/IPv6 可能造成漏项，原本失败的节点可能借默认代理“假通过”。标准 Docker bridge 出站被 SNAT 成 NAS 地址也不算独立隔离。

每份排序证据要带 `path_epoch` 和执行视角：节点域名 bootstrap、探测目标 DNS、TCP/UDP、IPv4/IPv6、核心版本、路由配置。未经校验的路径只用于诊断，不进入自动排名或淘汰。NAS 原始路径、真实路由器消费路径和手机蜂窝路径分别保留，不用一个值互相覆盖。

同日追加审计已经证实一个机场 TCP 端点被 R6S 接管；机场快照中 166 个 TCP 节点，有 149 个按当前 IPv4 解析与集合会进入 redirect，11 个旁路，另外 6 个仅 IPv6 或当前未取得 IPv4。149/160 是可按 IPv4 判断的 TCP 端点规则覆盖率，不能当成逐个连接证实或节点故障率。现有 NTT 等部分自建端点确在旁路集合内，不一概作废所有历史观测。完整证据并入生产迁移草案。

实施与验证细节见生产迁移草案；不会为做测速把整台 NAS 简单设置为无条件直连，也不会替换路由器当前规则后就直接宣告解决。

## 8. 分流、DNS 与产物质量

### 8.1 先修复确定错误，再引入受管规则块

同日已证实的 `direct` 行为声明错误、宽泛 games 抢走国内游戏、前置 global-ai 的共享 ASN、TikTok 域名族分裂、QUIC 拒绝规则位置和 UDP 未接管，都进入第一批回归用例。

长期把服务语义记录成“国内业务、明确境外例外、AI、媒体、开发社交、一般代理、IP 补漏”等受管块，建立相对顺序和反例测试。用户现有手动规则与 sort 原样保留；受管块先在候选方案生成，不直接重排默认方案。

国内业务按完整厂商域名族和已审定集合优先直连。对 `cn` 与服务集合的冲突生成首命中清单，区分有意的国际版例外与误代理；不机械地把全部 `cn` 放到表头，也不因“云厂商”或整个 ASN 而优先代理已确认的国内业务。

Google 全业务规则早于 AI、媒体、开发、云服务商和国内泛集合；Gemini 不被宽泛 AI 抢走，YouTube 不被普通影音池改写地区优先级。保留 Google 优先的相对约束，局部处理 _direct_domains、DNS 与内核快路冲突，不整体重排。

### 8.1.1 Google 全业务的严格地区优先

共同规则见[Google 选路策略](../../reference/Google选路策略.md)：**美国 → 新加坡 → 日本**。任一合格美国候选可用就用美国，地区内再比较信誉、稳定性和性能；所有适用美国候选确认失败才进新加坡，新加坡同理。仅当前主备失败、未测、过期、限流或预算跳过都不能充当整档耗尽。

覆盖 Gemini/Gmail/YouTube、搜索、账号/OAuth、API、静态/头像/字体、邮件、视频 CDN、FCM/Meet、Google 自营接口和 Public DNS 等关联业务；不只三张首页，也不误吞第三方 GCP 客户。研究文档保存版本化产品目录和正反例。Gemini 复用既有 Google 入口，不新增供应商前台组。

国家以实际目的范围出口证据判定，不能只看名称和入口。允许并需要在美国、新加坡、日本候选分别做 Google 专项，通用健康仍推荐非 Google 端点以避免混淆指标。美国档仍可用时，YouTube 也不能为节流量提前换新加坡；AI 成本不参与排序。

中心每周计划与客户端实际恢复分开：若客户端仅测两个主备，就不能据此宣称全部美国都失败。默认只在当前地区内恢复；跨区由完整候选和已启用的有界复核决定。正常策略三档耗尽明确失败，整台网关故障的基础联网是另一状态，不能由一个 Google 探针失败触发。

### 8.2 基础配置与运行环境各有职责

- 保留“引擎默认配置 / 引擎平台配置 / 设备独立配置”三个名称，不新增第四个覆盖层。
- 增加运行配置档案，例如终端与 OpenClash；这是受控源码默认值的选择维度，不是在平台扩展里绕过 DNS 禁写约束。
- 终端继续按自身能力生成 Fake-IP/TUN；路由器明确 LuCI 与面板各自管理的字段。
- 国内 DNS 不依赖代理可用性；节点域名解析与业务域名解析分开；需要真实海外地址的流量有明确可信路径。
- 家庭网络采用独立真实IP DNS、redir-host+UDP TPROXY/双栈和明确故障处置；Fake-IP 保留终端/实验场景，必须通过相应故障矩阵。禁止只依据源码删路由器现有 fallback。
- 修复应用 QUIC 的接管与匹配位置，保留国内、游戏、语音和自建 HY2 承载所需 UDP。UDP/443 是实用近似条件，不等于全部 QUIC。

### 8.2.1 全屋大陆服务的故障边界

网络/DNS/WG/SQM唯一终态见[家庭网络运行契约](../../reference/家庭网络运行契约.md)。本轮已核实dnsmasq有效include没有回指core；普通UDP/IPv6实际从WAN直出、CN-IP提前return均有现场证据，不再写成待猜测的配置可能。

最终关闭宽泛CN-IP提前旁路，使用TCP redirect+UDP TPROXY与双栈同一owner。real-IP DNS不经过Mihomo/业务节点：国内/本地独立原生，default/未知走两个专用加密DNS控制面；杭州公共DoH原生直达测试未通过，不能直接抄公共地址。HK/KR角色部署、bootstrap/TLS鉴权/电信与移动验证是明确前置任务，不达标不切家庭DNS。家庭AGH的DNS_DEGRADED与外出客户端自己的DNS降级分别验收。

核心健康时，不论当前/全部US/全部SG与JP/全部业务节点失败或变慢，国内DNS与DIRECT不等待节点复核。核心退出/挂起/残留接管由独立coreguard恢复原生WAN；用户已允许该救援期间海外原生尝试并告警。单服务或Google全档失败不误触发全屋模式。缓存/共享IP/境外CDN国内服务/IPv6/UDP/私有DNS均有具体回归与失败停止线，不用规则条数证明覆盖。

全量Fake-IP不作为家庭目标，避免核心停后旧虚拟地址妨碍基础联网。未知流量已有明确MATCH与故障处置，不由实现者临时决定；服务新依赖进入版本化语料/差异门禁与精确修复，不能承诺静态列表永久穷尽全球服务。

### 8.3 自动排名不等于客户端会按这个排名选

`url-test` 会选测试 URL 的快节点，不会理解 AI 信誉、住宅费用或解锁。[Mihomo url-test](https://wiki.metacubex.one/config/proxy-groups/url-test/)

面板先生成业务合格池：普通业务可在池内继续自动测速；稳定会话业务优先固定到叶节点/固定出口的已验证协议主备。把自动评分排序列表塞入 url-test，再声称客户端按综合质量选，是不成立的。

客户端可以手动改变选择，现有连接也不会因换组自动迁移；UI 分别显示计划与实际结果。Stash、官方 Mihomo 和 Smart 分支分别验证，不能将 fork 独有字段发给 Stash。

### 8.4 空池不能静默变直连

Stash 官方说明空 provider 或空组可能退成 DIRECT，因此服务端只返回 `proxies: []` 并不安全。[Stash provider](https://stash.wiki/proxy-protocols/proxy-providers)

构建时保证必须代理组有明确的受控失败行为；创建新资源 revision 后也做非空验证，已冻结 revision 的字节不可修改。不能借“候选耗尽”偷偷放行 DIRECT，也不能把一个永远连不通的占位节点当健康候选。保留现有空组保护思路，按真实客户端版本测试其效果。

## 9. 自动化与发布闭环

```mermaid
flowchart LR
  A[订阅和自建配置] --> B[统一身份与版本]
  B --> C[隔离探测与证据]
  C --> D[业务候选计划]
  E[用户意图与预算] --> D
  D --> F[预演与影响差异]
  F --> G[构建与冻结资源]
  G --> H[测试验收与生产发布]
  H --> I[设备下发与加载观测]
  I --> C
```

检测、规划、构建、发布是四个独立动作。实施/灰度先影子验证，G7后默认启用`auto_stable_v1`；已批准作用域与候选中的合格同地区运行切换无需用户逐次干预，也不等于规则/DNS/核心变更或整包发布。“立即发布”仍不隐含昂贵全套检测。

延迟从 80ms 变成 82ms 不触发发布；只有有效候选或实际计划变化才考虑重建。每次建议解释新增/移除节点、出口国家、成本、作用方案和受影响设备。人工固定是持续有效的约束，自动化不得下一轮悄悄覆盖。

短暂检测失败先复核和降置信；明确硬故障才触发有界故障恢复。常规恢复有冷却，不立即抢回主力。全链没有候选时保留最近可信配置或显式失败，不能切到未授权来源。

现有整包发布状态机继续使用。新方案不能因“逐方案校验”就宣称可以独立发布；候选策略先离线/影子预演，通过后才进入完整矩阵和测试通道。

### 9.1 默认调度与故障恢复分开

| 动作 | 最终默认与阶段 | 触发和边界 |
| --- | --- | --- |

频率、抽样、扩大条件、预算与冷却只引用[自动恢复与检测策略](../../reference/自动恢复与检测策略.md)，本稿不维护第二套数值。旧地区url-test/provider health-check/OpenClash自动任务按同一策略清点迁移，不能新任务已限频而旧600秒全扫仍在。周内容更新与本地故障恢复是不同通道；手工锁定和地区/授权约束持续有效，自动恢复不自行放宽。

### 9.2 周发布与设备周拉取的相位

NAS 完成本周任务不等于手机已更新。受管 R6S 推荐由“本周新构建发布成功”触发一次拉取及其新 revision 资源更新，没变化就不拉；避免刚在构建前拉过一次又等整周。它仍是每周内容更新闭环，不额外加入频繁节点检测。

没有中心推送能力的 Stash/手机默认保留 604800 秒内容更新，可能额外延迟接近一周，使用证据年龄接近 14 天的计划；休眠设备更久则状态未知。UI 必须显示计划年龄、最后下发与加载状态，不标成“本周已生效”。如审查后要求更快同步，可单独开启建议 24 小时版本检查，默认关闭；实际客户端不支持 HEAD/304 时可能仍是完整拉取，不能宣传为已实现的低流量检查。

旧冻结资源推荐至少保留 28 天，并保护活跃设备实际引用；休眠设备先更新配置再取新资源，兼容窗和过期提示进入验收。多方案共享 AGH 时，部署按 owner_target + dns_scope 解析，无法同时表达的 DNS 意图应阻塞，而不是最后一次发布覆盖其他设备；详见工程规范 §7.2。

### 一个典型操作流程

```text
添加来源
→ 原始节点对账预览
→ 规范名称与分类建议
→ 执行预算内检测
→ 查看业务覆盖及不确定项
→ 预演主备与规则影响
→ 测试通道与指定设备验收
→ 发布生产
```

手工批量命名、分类、检测和发布分别有按钮，不把“保存来源”变成不可预期的网络任务。所有详情先给人能理解的结论，再展开证据，避免要求用户阅读原始 JSON 才能作决定。

### 10.1 三个关键界面的具体布局

以下是界面信息设计示意，不是已完成界面或当前节点检测结果：

**系统状态**首先放家庭业务状态：国内解析/直连、海外代理、当前网关模式、最后故障演练。没有演练证据时显示“未验证”，不能因为进程活着就显示“大陆零影响”。第二行放 AI 覆盖、媒体地区、开发/社交主备与最近业务确认；第三行才是节点数量、任务和资源统计。活动区分别显示“本周深检”“来源更新”“设备拉取”，不把三者混成一个进度条。

**全部节点**默认只展示必要列：

| 节点 | 来源与协议 | 实测出口/地区 | AI 覆盖 | 媒体地区 | 稳定性 | 证据时间/视角 | 当前用途 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 友好名，可展开原名与 UID | 自建/机场，协议标签 | 未核对时明确未知 | 通过/限制/未知项数量 | 按已启用服务显示 | 样本数与失败类型 | NAS/路由器/手机分开 | 主力/备用/手工/未采用 |

筛选包含来源、地区、协议、能力状态、人工锁定、退役与证据过期。点击节点打开抽屉，先显示“为什么采用/排除”，再显示时间线与有限证据；敏感定义须独立查看。批量命名先预演，批量检测先显示预计请求/字节上限，取消不影响已发布配置。费用字段在流媒体/资源详情使用，AI 排名解释不出现费用权重。

**策略组/服务选路**保持现有组顺序。选中 AI 时展示一套策略、产品覆盖矩阵、实际主备和稳定出口；选中媒体时展示服务、内容地区、同区备用与流量限制。每项都分清“建议”“已接受计划”“已发布”“设备已确认”，人工选择不会被后台一次建议悄悄覆盖。

**发布预演**首先显示国内路径与规则语义变化，其次是出口/国家/候选变化、流媒体费用影响、资源版本和设备范围；最后才展开 YAML diff。阻塞原因链接到对应规则、缺池、权限或不兼容字段。保存、检测、预演、创建构建、发布测试和发布生产沿用清晰独立动作，后台只读页面不顺便触发探测。

### 用户旅程与兼容迁移

- **添加来源**：保存先做本地校验；抓取、节点对账、命名预演、预算检测和候选建议分步完成。批量操作明确本页、已选或筛选全集，由任务固定作用域和版本。刷新失败保留最近有效版本。
- **改善服务与排查卡顿**：先看方案/设备、首命中、DNS、既有证据和候选排除原因。只读查询不触发出网。连通、服务能力、观察视角、未知、跳过、过期和真实失败分开；计划、下发、加载和业务确认分别展示。没有客户端回执就不标成已切换。
- **发布与回退**：检测、预演、构建和发布对应独立动作；预演展示国内影响、Google 档位、出口、资源和设备范围。请求按作用域和版本隔离，重复操作幂等；冲突时保留草稿并要求重新预演。回退还要核对引用资源、DNS owner 和缓存。
- **界面兼容**：保持既有页面和路由、三层配置名、规则与组相对顺序；用现有组件、窄屏抽屉和清晰键盘焦点。门户兼容历史 PIN 的显式提交，新 PIN 按现行规格创建。凭据走独立授权与审计；普通响应保持脱敏，编辑区分保留、替换和清空。
- **迁移边界**：保留技术栈与数据库，分步完成兼容、验证、切换和退役。旧资源和活跃引用按工程规范 §9 保留；API 退役按[核心数据与兼容迁移计划](../plans/2026-11-15-MagicPanel-V2-01-核心数据与兼容迁移.md)的版本与使用回执门槛。基础配置的有效值、预览、编译和分发共享解析口径。
- **家庭和外出分别验收**：安装版本、脚本、控制器、鉴权、强制叶及选择读回分别验证；不能以 iOS 推断 Android 或 macOS。家庭 R6S 和 Apple TV 走家庭透明网络，WireGuard 只回家内网。先保全旧订阅的精确字节与引用资源，再按[家庭网络合同](../../reference/家庭网络运行契约.md)和[运行手册](2026-11-16-MagicPanel-V2-实施状态与运行手册.md)实施门禁；不要从 NAS 提前替设备应用网络变更。

## 11. 工程与生产交付分期

| 阶段 | 主要交付 | 不满足时不进入下一阶段 |
| --- | --- | --- |
| M0 基线与探测可信度 | 完整恢复验证、凭据接口收敛、路径审计、当前确定错误的回归集 | 没有恢复点、探测可能套代理、现网基线不清楚 |
| M1 节点身份和命名 | 统一 ID、版本、分类、别名、引用兼容、命名预演 | 改名会丢引用或重排、来源刷新不能稳定对账 |
| M2 能力检测与 UI | 分层检测、任务预算、出口/服务证据、所有来源轮转 | 结果混淆视角、未知被当通过、住宅仍被通用测速 |
| M3 选路与产物 | 统一 AI、多业务池、纯函数 planner、服务域名族/顺序、资源冻结 | 相同输入不稳定、空池直连、回滚不能恢复引用资源 |
| M4 测试与真实迁移 | 指定手机、Apple TV、R6S、VPS 分步验收与回滚 | 只有 NAS 测试成功、没有持续播放或加载证据 |
| M5 自动稳定恢复 | `auto_stable_v1`日检/地区有界扩检/事件恢复/合格同地区切换；G7后默认启用 | 缺本地执行能力、健康仍频繁换IP、隐形全扫、单业务失败触发全屋模式；规则/DNS/核心/整包自动生产发布仍独立off |

每一期都是可验收的增量。数据迁移启动时不发网络探测、不改用户 sort、不发布。首版不引入微服务集群、Redis、另一个订阅中台或必选的收费情报 API。

VPS 优化也分“测到的问题→对应改动→验证”：先比较同出口 TCP/HY2、冷连接与持续传输，再检查必要的服务配置、UDP、MTU、拥塞控制和资源瓶颈。不通用地重装所有 VPS 或再跑一遍一键优化脚本。

| D4 | Google 全业务优先于宽泛 AI/媒体规则 | Gemini 留 Google 路径；不静默整体重排 |
| D5 | NAS 独立探测出站，普通 NAS 与探测路径分离 | 需要一次受控的容器网络和 R6S 旁路变更 |
| D6 | 同一排序计划编译到多引擎，不依赖 Smart | 现用iOS/macOS/Android分别适配，其他target兼容保留 |

| D10 | 国内 DNS 与直连路径独立于代理核心；全量 Fake-IP 不作家庭迁移前提 | 以核心停机、挂起与海外 DNS 失效实测决定 OpenClash/DNS 终态 |
| D11 | 用户已确认核心整体失败允许原生WAN，含海外并告警 | 外部coreguard撤故障接管；普通Google/业务故障不触发全屋模式，恢复与预算按canonical |
| D12 | R6S 随本周新发布同步；手机默认周拉取并明确相位延迟 | 更快的版本检查须单独开启，不能把中心发布当设备当周已加载 |
| D13 | **用户已澄清：Google 美国 → 新加坡 → 日本** | 只有整档适用候选确认失败才回退；档内择优，未知/跳过不算整档失败 |
