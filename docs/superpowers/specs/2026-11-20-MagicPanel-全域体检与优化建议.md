# MagicPanel 全域体检与优化建议

复核日期：2026-11-20。代码基线：`main` 的 `c99d235`，复核时与 GitHub `main` 一致。策略依据为仓库的 [2026-11-20 改名后快照](../../../policy/snapshots/2026-11-20-after-rename.json)。快照不代表线上实际配置。本次核对源码、项目文档和相关测试，未读取生产设置、产物或日志，未做 R6S 或终端实测。

## 先处理什么

**撤回原稿的 P0 判定。** 把网页成功响应记为 `reachable` 是有意保守，不是误降级。现有代码已能用满足条件的专项证据生成部分服务分流；AI 等平台缺可靠的业务探针，Google 的构建报告也不能代替设备自动切换。两者都不能靠把网页可达升级为「解锁」解决。本次没有发现足以确认生产 P0 事故的证据。

建议先修三类可独立验收的问题：远程抓取和门户主动出网的边界、「测全部」的任务总预算、以及「全部节点」订阅的字段和令牌管理。同时建立规则首命中回归。等这些证据齐全，再决定改哪些规则或启用哪些恢复能力。

## 解锁证据如何进入分流

| 环节 | 已核实结论 | 建议 |
| --- | --- | --- |
| 网页与实际业务 | [`classify_page()`](../../../server/app/services/probes/base.py) 将普通网页成功响应记为 `reachable`，人机校验记为 `unknown`。已知页面特征只能说明响应像预期页面；HTTP 200 或 `ok_markers` 都不能单独证明登录、对话、播放或会员权益。 | 保留 `reachable`。按平台和功能定义最小充分证据；只有该证据能证明所标注的功能才进入候选。缺可信探测手段时明确显示未验证。 |
| 专项能力 | [Netflix 和 YouTube Premium 检测器](../../../server/app/services/probes/platforms.py)有独立正向判据。Netflix 核对指定标题目录对象，自制剧可见与非自制剧样本可见分别记录，两者都不证明全库或播放；YouTube Premium 需要明确资格提示。 | Netflix 地区缺失、冲突时保留未知，不用第三方 IP 地理库、Cloudflare 出口位置或页面语言补成片库地区。保留公开样本证据，另用客户端试播验证实际业务。 |
| 编译与组员 | [`service_proofs()`](../../../server/app/services/routing_planner.py)筛近期正向证据；[`_apply_service_groups()`](../../../server/app/compiler/render.py)还核对当前节点版本和产物中的材料，已支持 Netflix 日本等服务组及部分专组的组员调整。普通地区组仍主要按用户配置和过滤正则生成，客户端 `url-test` 不提供业务证据。 | 不全局改 `_group_entry()` 或按探测结果裁掉普通组。串测「真实探测器解析模拟响应 → 质量及服务证据 → 最终产物」，覆盖正例、未知、过期、节点参数变化及跨方案/设备隔离。已有解析与渲染单测，缺的是这条链路的回归。 |
| 正式发布与时效 | [`current_policy()`](../../../server/app/routers/builds.py)中的正式别名受 `build_regional_node_names` 和 `probe_build_aliases` 控制，预览有独立入口。源码回退默认值不能说明线上开关。证据过期影响后续构建，不能改写已发布产物。 | 把「没有生成」拆成开关关闭、缺证据、过期、参数变化、地区不符、不在该方案等原因。确有独立迁移需求再拆开关。验收分别核对预览、生产产物、客户端加载。 |
| Google 地区回退 | [`google_evidence.py`](../../../server/app/services/google_evidence.py) 和 [`routing_planner.py`](../../../server/app/services/routing_planner.py)已有档位与证据判定；构建报告不改变线路。`staged` 是迁移默认值，也是[实施记录](2026-11-16-MagicPanel-V2-实施状态与运行手册.md)中的有意门禁，未核对线上状态。 | 用[现有合同](../../reference/自动恢复与检测策略.md)交付受管切换及回执。Google 按 US → SG → JP；只要还有合格美国候选就留在美国。未测、过期、预算用尽或风控不能证明上档耗尽；三档失败时普通业务不走 DIRECT，核心整体故障的 `BASIC_WAN` 单独验。 |

旧体检缓存有真实的时效缺口：[`_states_of()`](../../../server/app/services/unlock_check.py)按节点名读取状态，不核对时间或参数版本；局部复测合并还会使条目级时间不能代表各平台都已复测。先给展示证据补节点版本和逐项时间，过期显示「待复测」。这不能证明正式分流正在采用旧缓存。漏斗的 `bilibili_intl` 与旧清单的 `biliintl` 也确有错位；会漏计确认或拒绝，但不会必然让流媒体徽章消失。统一 ID 后测「正好差一项」和「该项明确拒绝」，同时把「全部解锁」的旧注释改为实际阈值口径。

## 优先修复的风险和验收条件

| 项目 | 核对结论与建议 |
| --- | --- |
| **远程抓取** | [`fetcher.py`](../../../server/app/services/fetcher.py)已有协议限制、逐跳地址检查和体积上限，但检查的 DNS 结果没有绑定实际连接；显式代理路径也不能以本地解析证明最终目的地址。手工跨源跳转还复用带自定义请求头的客户端，没有隔离自定义凭据。先禁止跨源转发来源凭据，并约束实际连接和代理出口；按来源保留必要的内网例外。用隔离测试覆盖同源、跨源、IPv4/IPv6、内部地址拒绝和已有订阅兼容性。未证实生产可利用性或实际泄露。 |
| **匿名检测和 PIN** | [门户 `POST /unlock/run`](../../../server/app/routers/portal.py)允许匿名触发面板出网。已有 60 秒缓存、进程内锁和共享探测工作位，不能说并发可无限叠加。建议公开页读缓存，主动触发优先复用 `probe` 权限；如保留访客刷新，须有总预算、失败冷却和可信来源 IP。PIN 失败字典缺容量上限和过期清理，建议加有界过期并保留 `Retry-After`。未核对线上反代限流。 |
| **自主维护删除权限** | [`DELETE /file`](../../../server/app/routers/deps.py)经 [`CurrentUser`](../../../server/app/deps.py)要求 `edit`，写入、创建和提交还要 `reveal`。操作员可删除未被规则来源引用的工作树文件，不代表匿名可删或可直接推送。明确角色矩阵后对齐同类动作，补删除审计；回归只读者、操作员、管理员以及已引用文件。 |
| **「测全部」的范围与耗时** | [`start_quality_probe()`](../../../server/app/services/scheduler.py)反复取「待测节点」，启动时不冻结这一轮的清单。已有 500 批安全上限、单批节点上限和约 180 秒的批内预算检查；没有整个任务的墙钟/流量预算、累计进度和协作取消。建议启动时冻结清单与节点版本，按批保存、计数，支持取消及有界续测。验证正常结束、超时、失败退避和取消后共享工作位都能释放。 |
| **核心错误与已完成结果** | [`NodeEngine.start()`](../../../server/app/services/probe_engine.py)的 `Popen` 启动错误可能绕过 `EngineError`。质量任务入口已有核心不可用时的 409，指定节点体检可能漏接启动错误。探测框架已隔离多数单平台异常；可能丢失已完成批内结果的是核心、编排或持久化层的非预期失败。统一启动错误与入口提示，分开单节点失败、系统性失败及未测；只保存已完成的有效记录，保留原失败原因和退避。不要在 `finally` 无条件写入。 |
| **迁移与就绪状态** | [应用初始化](../../../server/app/main.py)记录迁移异常后继续启动；[容器健康检查](../../../Dockerfile)已有 setup 查询、目录可写和磁盘余量检查，旧库的 `users` 表仍可读时不能证明迁移完成。让未完成迁移的实例报告未就绪，并阻止依赖该迁移的后台写任务。验收首次初始化、旧表可读但迁移失败、修复后重新就绪。 |

原稿另外几项不宜直接照改：

- **600 ms 与 3000 ms**：[探测口径与交付记录](2026-11-19-业务分流与客户端交付.md#探测口径)记载：早期漏斗方案写 600 ms，后续按用户要求放宽至 3000 ms，与 [源码默认值](../../../server/app/config.py)一致。实际设置未读回。先量通过率、流量、耗时和失败分布，再决定是否调参。吞吐门槛的单位写清楚：2 MB/s（16 Mbps）。
- **Netflix 超时与地区缺失**：14 秒声明默认受全局 8 秒和剩余预算约束；这是客户端请求超时设置，不能理解为双样本探测总共只有 8 秒。先量两个样本各自的超时、解析失败和地区缺失，再决定是否改，保留墙钟与字节预算。
- **切换后是否串节点**：`select()` 读回控制器选中项，随后下载和探测经 mixed-port 发新请求。读回不证明实际出口，但原稿没有串节点证据。先做两个已知不同出口的隔离验证，核对连接归属；普通探活只能证明连通。
- **429 与 404**：[探测口径](2026-11-19-业务分流与客户端交付.md#探测口径)和测试支持对 429 不追加请求。单个网页 404 也不能证明服务不支持该出口，保留 `unknown/not_found`。修旧文档和 `NodeQuality.stage` 注释即可。
- **后台关停**：两个任务被取消后未等待，属于关停边界不清。等待被取消的协程也不会保证停止 `asyncio.to_thread()` 的在途操作。应先明确备份和留存任务的退出时限及临时文件处置；没有证据证明已产生半份 WebDAV 备份。

## 规则、DNS 和节点名称

默认方案的[快照](../../../policy/snapshots/2026-11-20-after-rename.json)里，`anthropic` 为 25，`search/youtube/google` 为 40–42，`global-ai` 为 43，`openai` 为 45，`Amazon` 为 55，`PrimeVideo` 为 90，`magic-process/cn/cn-ip` 为 119–121。「移动网络」保持相同相对顺序。原稿的 Amazon 53、`global-ai` 40 和 `anthropic` 被通用 AI 遮蔽均不符合该快照。

| 项目 | 应做的验证 |
| --- | --- |
| Prime Video、Amazon 和 AI | [渲染器](../../../server/app/compiler/render.py)在拆出 Prime Video 且匹配到预期规则和目标时，会在 Amazon 前补视频域，也会避让显式域名规则，但没有遍历所有直连集合。快照中的 `openai` 和 `global-ai` 仍指同组；拆给不同目标后才会产生误分流风险。用最终 YAML 和对应规则集版本验证样本；只修证实的冲突，不强套「专项永远早于通用」。 |
| 进程与国内直连 | `magic-process` 靠后与自维护规则置顶的历史说明不同；`cn/cn-ip` 靠后属于已有策略取舍。按具体域名、IP、进程和平台能力模拟首命中，先确认误分流再调整。保住明确直连、拒绝和最终 `MATCH`。 |
| DNS 合并 | [渲染合并](../../../server/app/compiler/render.py)允许拓展模块、平台扩展覆盖 DNS，结构键限制不禁止整个 `dns`。[配置文档](../../配置文档.md)同时写了「DNS 可由拓展模块提供」和「各层一律不写 `dns:`」，还描述了合法覆盖场景。先盘点各层用途，展示最终值和覆盖来源；明确不可覆盖的键后再做校验。不直接封整段 DNS，也不借此变更 R6S。 |
| 名称和组过滤 | `filter_names` 使用兼容标签是为了稳定成员。贸然改成最终展示名会让已有精确正则失配。改名前提供组成员差异、空组告警及含机场标签的正则清单；长期把稳定筛选字段从显示名中拆出，再逐组迁移。 |

验收按「默认/移动网络 × Stash/Mihomo × 有独立配置的设备」查看产物。样本记录期望规则、实际首命中、目标与规则集版本；无法离线解析的集合写明未验证。至少覆盖面板订阅直连、家内域名和国内 DNS、Google、Claude、Telegram、影音及兜底。服务端 200、304 或最近拉取时间不等于客户端成功加载，交付时另外核对终端的加载结果和实际出口。

## 原稿遗漏或应降级的事项

| 项目 | 审计意见 |
| --- | --- |
| 「全部节点」订阅 | [`nodes_config()`](../../../server/app/routers/feed.py)在 GET、HEAD 都会采集并序列化。普通 GET 支持 304，但当前时间写入 YAML 注释并参与 ETag，节点不变也会使 ETag 随时间变化；探测采集器的内部 `source_id` 也会混进来源节点的 `proxies`。先做专用字段投影和稳定 ETag，测同内容 304、节点变化更新、HEAD 及目标客户端导入。有实际请求量与耗时证据，再做按版本失效的渲染缓存。 |
| 全节点令牌的影响范围 | [`rotate_nodes_token()`](../../../server/app/routers/portal.py)允许持门户 PIN 的访客轮换全局令牌，旧链接随即失效。区分读取和轮换的权限，明确改 PIN 是否应吊销既有链接，核对路径令牌的访问日志脱敏。测试旧令牌失效、错误令牌拿不到任何缓存内容、合法下载正常。未读日志，不宣称已泄露。 |
| 门户与 UI | [`Portal.vue`](../../../src/views/Portal.vue)首屏直接访问两个数组的 `.length`，当前 API 固定返回数组；这是响应变化时的健壮性风险。使用未过滤的安全计数。「达标」说明为「通过延迟和下载测速」，不能暗示业务全部可用。发布动词、环境名和历史事件按真实动作对照；「这台设备」「暂无」等低优先级。 |
| 测试与 CI | [视图冒烟](../../../src/v2/allViews.spec.js)通过正常夹具验证挂载，文本非空不能保证主操作可用。给关键视图加关键按钮和缺字段场景。[CI](../../../.github/workflows/ci.yml)没有执行 [Playwright 门户用例](../../../e2e/v2/portal.spec.js)，目前每种视口 5 个，API 是夹具。可用独立 Chromium 作业守桌面/移动交互，后端继续验证真实授权，并在 [README](../../../README.md)列清本地与 CI 的检查。 |
| 备份与恢复 | [WebDAV](../../../server/app/services/webdav.py)已实现，「尚未实现」描述过时。[`backup.sh`](../../../scripts/backup.sh)按同一时间戳建库和密钥，但独立轮转，异常中断或密钥缺失时可能失配。以成套备份为单位校验和轮转，隔离恢复时验证私密项可解密、发布指针与相关资源可恢复。[Compose](../../../docker-compose.yml)保留可手动启用的 backup profile；未核对线上运行情况，先确认保留策略再删。 |
| 脚本与历史数据 | [`usvps_add_nodes.py`](../../../scripts/usvps_add_nodes.py)含固定节点端点及 Reality 连接参数，账号凭据另行读取。公钥不是私钥；未核实参数仍有效或真实凭据曾泄露。盘点脚本及历史参数的必要性，确认暴露时再按影响轮换。旧方案精编脚本有策略写入和强制删组，应标记适用范围并保护生产目标；[网络实验脚本](../../../scripts/ops/network_lab.py)的本机缓存路径应改为显式配置，同时保留核心和权限校验。 |
| 状态与观测 | AGENTS 里的多个「当前生产构建」是不同日期的记录。建议只在注明日期的实测记录使用构建号。下一轮补采实际镜像提交、生产产物摘要、客户端最后成功加载、探测队列耗时/字节与中止原因、有效业务证据覆盖率、隔离恢复回执。不采集完整节点参数或令牌。原稿所述 NAS I/O 事故与探测负载的因果关系未核实。 |

## 实施顺序

1. **收紧边界，约束负载。** 抓取、门户及全节点令牌、探测任务总预算、核心启动和迁移就绪分别做小改动。安全改动也要用隔离测试证明拒绝边界和正常订阅兼容性。
2. **建立产物基线，再修有证据的冲突。** 做首命中回归、专项探测到产物的回归、证据时效和订阅响应契约。改策略数据前后导快照；测试发布后对比 YAML、节点和规则集引用。出现国内误代理、DNS 回归、空组或客户端加载失败，停止推广并保留已验证旧版本。
3. **补真实回执，再决定激活。** 实机核对 Netflix 播放与 Google 恢复，按已有合同覆盖 Stash 和 R6S、家宽和移动网络；通过故障、预算和回滚门禁后才考虑激活。文案、历史记录与脚本清理可独立排期。

本次 135 个相关后端用例、16 个前端视图冒烟用例均通过。Playwright 枚举了 10 个门户用例，本机未安装 Chromium，未运行。上述改进未实施；本次只交付这份复核文档。
