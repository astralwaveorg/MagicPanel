## 2. 把“配置没有 bug”变成放行标准

依次检查五层，不允许以前一层的 PASS 代替后一层：

1. **输入合格**：真实规则字节严格解析，格式/behavior/引擎兼容，失败不替换上一份合格内容。
2. **编译正确**：保留既有 sort/相对顺序；最终配置的首命中、目标组、递归叶和 DNS 意图符合业务期望。
3. **完整包可加载**：固定实际核心加载候选配置和同 revision 资源，不用回环占位 URL 或临时下载的最新同名文件冒充正文验证。
4. **运行路径正确**：OpenClash 覆写、AGH、Geo/IP 快路、nft、IPv6/UDP、客户端模式均与已验证路径一致；下载不冒充加载。
5. **业务完成**：GitHub 动态片段与下载、TikTok 连续分段、Google 全家、国内应用和 Apple TV 完成各自旅程；首页 200/204 仅为部分证据。

关键样本要求 100% 符合已审期望；任何国内误代理/误 REJECT、应代理流量直连、Google 越档、真实核心缺验证均不以平均通过率抵消。只对已支持/适用的目标计分，`unknown/not_run/unsupported` 单列，不转成 PASS。

## 3. 规则内容先隔离验证，再成为有效 revision

02/Task11 唯一拥有 `services/rule_content.py`、`services/rule_health.py`，接入 `updater.refresh_provider()`、`repo_sync`、内联规则保存、构建输入。复用现有 fetcher 的网络限制与大小限制；`count_rules` 只作显示计数，不能作资格判定。01 只提供私密存储，04 消费结果，不重复实现。

固定纯接口：

```python
def validate_rule_content(body: bytes, *, fmt: str, behavior: str,
                          engine_caps: dict) -> dict:
    """返回 body_sha/semantic_sha/count/format/behavior/validator_version；失败抛 RuleContentError。"""

def evaluate_rule_health(refs: list[dict], *, now, policy: dict) -> dict:
    """返回 sources/blockers/warnings/health_sha；无网络、无隐式系统时钟。"""
```

验证要求：

- YAML 必须为声明结构，`payload` 必须为条目列表；text 逐条按声明 behavior 解析；严格 UTF-8，不用替换字符掩盖编码问题。
- domain 不接受 `DOMAIN-SUFFIX,...` 冒充域名；classical 不接受 `+.example.test` 简写；ipcidr 检查 IPv4/IPv6 CIDR。逐条规则类型、参数和引擎能力按现有官方白名单验证，不因支持混合类型而放宽为任意字符串。
- MRS 不手写一个猜测解码器。用已固定版本的官方实现/工具对**实际候选字节**作读取和 behavior 验证，保留工具版本/二进制摘要；离线真实核心矩阵再次加载。工具不可用就是未验证，不能返回 count=0 当成功。
- HTML/JSON 错误正文、空响应、损坏/截断 MRS、错误 payload、错误类型全部拒绝。合法空集合只允许明确标为可空的来源；原非空来源突变为空必须审查。
- HTTP 状态、Content-Type、下载字节数是辅助信息，不能替代内容验证。大量增删、DIRECT/REJECT 扩张、公共后缀/关键词/全 ASN 扩张进入语义差异审查；不能用条数阈值自动删除用户意图。
- 网络/解析/验证失败只更新尝试与错误记录，不改有效正文/hash/revision/成功验证时刻。下载成功但待验证为 candidate，不标有效。
- remote/repo/inline 共用资格入口。repo 每文件验证并绑定 commit 或受控工作树摘要；整仓同步成功不掩盖其中一个文件失败。

最小红灯回归必须覆盖：HTTP200 HTML、空 body、坏 YAML、payload 非列表、domain/classical 混用、坏/截断/错 behavior MRS、合法小集合与经审空集合；每个失败例断言旧好正文与 revision 不变。

官方依据：[Mihomo rule-provider 的 behavior/format](https://wiki.metacubex.one/config/rule-providers/)、[Mihomo 规则类型及优先级](https://wiki.metacubex.one/config/rules/)、[Stash 集合格式与本地缓存](https://stash.wiki/rules/rule-set)。两引擎能力分别核对，MRS 当前只用于 domain/ipcidr。

## 4. “没有过时”必须有三种时钟

每来源保存并区分 `attempted_at`、`validated_at`、`content_changed_at`，另有有效 resource revision/hash、validator version、上游定位信息及本次状态。`validated_at` 表示成功取得/确认当前有效字节且验证通过；字节多年不变也可能新鲜，刚下载的坏字节也不合格。

- HTTP304 仅在本地有对应有效正文，ETag/来源身份匹配时刷新成功复核时间；丢正文后收到304不得视为成功。
- repo 正文不变但 commit/文件复核成功可刷新 validated_at，不制造内容 revision；单文件失败不刷新其时间。
- `content_changed_at` 只在有效正文变化时更新。复核时间与错误状态进入健康报告，不因为时间前进就改变 build_input_sha，避免无意义重建。
- 构建冻结实际字节、健康摘要和相关验证证据；发布时按当前时间重评有效期，不用构建时 PASS 永久背书。影响决定的 health_sha 绑定状态/策略/有效 revision，不包含无意义秒级时间波动。

默认仍为**周批量抓取/深度节点测试**，不恢复每天全扫。规则健康采用独立的 `rules-weekly-v1`：引用来源成功复核年龄 ≤7 天 fresh，7–14 天 stale，>14 天 expired；此规则不复用节点测速开关。恰逢周任务前后按明确 UTC 截止值评估，不能改系统时间规避。

| 情况 | 继续服务既有版本 | 新候选/自动生产发布 |
| --- | --- | --- |
| 本次抓取失败，但引用的合格正文仍 fresh | 是，提示失败及沿用 revision | 内容/核心/业务回归均过可继续，报告不是“本轮全部更新成功” |
| 引用来源 stale | 是，显示年龄与最后成功检查 | 可生成候选；阻塞自动生产，人工仅可显式批准继续沿用这份已验证正文，批准绑定包/来源 revision/期限并留审计 |
| 引用来源 expired | 是，保留上一份可用配置并告警 | 阻塞新生产；先成功复核/修来源或审定替代规则，再验收 |
| 引用正文缺失/不合格/无法验证 | 不切换到候选坏内容 | 阻塞；不清空集合、不静默丢规则 |
| 不在此包任何目标中引用的来源失败 | 无影响 | 不以无关来源卡住本包；单列来源错误 |

对有更长审定周期的自维护静态集合，用显式版本化策略记录周期与原因，不能悄悄延长全部来源。人工沿用 stale 不代表已更新，不改变 validated_at；过期证据不得靠人工重打时间戳变 fresh。现网继续服务旧版是可用性取舍，**不表示旧规则重新获得时效保证**。

第三个时钟是**设备实际加载**：上游已复核、NAS 已发布、客户端已加载分别显示。手机周拉取仍可能额外迟一周；休眠设备 unknown。版本 URL 内容不变，因此刷新旧 provider 不能代替拉取新配置；R6S 仅在已审受管发布后同步新包并核实际资源。保留旧版供回滚，但 UI 要显示当前设备与最新已验证包的差距。

紧急回滚区别于发布新候选：可按已审恢复流程恢复曾验证、仍完整保留的整包，同时如实显示其规则年龄，不借此重置时钟；解密/资源完整性/凭据撤销/设备权限仍须通过。02/Task13为该恢复操作记录专用审计原因，不能拿普通自动发布绕过时效门禁。

没有机制能证明上游维护者刚好收录了所有新域名。上游提交年龄、最近一次复核、业务语料最近验证和实际漏分流是不同信号，不能以“刚抓取成功”显示全网覆盖最新。

公共样本由本项目冻结规则、官方依赖说明和授权实际观察确认并注明来源/复核日期。一个服务的依赖可能合法使用不同 CDN/IP，不要求所有目的 IP 相同；对账号/地区敏感业务要求一致的**实际目的出口地区与审定会话路径**。

执行输入必须是：最终 target/device/variant/profile，完整置顶规则、设备 overlay、资源真实字节、DNS bundle；04再加入实际 OpenClash 转换与前置快路。仅在数据库规则表上模拟不合格。处理流程是 DNS 决策→路由器接管/旁路→核心首命中→组递归→实际叶/出口；事实不足返回 unknown。

候选与上一份已验证包比较：首命中、目标业务、DIRECT/REJECT、地区和解析分支的变化均给具体 case/rule/path。关键业务规则因 scope 被剔除，或落至不符合业务要求的 MATCH，阻塞自动发布。合法平台告警不一律升级为错误，关键适用语料不能因 warning 被静默跳过。未经过审查的上游内容变化不得自动改写 expected 让测试变绿。

触发回归的输入包括规则正文/顺序、默认与平台/设备配置、render/schema/core、策略组/节点资格、AGH 与 DNS、Geo/IP 快路数据及 OpenClash 覆写变化。只改 DNS/Geo 也可能漏代理，不能跳过。

每周批次也重跑本地确定性语料并显示 corpus_version、semantic_verified_at、实际业务观察时刻与范围，不额外向全部节点发请求。已知新增依赖/失败请求或上游格式变化使相关覆盖报告立即失效；上游同hash成功不刷新业务观察时刻。未知依赖发现进入待审候选与反例，不能仅用同一上游清单自证覆盖。没有近期实际业务证据时只能宣称当前语料回归通过。

## 6. 周检、备用与省心体验的真实承诺

用户已明确以少变动、少人工为目标。最终模式为[auto_stable_v1](../../reference/自动恢复与检测策略.md)：每周全面评估，每日地区抽样，当前路径小哨兵与可信故障事件驱动有界复核，异常才逐级扩大；主备合格自动切换，健康不换IP，整包自动生产发布仍独立关闭。实施/灰度前不开启，G7按真实能力回执启用；不能再以周间手动处理作为本次完成标准。

02/Task6–7输出普通业务状态，04本机执行与读回，03显示同一结果：

| 状态 | 判定 | 自动稳定模式的动作 |
| --- | --- | --- |
| active | 当前叶有新鲜适用证据且无后续失败/出口冲突 | 保持，不为小幅延迟/排名变化切换 |
| verified_standby | 当前失败且备用新鲜合格 | 自动CAS切换并GET读回，只影响相应业务新连接 |
| cold_unverified | 没有合格备用，但存在未验证候选 | 自动有界复核、退避分批继续，不等待用户点测，不把unknown当失败 |
| uncertain | 观察点/adapter/路径异常或证据冲突 | 保留未确认选择、诊断测量系统，不清空节点池 |
| all_failed | 完整适用候选均有有效业务失败证据 | 明确海外业务失败并有界恢复；国内DNS/DIRECT继续，不转DIRECT冒充成功 |

上述状态不替换Job状态。A失败/B新鲜/C未知、全部未知、全部失败、adapter整批失效、旧计划过期、中心不可达/设备休眠均须可重放。中心建议不冒充设备已经切换；Android/macOS/iOS分别验本机执行器，AppleTV按家庭透明路径验收。

Google只按完整证据执行US→SG→JP，地区50%抽样阈值只升级检查范围，不授权跨国；低档运行时自动复核上档恢复，任一合格US恢复按共同策略确认后返回。所有档失效但核心仍活、节点极慢，都不能改变国内解析或DIRECT路径。

业务资格至少说明服务、HTTP/2/3或TCP/UDP能力、IP族、页面/API/CDN/播放阶段与观察点。周检中的短 HTTP/有限下载只能证明对应范围；不做全节点播放/账号测试。04对少量获准候选完成既有长时场景，再冻结可用于发布的业务验证报告；后续无影响变更可复用与输入 hash 匹配的报告，不能每次小发布都强迫用户重播半小时。

持续业务的会话出口变化单独记录：节点 revision 不变不代表目的出口不轮换；短期多次观察/实际目的专项给出范围。IP轮换、地区变化或已确认服务失败让对应 affinity/业务证据失效，不能沿用稳定标签。不同协议共用出口仍是同故障域，不当成独立多出口冗余。

有限观测记录`observed_egress_set/destination_scope/ip_family/observed_at/variability`（fixed/rotating/unknown），不按机场/自建永久加减分。同UID同revision出现两个出口，即使均US，也不能继续声称固定IP；IPv4/IPv6与不同目的的出口证据不混用。推荐切换默认只影响新连接，保留无关已建立连接；确需断开失败连接仅限已审scope，禁止清空全屋conntrack强迫切换。上游轮换无法由面板约束时显示限制，`selection_hold`不冒充`egress_affinity`。

## 7. 国内故障隔离与运行漂移

核心外守护是必需职责，与业务恢复开关独立。统一待实测放行预算：从本地注入核心失败时刻起，**8秒内撤除本owner失效接管，10秒内恢复国内新建连接**；本地检查候选周期2秒、整轮探针共享1秒deadline、连续3败。用 monotonic 固定起始周期，不是超时后再 sleep 两秒；受控本地数据面与控制面联合判断，单一外网服务失效不当核心挂死。连续5次成功且冷却60秒后才重新接管。这是实施验收要求，尚不是生产已达到的承诺；不足则修复/收敛路径，不临场放宽阈值。计时含 DNS 与 nft 生效，持续新源端口/冷DNS检查；上游 WAN 同时故障单列，旧TCP/应用退避会话可断，不能写成十秒内无缝恢复。

关闭宽泛CN-IP提前旁路；独立DNS与核心外救援分别负责正常国内路径与核心故障恢复。境外CDN、共享IP、ECH、自带DNS、IPv6/UDP和遗留conntrack都需矩阵。故障时国内默认DNS不等待境外代理；实际已确认CN-IP return在redirect之前，最终关闭该宽旁路，不再把维护pass例外作为默认解决方案。无法分辨的共享IP不作“已全部保护”的假保证。

04只读运行观测加入 config/envelope/resource/core/DNS/Geo/nft owner revision 的期望与实际差异。OpenClash/Geo/广告/DNS 不允许脱离已审bundle各自自动推进生产再声称全包原子；无法冻结的外部更新明确为漂移，自动生产保持停止并复核受影响语料。下载正常但加载/子资源未知时显示“待确认”。

低频审计复用授权被动数据与本地状态；主动请求只按auto_stable_v1入预算，不由页面GET暗发；脱敏聚合 MATCH/cn-ip/异常命中只作诊断线索。MATCH 增加不直接判漏代理，海外域由 MATCH 代理本来合法；命中计数也不能代替实际连接证据。不采集完整 URL、账户或内容，不启用全屋长期明文流量记录。
