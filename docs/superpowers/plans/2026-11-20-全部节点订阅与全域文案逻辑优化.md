## 任务 1：全部节点订阅（不含复杂分流）

### 需求判定

「所有节点列表，不含复杂分流」= 一份**只含节点**的订阅：全部启用节点（订阅来源 + 本地节点），一组一条规则（`MATCH → 🚀 默认代理`），没有 46 个策略组和 136 条分流。用途是把节点池导入任意客户端/工具，或直接分享。

### 方案对比

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 代理提供商段复用 | 复用生产产物的 `proxy-providers` | 拒绝：provider 里含整套订阅更新链路，且 provider 模式节点不在产物顶层，不是「节点列表」 |
| B. 构建期新增产物 | 每次构建多渲染一份 `nodes.yaml` 进构建目录 | 拒绝：改构建矩阵，牵动校验/发布/读回，重；且「所有节点」含未进产物的来源节点，产物口径反而不全 |
| C. feed 实时渲染 + 独立令牌 | 新端点 `GET /feed/nodes/{token}.yaml`，令牌存 settings（密文），门户 PIN 门内展示链接 | **采用**：与设备订阅同一安全模型（高熵令牌承担安全，PIN 只挡页面查看）；实时渲染，不依赖构建发布；节点池用 `scheduler._collect_probe_proxies()`（已统一 emit_name、去占位节点、去重、含本地节点） |

### 实现要点

- `server/app/routers/feed.py` 新增 `GET /feed/nodes/{token}.yaml`（GET/HEAD）：令牌与 `settings.portal_nodes_token_enc` 比对；内容 = 全部节点 proxies + 单个可见 select 组 `🚀 默认代理`（成员 = 全部节点 + DIRECT，节点在前）+ `MATCH,🚀 默认代理`；`no-store` + ETag 协商与设备 feed 一致；预览（`?preview=1`）不记拉取；不更新任何设备时间戳。
- 令牌懒生成：门户数据接口首次访问时若无令牌则生成（`secrets.token_urlsafe`，密文入库）；提供轮换（作废旧令牌）。轮换与生成记审计。
- `portal.py /data` 返回 `nodes_feed`：`{url, preview_url, node_count}`，PIN/登录门内展示。
- `Portal.vue` 设备区上方加「全部节点」卡片：地址一行（点击复制）+ 复制/下载/二维码 + 「重置链接」（二次确认）。二维码复用现有弹层。
- 链接里的令牌轮换后旧链接立即失效；卡片上的 `?preview=1` 预览不记任何统计。
- 测试：`server/tests/test_feed_nodes.py` —— 令牌鉴权（错误令牌 404）、内容形状（proxies + 1 组 + MATCH）、占位节点不在列、本地节点在列、轮换后旧令牌失效、preview 不记统计。

### 验收

- 门户未登录（PIN）→ 能看到全部节点卡片与链接；curl 该链接得到合法 YAML（python yaml 解析通过、组/规则形状正确）。
- 403/404：错误令牌拿不到内容。
- 客户端可用性按 Stash/mihomo 对裸配置的加载为准（无登录、无播放要求）。

## 任务 2：全站文案 humanizer 检查

### 方法（ste80-humanizer，中文适用 Pass 1 + Pass 2 结构规则）

- 范围：`src/views/*.vue`（17 个）、`src/components/*.vue`（全部）、`Portal.vue`（公开页，最高优先）、`server/app/routers/*` 的用户可见报错文案（只改明显 AI 腔，不动语义与状态码）。
- 原则：**保事实、保条件、保确定性**；不改代码、路径、命令、标识符、报错码；「优化不是简化」——信息不能丢；一句一个重点；不排比凑三；不用「不是 X 而是 Y」开场、不用空话收尾；界面标签保准确（如「发布测试/发布生产/抓取并发布」等既定文案不改名）。
- 已定案的术语保持：引擎默认配置/引擎平台配置/设备独立配置、发布测试/发布生产、当前网络/服务器网络、抓取并发布、预览节点改名、Netflix 日本 等。
- 逐文件处理并记录改动要点；不改含义只改表达；拿不准的原文保留。
