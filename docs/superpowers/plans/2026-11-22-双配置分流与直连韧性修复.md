# 双配置分流与直连韧性修复

## 范围与目标

OpenClash 的借用模板与 MagicPanel 生产订阅独立发布。先修已证实的规则和策略组问题，再验收设备与故障路径。全量规则集合、账号切换和家庭网关接管分开处理，每项单独留证。

## 正常态

| 项目 | OpenClash | MagicPanel |
| --- | --- | --- |
| 国内与内网 | 保留当前明确直连和解析后大陆 IP 规则；先覆盖可证实的漏项 | 保留已有直连集合、6 条精确补充、国内域名及 cn-ip；保留设备独立规则 |
| 境外通用 | 国外域名去掉 DIRECT，默认故障转移；保留通用代理兜底 | 保留现有国外域名代理组与末尾 MATCH |
| subapi.dnscli.top | 规则纳入模板，目标使用模板与内核统一后的 JP 自建组名；检查启动时不丢失 | 无设备反馈证明需要同一例外，保持独立 |
| Google | 美国自建、美国自动、新加坡自建、新加坡自动、日本自建、日本自动；默认美国，保留人工选择 | 同样修正三档顺序，移除可能越档的综合选项；构建全部已启用平台 |
| AI 与账号 | Claude、ChatGPT、Grok、Copilot、通用海外 AI 先收窄到自建；保持有序故障切换 | 保留用户审查过的三自建链；没有账号级稳定 IP 需求和回执前不改成强制单出口 |
| X 和其他账号 | 如果连接证据显示会话跨出口且影响使用，再拆精确账号规则；不因文章引入整域或进程关键词 | 同左；需要固定出口的账号应选独立单节点，故障由用户决定是否切换 |

Google 保留手动选择，是因为普通连通性检查不能证明整档业务失败；未测、403、人机验证和慢速分别记录。三档自动回退另走已有专项门槛。保留已审的内网、PT、媒体和引擎特例。正常态未知境外流量不能通过通用 MATCH 变成直连。

## 大陆直连覆盖标准

不整套叠加 Loyalsoldier。保留当前精确补充；由最小权限的连接样本抽查兜底、宽泛境外集合和专用条目。每条样本保留域名、首命中、实际出口、A/AAAA 解析结果和访问结果。域名归属、同一 CDN 的海外服务、设备误用家庭代理分别排查。精确域名补充必须有业务与可达证据；不以整个 .top、共享 CDN 或泛关键词作国内证据。

抽查内网/NAS、家庭域、淘宝/支付宝入口、微信、美团图片/常见国内 CDN、现有精确补充，覆盖新连接、IPv4/IPv6 与 UDP。失败逐条定位。未见过的域名、境外 CDN 或 DNS 污染场景无法靠有限列表承诺零误判。新增独立直连集只有在扣除现有规则和代理冲突后有明确净增量才考虑。

## OpenClash 国内连通性

代理节点全失效而核心仍工作时，已知国内和内网 DNS/直连必须不等待代理检测，不受代理组故障转移影响。采购或依赖国内外共用的 DNS 上游前，要分别确认 AdGuard Home、dnsmasq、拦截层和外网递归的依赖关系。

正常停止、崩溃和 SIGSTOP 分开验收。仅添加 DIRECT 规则无法绕过已失效核心的透明接管。按《家庭网络运行契约》先隔离验证，正常停止验证 DNS 及 TCP/UDP 接管被清理；崩溃/挂起由核心外守护撤销 OpenClash 所拥有的接管，再由原生 DNS 和 WAN 恢复。已有看门狗启动核心的动作不能代替撤接管。阈值为 8 秒内撤接管，10 秒内冷 DNS 和新源端口连接恢复；不保证已有 TCP/UDP 会话永不中断。不改 cron、守护、DNS、网络或防火墙，不在生产做停进程故障注入；生产灰度必须使用已审维护窗口、本地管理入口和可回滚基线。未完成则明确标注不可保证。

## 发布与回退

1. 保留 OpenClash 模板基线和 MagicPanel 改前策略快照，核对源和运行配置。
2. OpenClash 串行修改，深检并复查引用；提交推送、ocupdate 带哨兵、读取运行 API；核对域名命中、日本自建组与出口，境外默认代理，国内示例依然直连。失败用模板 revert 再按同一机制加载；不改现场守护脚本。
3. MagicPanel 仅改相关策略数据，通过数据自检后创建构建。发布测试，逐份核对前后规则及策略组、Mihomo 核心校验、Stash 结构校验；用 CAS 发布生产，HTTP 读回配置，同时跟踪真机加载。失败恢复上一生产构建，策略数据定向回退，不能用旧快照覆盖后续用户改动。
4. 先验正常态，再验节点全失效、正常停服及核心崩溃/挂起。配置下载成功不代表真机加载，也不代表故障态通过。按设备和故障场景分别记结果。
