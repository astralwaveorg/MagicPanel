# MagicPanel V2 生产验证与路由器末期迁移 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已授权的实现/提交/部署测试目标下，先完成手册备份与严格白名单安全准备，再实现本机自动恢复、独立DNS与完整验收；网络切换与最后订阅更新仍末期进行，以真实回执决定推广。

**Architecture:** 复用构建/发布状态机，新增观测、本机恢复执行器与验收编排。前期代码/fixtures/VM/NAS staging不写生产NAS/feed；另允许固定router.safe_preparation和独立HK/KR DNS角色部署。ROUTER_FINAL先冻结旧分发/NAS升级，再分层迁移R6S，最后更新生产订阅、灰度与推广。

**Tech Stack:** 现有 FastAPI/SQLite/Python/pytest/Vue/Vite；固定版本 Mihomo 与实际 Stash/iOS/tvOS/macOS 客户端；一次性 Linux VM 的 network namespace/nftables/iproute2；现有 OpenClash/fw4/procd；Python 标准库、已有 cryptography/PyYAML。

**Spec:** [家庭网络运行契约](../../reference/家庭网络运行契约.md)是网络/DNS/WG/SQM唯一最新目标，[自动恢复与检测策略](../../reference/自动恢复与检测策略.md)是节奏/阈值/预算唯一数字合同；再读[总体设计](../specs/2026-11-15-MagicPanel-V2-总体设计与审查稿.md)、[工程规范](../specs/2026-11-15-MagicPanel-V2-工程检测与验收规范.md)、[个人生产草案](../../network/2026-11-15-MagicPanel-V2-生产迁移草案.md)。01提供身份/能力授权，02提供observer/path/freeze及planner/编译/冻结资源/发布门禁，03提供用户界面与体验闭环；04独占运行观测API及完整runtime_observations表/迁移。04.2可先于02 API集成完成，不产生设备网络操作。

```python
def authorize_operation(operation, phase, proofs):
    registered=OPERATION_REGISTRY.get(operation.get('id'))
    if registered is None:
        return ['UNKNOWN_OPERATION']
    if operation!=registered:
        return ['OPERATION_DEFINITION_MISMATCH']
```

### 04.7.1 execution_owner、epoch与修订号

- `execution_scope`按实际控制器select唯一定位：终端为`device:<device_id>:group:<group_ref>`；R6S共享组为`router:<asset_id>:group:<group_ref>`，LAN设备只映射到该共享scope，不能各自成为同一select的写者。04注册scope到设备/组/控制器的白名单映射；URL/body不能改变它。
- 每scope只有一个固定`execution_owner`，值为已注册本机执行器ID；`owner_epoch`是一次受信安装/移交生成的随机128-bit ID，绑定owner公钥与scope；策略包携带该授权。普通候选/策略更新及软件升级保留epoch与journal；不能因重启、NAS离线或恢复旧备份自动换epoch。所有proposal/intent/receipt都必须精确匹配owner+epoch+scope。
- `selection_revision`仅由该本机owner在持久状态确认后单调推进；NAS仅镜像，不另做选择revision CAS。proposal携带`expected_selection_revision/expected_selected_ref`，由本机锁内检验。它与catalog/node/config/环境release revision完全独立；离线本机从7切到8/9，NAS仍显示7只是陈旧镜像，不是另一条可写分支。
- owner移交/epoch重建必须先取得旧owner停止/卸载的可信回执，或实际撤销旧owner可写控制器的能力，再安装新epoch并只读对账。旧owner无法fence时不移交、不让NAS接管。普通UI手工选择也发送proposal给同一owner；App原生手改属于外部变化，本机检测后暂停该scope自动写，记录`external_change`并只读对账，不覆盖它装作CAS成功。

### 04.7.2 最小持久状态与HTTP合同

04唯一建表/迁移并向01注册备份。NAS表是assignment、proposal ledger和receipt镜像；本机表/单JSON journal才是选择状态权威，不共享同一个可写SQLite文件。

固定服务合同：


- POST `/api/v1/runtime-recovery/proposals`为唯一NAS写建议入口，body=`{device_id,decision,idempotency_key}`，runtime_write+CSRF；由注册device/group解析scope/owner/epoch，复核02可信建议、候选/锁/expiry/scope。202返回`{action_id,status:'proposed',execution_scope,execution_owner,owner_epoch,expected_selection_revision}`，不返回伪造的已切换状态。同key同payload返回原记录，异payload409。已有`/runtime-recovery/apply`只作同一proposal兼容入口，也返回202；从接口及内部服务删除controller参数，不准NAS直接PUT。
- 本机按已签名周包自行产生的恢复decision与NAS proposal进入**同一个本地入口/同一把锁/同一journal**，校验相同字段，不需要NAS在线。本机主动获取proposal只读、不消费选择revision；旧proposal抵达时若本机revision/ref已变，记rejected/stale，不PUT、不回滚本机选择。
- POST `/api/v1/runtime-recovery/receipts`仅接已注册owner的签名安全回执；机器principal绑定scope/epoch，管理会话仍需runtime_read+CSRF，只有runtime_read不足以冒充owner。回执固定`schema/action_id/execution_scope/execution_owner/owner_epoch/selection_revision/prev_receipt_sha/payload_sha/selected_ref/scope_sha/status/observed_at/receipt_sha/signature`，正文canonical后签名，不能使用回执自带公钥替代受信registry。GET `/runtime-recovery/state?device_id=&group_ref=`只读runtime_read，返回owner/epoch、最后确认revision/ref/receipt、mirror_state/as_of；不调用controller。
- 同epoch同revision同hash幂等；同revision异hash为`selection_fork`，隔离回执并暂停该scope新proposal，不能最后写入者胜出。新回执必须接上prev_receipt_sha；缺中间记录返回`receipt_gap`，本机补交未确认链后再收新末端，不以收到时间排序。旧epoch只能存历史，不能修改当前镜像；跨owner/epoch写请求拒绝`execution_owner_mismatch`且controller零调用。

NAS恢复点早于本机已压缩的确认链时，不增新队列/nonce协议。该scope保持reconcile_required并停发proposal，由已注册本机owner锁内只GET后提交签名reconcile观察，使用既有collector时效/身份检查及当前owner/epoch校验；04记录历史缺口，镜像只可前进到已确认本机高水位，不伪造丢失历史、不发PUT、不重放intent。缺有效owner/当前观察就保持阻塞并安排本机只读对账，不能自动换epoch或接受回执自带公钥。

选择receipt链只记录实际选择状态提交；拒绝/未完成/无变化proposal返回action结果，不以同revision另造选择receipt。无变化不PUT、不加revision；外部变化的已确认新基线由本机推进一次revision并保持暂停，值变回旧节点也不复用旧revision（ABA）。
