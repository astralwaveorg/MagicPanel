# 环境与地址速查

这份文档回答一个具体问题：**仓库和脚本里出现的那些内网 IP，到底是哪台机器。**

仓库里所有内网地址都出自本文档。网络环境变了（换 IP、换机器），先改这里，再改引用它的地方。

---

## 拓扑

```text
家里局域网 10.0.1.0/24
├── 软路由    R6S        10.0.1.1 —— OpenClash 在这里做全屋透明代理与分流
├── NAS       Altair     10.0.1.2 —— 跑 magicpanel 容器，面板本体在这
└── Mac mini  NoraMac    10.0.1.8（有线 en0）/ 10.0.1.9（Wi-Fi en1）—— 仅开发机
```

**面板跑在 NAS 上，不在这台 Mac mini 上。** 这是本项目最容易被搞混的一点：
凡是「服务端做的事」——抓取订阅、抓规则集、测速、构建、发布——都发生在 NAS 容器里。

**代理已经上移到路由器**：2026-11-10 起由 R6S 上的 OpenClash 做透明代理并分流，
局域网内所有设备（含 NAS 容器）无需任何 `HTTP_PROXY` 配置；Mac mini 上原来的 Stash
代理已停用。

## 机器清单

| 角色 | 主机名 | 地址 | 登录方式 | 备注 |
| --- | --- | --- | --- | --- |
| 软路由 | R6S | `10.0.1.1` | `ssh root@10.0.1.1` | ImmortalWrt + OpenClash；全屋网关与代理 |
| NAS | `Altair` | `10.0.1.2` | `ssh archon@10.0.1.2`（免密） | 容器 `magicpanel`，数据目录 `/app/data` |
| Mac mini | `NoraMac` | `10.0.1.8`（有线 en0）<br>`10.0.1.9`（Wi-Fi en1） | 本机，不要 ssh 自己 | 开发机，不再承担代理 |

`10.0.1.8` 与 `10.0.1.9` 是**同一台 Mac mini 的两个网卡**，不是两台机器。
`archon` 是用户名，`Altair` 才是 NAS 的主机名。

## 代理

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 透明代理 | R6S `10.0.1.1` 上的 OpenClash | 局域网内所有设备自动生效，无需每条链路单独配置 |
| DNS | `10.0.1.1`（AdGuard Home） | 大陆直连、海外走代理；设备端无需指定 |
| 容器内 `HTTP_PROXY` | **留空** | 走透明代理；显式配置反而会把节点测速带偏 |
| APT 代理 | **留空** | `/etc/apt/apt.conf.d/99proxy` 曾写死 `http://10.0.1.8:7890`，代理下线后 `apt update` 所有源报「拒绝连接」，包完全装不上 |

面板里的「抓取代理」`proxy_url` 一律留空。历史遗留的 `http://10.0.1.8:7890`
（Mac mini 的 Stash）已于 2026-11-10 全部清空，包括 3 个节点来源与 88 个规则来源。

> 为什么不能用 `127.0.0.1`：容器里写 `127.0.0.1` 指的是容器自己，既不是 NAS 也不是路由器。

## 改网络后怎么核对

NAS 侧（面板抓取与测速真正走的路径，最关键的一条）：

```bash
ssh archon@10.0.1.2 'docker exec magicpanel curl -s -o /dev/null \
  -w "%{http_code}\n" -m 10 https://www.gstatic.com/generate_204'
# 期望 204（经路由器透明代理）
```

大陆直连（必须不依赖代理）：

```bash
ssh archon@10.0.1.2 'docker exec magicpanel curl -s -o /dev/null \
  -w "%{http_code} %{time_total}s\n" -m 8 https://www.baidu.com'
# 期望 200 且耗时在 0.1s 级
```

节点测速（面板「本地节点 → 测速」）必须直连节点服务器：

```bash
ssh archon@10.0.1.2 'docker exec -w /app -e PYTHONPATH=/app magicpanel \
  python -c "import socket;print(socket.gethostbyname(\"lax.magichub.top\"))"'
# 期望返回该节点的公网 IP，不是 10.0.1.2
```

> 历史坑：dnsmasq 曾用 `address=/magichub.top/10.0.1.2` 通配所有子域，
> 把 `lax/kix/hka.magichub.top` 全部解析成 NAS 自己，导致节点测速全部失败。
> 现改为 AdGuard Home 的精确 rewrite（仅 `magichub.top` 指向 NAS）。
