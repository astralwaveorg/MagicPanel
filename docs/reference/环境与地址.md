# 环境与地址速查

这份文档回答一个具体问题：**仓库和脚本里出现的那些内网 IP，到底是哪台机器。**

仓库里所有内网地址都出自本文档。网络环境变了（换 IP、换机器），先改这里，再改引用它的地方。

---

## 拓扑

```text
家里局域网 10.0.1.0/24
├── Mac mini  NoraMac    10.0.1.8（有线 en0）/ 10.0.1.9（Wi-Fi en1）
│     └── Stash 混合端口 7890 —— 同时监听 127.0.0.1 与 0.0.0.0，内网可直连
├── NAS       Altair     10.0.1.2 —— 跑 magicpanel 容器，面板本体在这
└── 软路由    R6S        10.0.1.1
```

**面板跑在 NAS 上，不在这台 Mac mini 上。** 这是本项目最容易被搞混的一点：
凡是「服务端做的事」——抓取订阅、抓规则集、测速、构建、发布——都发生在 NAS 容器里；
Mac mini 是**开发机 + 代理机**（Stash 在这上面跑）。

## 机器清单

| 角色 | 主机名 | 地址 | 登录方式 | 备注 |
| --- | --- | --- | --- | --- |
| Mac mini | `NoraMac` | `10.0.1.8`（有线 en0）<br>`10.0.1.9`（Wi-Fi en1） | 本机，不要 ssh 自己 | 开发机；Stash 代理跑在这里 |
| NAS | `Altair` | `10.0.1.2` | `ssh archon@10.0.1.2`（免密） | 容器 `magicpanel`，数据目录 `/app/data` |
| 软路由 | R6S | `10.0.1.1` | `ssh root@10.0.1.1` | OpenWrt |

`10.0.1.8` 与 `10.0.1.9` 是**同一台 Mac mini 的两个网卡**，不是两台机器。
`archon` 是用户名，`Altair` 才是 NAS 的主机名。

## 代理端口

| 端口 | 归属 | 协议 | 谁在用 |
| --- | --- | --- | --- |
| `7890` | Stash 混合端口 | HTTP / SOCKS | 抓取订阅、部署与发布脚本出网、访问 GitHub |
| `6152` | Surge 外部访问 | HTTP | `scripts/nas_proxy_switch.py`：给 NAS 配全局代理 |
| `6153` | Surge 外部访问 | SOCKS5 | 同上 |

Stash 在 7890 上同时监听 `127.0.0.1` 与 `0.0.0.0`，所以内网其它机器（含 NAS 容器）能直连它。
Surge 的 6152/6153 要在 Surge 里打开「允许来自局域网的连接」才会监听，没开时 NAS 侧配不上全局代理。

2026-10-31 起，面板里**全部远程抓取都已配上这个代理**：84 个远程规则来源 + 4 个节点来源
的「抓取代理」`proxy_url` 均为 `http://10.0.1.8:7890`（此前直连 GitHub 时好时坏，审计里
反复出现 SSL 握手超时 / HTTP 403）。隐含依赖：**Mac mini 的 Stash 必须在跑**——它挂了
抓取会全部失败，但抓取失败不会覆盖上次成功快照，客户端 feed 不受影响；新加的远程来源
记得在来源上同样配上代理。

## 什么时候写 `127.0.0.1`，什么时候写 `10.0.1.8`

**取决于代码在哪台机器上跑**，这是本项目最容易踩错的地方：

| 场景 | 代码在哪跑 | 正确写法 | 写错的后果 |
| --- | --- | --- | --- |
| 节点来源 / 规则来源的「抓取代理」`proxy_url` | **NAS 容器**（面板服务端） | `http://10.0.1.8:7890` | 写 `127.0.0.1` 会连到 NAS 自己，实测 connection refused，订阅与规则集全部抓不到 |
| `scripts/deploy.sh` 的 `DEPLOY_PROXY` | **NAS 端**（ssh 过去注入 `docker compose build`，构建时要拉 npm/pip 包） | `http://10.0.1.8:7890` | 写 `127.0.0.1` 会让 NAS 连自己，镜像构建拉不到包 |
| `scripts/release.sh` 的 `GH_PROXY`、`scripts/fetch_geo_data.sh` 的 `PROXY` | 开发机（Mac mini） | `127.0.0.1:7890` 或 `10.0.1.8:7890` 都行 | 两种都通，取哪个看当时在哪台机器上跑 |
| `scripts/nas_proxy_switch.py` | NAS 上 | `http://10.0.1.8:6152` / `socks5://10.0.1.8:6153` | 写 `127.0.0.1` 等于让 NAS 连自己 |

一句话记住：**凡是代理会被 NAS 那边用到的，就必须写 Mac mini 的内网地址 `10.0.1.8`；
只有纯本机跑的 curl 才可以用 `127.0.0.1`。**

## 改网络后怎么核对

本机（Mac mini）：

```bash
hostname                                    # 期望 NoraMac
ifconfig | grep 'inet '                    # en0 = 10.0.1.8，en1 = 10.0.1.9
lsof -nP -iTCP:7890 -sTCP:LISTEN            # 期望看到 Stash
curl -s -m 8 -x http://127.0.0.1:7890 -o /dev/null -w '%{http_code}\n' \
  https://www.gstatic.com/generate_204     # 期望 204
```

NAS 侧（面板抓取真正走的路径，最关键的一条）：

```bash
ssh archon@10.0.1.2 'docker exec magicpanel python3 -c "
import urllib.request
h = {\"http\": \"http://10.0.1.8:7890\", \"https\": \"http://10.0.1.8:7890\"}
op = urllib.request.build_opener(urllib.request.ProxyHandler(h))
print(op.open(\"https://www.gstatic.com/generate_204\", timeout=8).status)
"'
# 期望 204
```

这条如果不通，面板里的「抓取走代理」就是坏的——先查 Stash 是否在跑、7890 是否在监听。
