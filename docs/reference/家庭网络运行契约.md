## 1. 唯一拓扑与优先级

- 家庭：杭州，中国电信宽带，签约下行1000Mbit/s；用户观察上行常见60–80Mbit/s、峰值100。R6S是主路由，OpenClash做全屋透明分流。
- 家庭NAS、Mac mini、Apple TV等不安装第二套日常代理。NAS只运行面板与隔离节点检测worker；临时核心仅用于检测，不接管NAS日常流量。
- 外出：中国移动网络，主用现有Android、MacBook、iOS的Stash配置；MacBook在外通过实际所用网络/移动热点验收。电信、移动分别记录观察点，VPS结果不能代替任何一方。
- WireGuard只回家访问NAS/路由器内网，不作为全部流量出口。历史Mac mini/Apple TV/Windows等设备记录保留兼容，不强迫安装/重新启用这些代理客户端。
- P0：代理节点、全部代理、地区失败/极慢不得成为国内DNS和DIRECT的前置条件。P1：海外按业务/地区策略恢复，Google严格US→SG→JP。P0先于自动选优速度。

## 3. 防火墙与透明接管最终选择

**保留Linux TCP redirect，增加UDP TPROXY，统一双栈；首版不换TUN。**

1. 关闭宽泛`china_ip_route`/`china_ip6_route`提前直连；国内DIRECT由已验证首命中规则决定，核心失败由核心外守护恢复原生WAN。避免长期维护共享IP的例外集合。
2. 只豁免本地/保留地址、管理回程、节点自身bootstrap/隧道端点、独立DNS控制面和已隔离探测源。逐项绑定用途，不使用“所有443”“整个NAS永远不接管”这类宽豁免。节点端点豁免防递归，不表示访问其同IP所有网站都应直连。
3. IPv4 UDP启用TPROXY到实际7895，使用OpenClash注册的mark/table与local路由。IPv6 TCP/UDP使用该固定插件版本支持的TPROXY模式，配置`ipv6_enable=1`及对应v6 UDP入口；字段枚举值以现场脚本能力表产生，不凭空猜`ipv6_mode`数值。
4. 04实现版本适配器：读取插件脚本/核心能力，输出确定的UCI+规则+路由bundle及允许差异，先在隔离环境运行同版本再封包。缺模块/字段不支持先补齐已审依赖并重验；双栈验收失败则停止该迁移、保留旧生产，不带未接管IPv6假称全屋完成。
5. offload继续关闭；不并行打开硬加速、换核心或更新Geo。nft/fw4/OpenClash重启后的规则必须由同一owner入口恢复，不能让两个脚本互相补规则。
6. QUIC由已经接管的流量治理；仅在服务/节点已证明UDP不可用时对该scope快速拒绝使应用回退TCP。相关规则位于服务允许规则前，不全局封游戏/语音/WG或Hysteria2隧道UDP。
7. 从端点可信DNS获得真实地址，不依赖sniffer修复污染IP；sniffer负责可见域名辅助识别。对ECH/纯IP不能虚构域名；未分类外部流量按MATCH代理，国内明确集合/国内IP兜底保持既定顺序，必须通过业务语料及共享IP负例。

官方支持范围：[Mihomo redirect仅TCP、TPROXY支持TCP/UDP](https://wiki.metacubex.one/config/inbound/port/)。实际路由/mark/IPv6仍以固定OpenClash版本的隔离与现场回执放行。

## 4. DNS：移出业务代理故障域，并考虑杭州防火墙

### 4.0 2026-11-16 用户修订：公共多源为主，HK/KR 降级为可选

本小节修订旧 DNS 选型；冲突时以本小节为准。HK/KR 自建 DoH 不再是 Router Final 的必备条件，18443 专用入口方案暂停。原因：自有 VPS 的可达性、续费、单域封锁和单机故障都会变成家庭 DNS 的关键路径；“自有”提高控制力，但不天然提高可用性。

新基线：

1. **公共多源 DoH/DoT 优先**，至少使用不同运营方的标准 443 端点，并用杭州电信与中国移动分别实测；单一公共服务商也不可作唯一前提。
2. **国内域、本地域、bootstrap 仍走国内直连 DNS**，不等待任何海外 DNS。
3. **HK/KR A 记录可保留但默认休眠**；只有在标准 443、电信/移动、长期稳定实测通过后，才可作为公共源之外的可选补充。不再部署或依赖 18443 专用入口作为切换门禁。
4. 若所有海外解析源失败：CN/本地/bootstrap 继续工作；未知海外新域进入 DNS_DEGRADED，可用短 TTL stale 缓存，不改 DIRECT/DNS 规则，不把未知域偷换成国内结果。业务代理侧可由远端节点解析域名。
5. DNS 健康检查、TLS 验证、provider 归因和故障隔离逻辑继续有效；不能因某公共端点可用就把它当永久可信根。

因此，当前路由器候选不等待 HK/KR DNS 服务；旧 A 记录可以保留为休眠规划资源，但不应进入默认配置。


**固定选择：AGH继续服务LAN/WG的53端口；dnsmasq继续DHCP/本地与国内应急；全部客户端DNS上游不经过Mihomo或业务节点。保留real-IP，首版不向家庭终端发放Fake-IP。**

本轮通过单次子进程GID65534命中现有output豁免，固定IP/SNI/TLS正常验证，无环境代理、无路由器规则修改。CF/Quad9/AdGuard/ControlD/DNS.SB若干公开端点在本次预算内超时/TLS失败；国内AliDNS同方法48ms成功，但`www.youtube.com`返回69.171.235.22，不能当可信海外解析。结论仅适用本次杭州电信路径，不推测中国移动结果或永久归因。Mullvad公共DNS官网已公告2026-11-02停服，也不加入备用。

因此，**不将常见公共DoH直连作为本方案的可用前提**，采用专用自建加密DNS端点（**2026-11-26 状态：HK 机器 hka 已退役、`dns-hk`/`kix` A 记录已删除，HK 侧退出；自建 DoH 仅剩 `dns-kr` 一路休眠候选，按 2026-11-16 修订不作 Router Final 必备**）：

- 首选`ora-kr`（`hk` 侧 2026-11-23 退役、`dns-hk` 记录 2026-11-26 删除，退出候选），部署隔离AGH解析服务，由Caddy提供标准TLS的`dns-kr.magichub.top:18443` DoH。复用现有机器，不新增家庭DNS中间层，不动其无关线上服务；端口占用、磁盘/内存/架构与证书先预检。ARM韩国使用已验证arm64构建。
- 这两台的DNS角色与业务代理池分开，**相同端点/故障域不再作为日常业务代理候选**，避免“全部业务节点失效”同时击穿DNS。DNS端点不是质量评分更高的代理节点，不参与地区测速/AI排名。
- DNS服务只开放TLS解析入口，不开放公网UDP/TCP53递归；每设备独立DNS-only随机路径token，Caddy鉴权后重写为标准DoH路径，适配仅支持URL的客户端；不要求各平台额外HTTP header。该私密URL按凭据加密存储/分发，公开DTO/脚本/日志不包含它；关闭或脱敏URI日志，限速且不复用订阅/控制器令牌。
- 证书固定复用KR现有1Panel v2.4.0的Cloudflare DNS-01发行链，为两个DNS域分别签发单SAN证书并开启续期；不分发已有wildcard私钥。HK通过固定受限DNS-only部署通道取其证书，续签核验SAN/链/有效期/密钥配对后原子替换，仅reload新DNS Caddy。标准Caddy加载文件证书，`auto_https off`并显式TLS，独立管理监听/存储，仅监听18443，不抢现有80/443或依赖Cloudflare插件。现有发行链不证明当前DNS写权限，实施时真实签发核验，失败保留旧家庭配置、不关闭TLS验证。
- 两端点地址/证书名/bootstrap均冻结，R6S和Stash的**明确DNS控制面直达规则**位于通用代理之前，限实际地址/端口/用途；不是“整个DNS服务器所在ASN放行”。规则重载后检查它仍不经过Mihomo业务代理。远端上游访问在海外，不依赖家庭节点；服务器resolver健康/证书到期由控制面独立监控。
- 默认18443须通过电信/移动与实际客户端；该端口受阻时，固定改为**同主机标准443的独立SNI虚拟主机**，不改变无关站点路由，先语法检查再reload。现场HK的80/443/18443无监听，KR现有80/443在用但18443空闲：KR优先独立18443，443分支需给现有反代新增独立host并演练回退。仍不通过则阻塞该部署，不先切家庭DNS，不偷换成经代理公共DoH。
- 新业务候选递归排除这两个DNS角色，但旧构建/手机缓存尚可能引用它们；先独立部署DNS，**不提前停止旧代理服务**，待各批迁移/留存引用确认后才退出旧业务角色。并发/同机故障关系写进inventory，不能只改显示标签宣称独立。

这是本次迭代的明确新增部署任务，不是现有已运行能力。本轮已只读确认HK有Caddy、可用内存约1GiB/磁盘约15GiB，韩国arm64有Docker且资源充足；两机用无环境代理的原生连接向可信上游查询测试域均得到HTTP200/正常DNS响应（约84/38ms）。这证明后端路径可行，**没有证明尚未部署的入口已可达**；尚未安装DNS服务、创建记录或证书。

证书核验补充：KR当前有效证书公开SAN覆盖`*.magichub.top`及根域，2026-12-27到期，已有自动DNS-01续期；HK现有证书只覆盖`hka.magichub.top`，不覆盖新DNS域。公开NS为Cloudflare，两个新DNS域尚无A记录，实施时以现有授权创建DNS-only记录；不据NS信息推断已持有写权限。发行与续期路径已固定，不再将选哪种ACME方案留待现场猜测。

DNS凭据复用01的加密私密资源存储与02的受控物化流程：引擎默认配置、DNS意图、普通DTO和策略快照只存安全资源引用；只有带设备授权的私密产物及服务器受限配置包含完整DoH URL。界面默认遮蔽路径token，显式reveal才可查看；日志不得记录带token的URI。它不是新增任意YAML覆盖层，DNS仍由引擎默认配置与受控DNS意图编译。轮换生成新资源revision，保留仍有有效旧客户端引用的短期凭据，按撤销/留存策略退出旧版本；不能直接换服务器token使所有旧设备一起失效。

正常解析DAG：

```text
家庭终端 / 经WG获准的回家设备 → AGH:53
  本地域 / PTR                    → dnsmasq:5353（不回指AGH/Mihomo）
  已审大陆域/受保护大陆应用       → 两家国内DoH，原生WAN
  其他及尚未分类域名              → DNS-KR（HK 侧已退役），原生TLS，不经业务代理

Mihomo自身节点bootstrap            → 固定国内基础DNS，不走业务组，不依赖自己
本机内部DIRECT解析                 → 国内基础DNS
其他内部可信解析                   → 同一独立DNS控制面，不回指AGH形成环
```

AGH的CN/本地条件由同一DNS意图编译，保留精确/后缀语义；无法等价表示的意图构建时拒绝，不整域放宽。未知域名正常也取得可信真实地址，避免把“先知道它是海外”作为正确解析前提。

**异常处置固定：**

| 事件 | DNS动作 |
| --- | --- |
| 美国/日新节点或全部业务节点失败/极慢 | 不切国内DNS、不等待业务复核；独立DNS照常 |
| OpenClash/core停止、挂起、reload | AGH与dnsmasq继续原生工作；守护处理透明接管，不把DNS送到死核心 |
| 一个独立可信DNS失效 | 使用另一独立端点，有界超时/熔断，不重复排队 |
| 两个可信DNS均失效 | `DNS_DEGRADED`，立即保留CN/本地分支，default显式临时改国内应急并告警“海外解析可信性降级”；不把国内结果标可信海外答案 |
| AGH进程失效 | 独立守护把本owner DNS入口转dnsmasq5353国内应急并告警；恢复确认/清理自身缓存后回原bundle，不依赖AGH API自救 |
| dnsmasq失效 | AGH大陆DoH/可信DNS继续；本地DHCP续租/本地域单独告警与procd恢复，不停止整个代理 |

DNS应急判定使用本地可控探针和控制面结果，不用Google成功作为唯一健康信号。失败不缓存成长期NXDOMAIN；应急与恢复有独立epoch/事件记录。查询业务故障与DNS控制面故障分开，不把两端点TLS证书过期伪装成“所有美国节点挂了”。

两端点全失效确认由独立DNS状态机在3秒总预算内完成，原子替换AGH default配置、不重启共享AGH；已审CN条件从第一时刻独立，不等待这3秒。恢复需连续3次受控查询成功、相隔10秒再回可信default。未知国内域在额外的双DNS故障转换期受此预算保护，不能声称绝对零等待；它与代理节点故障是不同矩阵。state/epoch/last-good持久化，重启不丢国内应急。

**外出客户端独立验收：**家庭AGH状态机不能控制蜂窝手机DNS。可信DoH只配入已经验证的客户端，不强推系统级fail-closed DoH profile；`follow-rule`默认关闭、节点bootstrap/国内域走独立基础DNS，保留系统/运营商DNS作为退出客户端后的基础路径。实际Android/macOS/iOS必须分别验证双可信DNS失效时国内解析有界回退；仅正常态可达不算通过，缺能力就阻塞该客户端推广，不照搬家庭自愈结论。[Stash DNS](https://stash.wiki/en/features/dns-server)

AGH LAN限流改为0，前提是53只准LAN/获准WG/loopback且WAN关闭；保留小缓存，关闭会影响功能的全局强拦截。dnsmasq明确`noresolv=1`、国内上游两家、本地/PTR，禁止include产生回指；IPv6 AAAA在双栈验收通过后再解除旧filter-AAAA，不仅改一处核心ipv6开关。广告仍执行宁漏不误杀。

## 5. WireGuard仅回家，不抢出海默认路由

现有wg0监听51820，保留其网段与peer身份/密钥。路由器peer AllowedIPs只对应各自/32（有IPv6才各自/128），不增加0/0或::/0；不把wg0设为WAN默认。

外出优先在现有Stash配置中使用**WireGuard出站节点+既有路由回家组**，只把家庭内网与明确家庭域路由回家；避免手机同时启动Stash与系统WireGuard争抢一个VPN槽。对这些设备，回家精确规则须排在通用private/DIRECT前，不能被`_direct_domains`置顶规则抢走；按设备scope新增结构化规则与已核实hosts，不整体重排其他用户规则。该节点为各设备独立peer，不复用多设备私钥，纳入私密节点/资源与撤销流程。

显式系统WireGuard配置保留给确需的设备，其客户端AllowedIPs仅家庭/隧道子网；DNS如使用家中AGH则到隧道地址，经隧道路由，不将国外DNS通过家庭OpenClash套第二次。能按域分派的Stash仅将家庭域的解析送家中AGH，普通域仍按移动设备DNS策略。家庭端禁把WG流量默认再转业务代理；LAN内访问不进WAN SQM，不无端给NAS文件传输限到50M。

PPPoE MTU1492、现WG MTU1420。跨IPv4/IPv6封装推荐WG MTU1400作为候选，用内网大文件/PMTU/UDP和回程实测后封包；不会仅因小ping正常就确认无MTU问题。MSS clamp只作用相应forward链，不写全局固定MSS影响其他设备。WG控制mark与OpenClash mark分域，CAKE不覆盖它们。

家庭可信Wi-Fi在支持的平台配置Stash按需连接的排除SSID，自动停终端VPN，外出再启用，避免端侧隧道又被R6S代理；首次设置本机采集/确认实际SSID，不凭文档猜名字。Android/macOS/iOS分别验证，不支持的版本先升级/适配。该设置不要求给NAS或Mac mini安装代理。[Stash按需连接](https://stash.wiki/en/features/on-demand)

## 6. SQM分开校准，不与路径修复混改

保持CAKE+pppoe-wan/ifb，软件/硬件offload关闭。当前900/50Mbit/s是有效保守配置；用户提供上行常见60–80、峰值100，不能按100峰值设整形。

网络路径与DNS稳定后，最后单独窗口做电信原生WAN三组短时上/下行及满载延迟对照（不经代理、不跑全节点测速）。初始候选下载900、上传55Mbit/s，选稳定可持续低值的90%–95%，以满载国内DNS/TCP延迟、丢包与CPU余量验收；55M若使延迟劣化就回已保存50M。仍不合格则按实测稳定值重新计算并重跑报告，不追100M峰值。

不把低业务吞吐直接认成SQM：同时检查qdisc backlog/drop、CPU软中断、PPPoE MTU/MSS、节点协议/服务器、移动/电信视角。代理媒体可以消耗共享物理带宽，CAKE负责公平排队；验收要求代理下载/上传满载时大陆查询与新连接不被长期饿死。吞吐与loaded latency分别报告，不承诺网络满载时零延迟变化。

## 7. 全故障矩阵：必须逐项通过

在隔离网络先运行，最后只对已审灰度scope做实际注入；不在本轮生产停止服务。

| 注入 | 海外允许结果 | 大陆必须结果 |
| --- | --- | --- |
| 当前节点断线 | 有界复核/合格备用自动切换 | 原DNS/DIRECT不变 |
| 所有US失败 | 先完整US证据再SG，再JP | 不等待档位遍历、不换DNS |
| 所有SG/JP失败 | Google留US；其他按政策恢复 | 原DNS/DIRECT不变 |
| 所有业务代理节点失败而core活 | 海外明确不可用并退避，不DIRECT | 国内仍可解析/访问，无海外DNS等待 |
| 节点极慢、TLS/UDP黑洞 | 受影响业务降级/同区换合格节点 | 国内请求不排在节点检测/超时队列后 |
| core正常停/kill/SIGSTOP | BASIC_WAN告警，海外可原生尝试 | 从注入起8秒撤接管、10秒新源端口/冷DNS恢复 |
| OpenClash/fw4重载、旧conntrack | owner重建/受控清理 | 同上；不全局flush，不靠重启全家 |
| 可信DNS单/双失效、AGH失效 | 单备/明确DNS_DEGRADED | 国内独立与本地应急仍工作 |
| WG连入/断开/MTU边界 | 仅家庭内网路径变化 | 家庭默认WAN/DNS和普通终端不变 |
| SQM双向满载 | 受整形限制 | 国内DNS、新连接无持续排队/丢弃，记录与原生对照差值 |

域名样本包含淘宝/支付宝入口、大众点评/美团图片、微信/Apple国内、NAS管理与家庭域，另含国内境外CDN/共享IP、普通未知域、IPv4/6与UDP；失败不以平均分掩盖。先验证首命中，再验证真实出口与页面/API/图片链路。

1. G0核对资产、实际启用设备与电信/移动视角；保存当前有效路由/DNS/SQM/WG/核心摘要和受限恢复材料。当前只读证据不能代替执行当天preflight。
2. 先实现代码、纯状态机、DNS意图/owner、受管恢复脚本、隔离故障矩阵；不改路由器。
3. 在HK/KR独立部署并验DNS控制面：占用/架构/证书/到期/鉴权/原生WAN可达/真实DNS答案/国内与GFW样本。两个端点不达标则保持旧家庭配置，禁止把备用偷换成经代理公共DoH。
4. NAS staging与旧版本兼容冻结、备份恢复通过；主用Android/macOS/iOS逐平台验本机恢复能力，不把一平台API照搬到另一平台。电信+移动真实测试均通过才认定已验证；移动没有样本就明确阻塞相应移动推广，不能拿VPS模拟绿灯。
5. 最终窗口先冻结旧feed并升级NAS，可结束第一窗口；再次核对后最后改R6S：独立DNS→核心外守护→TCP/UDP/双栈接管→灰度故障矩阵，每层验证再下一层。DNS或双栈不通过就恢复完整前一bundle，不带缺项推广。
6. 家庭灰度48小时及一周常规使用，手机家中避免客户端隧道再次被路由器代理，外出回家只WG内网。SQM最后独立校准。自动恢复按独立开关和本机能力回执启用，健康不换出口；整包自动生产发布仍off。

### 9.2 为什么不能直接勾全局开启

固定OpenClash脚本在`auto_smart_switch=1`时，把**所有url-test与load-balance组**改为smart；不直接转换select/fallback。对当前这份活动配置，将影响3个url-test。它没有按Google/AI用途的转换白名单，原select/fallback即使没改，其引用的子组也可能已变。`policy-priority`是软权重，不是US→SG→JP硬门禁；成员池混国或递归混入下档时不能用权重补救。即使全部叶节点同国，也不能把Smart连通反馈当完整地区业务耗尽证据。[固定转换源码](https://github.com/vernesong/OpenClash/blob/8e9b4671192ab14b3f828cb963c1ec240b09e679/luci-app-openclash/root/usr/share/openclash/yml_rules_change.sh#L407)

Smart按目的域/网络及连接反馈选择、重试，不能承诺AI账号会话固定出口。首版排除Google及全部递归子组、AI、地区版权媒体、账号风控/支付、路由回家、DIRECT/DNS/管理与探测控制面。它也不是完全被动：固定源码含恢复/目标状态检查和连接后的主动probe，组/provider健康检查另计；只把interval拉到一周或lazy打开不能证明没有额外公网请求。所有新增请求/字节必须计入已审预算，不与面板并行暗测。[运行版本Smart实现](https://github.com/vernesong/mihomo/blob/96feb2a175eb65b05ae2a60d222a279f90990695/adapter/outboundgroup/smart.go)

### 9.3 受控实验与回滚门槛

1. 全局自动转换始终关闭，只在独立工作目录/网络隔离实例中显式创建一个**同国、2–3个已合格叶节点的通用海外静态下载实验组**；不递归引用可能扩张的跨国组，不含DNS专用角色或未授权住宅。不改用户原组名、sort与规则顺序，不接管全家。
2. 初期`uselightgbm=false`、`collectdata=false`，不设来源/价格权重；模型自动更新关闭。UCI的0多为“不覆写”，不会撤销输入YAML已有的smart/true字段，必须验证最终运行YAML。`sample-rate=0`不能当禁采集开关；关闭的是collectdata。
3. LightGBM若另审，只能离线物化已核来源/许可、模型版本与SHA的文件，先禁网验证；缺/坏模型的首次加载可能主动下载，即使模型自动更新未开。含Smart的`-t`也只在隔离`-d`运行，不能借配置检查改动生产模型/数据库。[模型初始化源码](https://github.com/vernesong/mihomo/blob/96feb2a175eb65b05ae2a60d222a279f90990695/component/smart/lightgbm/lightgbm.go#L539)
4. 放行必须：关键首命中/国家/空池/国内故障case全过，0越档、0额外DIRECT、0关键会话无故换出口；增量主动请求/字节全部可计量且不超已审小样本预算；至少3个同WAN时段A/B复现收益、成功率不低于对照、TTFB P95不劣，并完成48小时灰度/重启/故障回滚。没有可重复收益就维持默认关闭，不能以模型分数宣称IP信誉或解锁改善。
