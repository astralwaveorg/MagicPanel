# 自动恢复与检测策略

2026-11-15 用户最新定案。模式名 `auto_stable_v1`。本文件是检测节奏、恢复默认值、扩大范围和防抖的唯一数字合同，取代V2旧稿的 `weekly_manual`、`record_only`、M5最终默认off。网络/DNS/WG/SQM以[家庭网络运行契约](家庭网络运行契约.md)为准：杭州电信家宽、中国移动外出分别取证，家庭全屋透明、外出客户端与WG只回家内网。实施/灰度前仍保持生产自动化关闭，验收后按本策略启用；本轮没有修改生产。

目标：**少变动、少人工、故障自动恢复**。频繁检查不等于频繁换出口；全面测试、轻量检查、切换现有节点、发布新规则是四种独立动作。用户已选择核心整体故障时恢复全屋原生WAN（海外允许尝试直连）并明确告警。

## 1. 默认节奏

| 动作 | 默认值 | 范围/结果 |
| --- | --- | --- |
| 全面能力/信誉/分类评估 | 每周一04:00，Asia/Shanghai | 全部已授权适用节点；复用既有8000请求/768MiB深检预算；生成排序和资格，不因排名小变动切换健康出口 |
| 来源与规则常规抓取 | 每周，先抓取验证再深检 | 无有效变化不重建；故障指向来源记录变化时仅补抓受影响来源 |
| 地区日检 | 每天08:00，Asia/Shanghai | 每非空地区最多3个独立故障域：当前主力、首备、轮换备用；每节点最多2个受控小请求，不测下载带宽/全部产品 |
| 当前路径哨兵 | 每300秒，仅当前使用或设备预先声明的常用路径 | 同视角按NodeKey/实际出口与探针目标去重，最多4个当前路径，每路径1个小请求；健康不测备用；不执行全部地区/全部节点递归测速 |
| 真实故障事件 | 收到可信事件即处理 | 没有可靠被动事件的客户端由当前路径哨兵补充发现；一次异常先复核，不能直接全量重测 |
| 地区扩大检查 | 日检异常复核后自动入队 | 只查受影响地区全部适用节点的必要连接/受影响服务；不顺带做全源信誉/带宽深检 |
| 全局异常扩大检查 | 多地区确认异常且控制目标正常 | 先控制面诊断，再在预算内全节点必要检查；最多1次/72小时，单个地区或单个服务失败不触发 |
| 正常自动切换 | 有确认故障且备用复核合格 | 同业务、同允许地区优先，只影响新连接；读回确认；不重排规则、sort、组名/节点标识 |
| 自动整包生产发布 | 独立开关，最终默认off | 自动切换已安装候选不需要重新发布规则/DNS/核心；规则/配置/核心大变更仍走测试/灰度/整包门禁 |

300秒哨兵是用户本轮要求自动恢复后明确新增的**当前路径**检测，不是恢复旧版600秒递归扫全机场。UI显示实际请求上界、设备电量/休眠限制与开关，不藏在provider或组默认值里。没有使用状态API时按设备声明的最多4个常用路径运行，不能谎称“只在应用打开时检查”。

## 2. 地区健康阈值与扩大范围

抽样从最近周评估合格节点中选择，优先不同实际出口、不同来源/机器；同IP多个协议不算多个独立样本。没有3个独立出口就用实际数量；住宅未授权不入样本。

1. 两个控制目标属于不同故障域，先排除测试目标、NAS路径/DNS、执行器和WAN共同故障。控制面异常为 `measurement_degraded`，不把所有节点判死，也不通过更多全测放大故障。
2. 该地区有效样本的通过比例 **>50%且至少有1个满足业务要求的可用主备**，不扩大；当前主力单独失败仍立即走定向恢复。
3. 通过比例 **≤50%**，10分钟后复核同一地区；两轮结论一致且样本结果均可判定，才扩大到该地区全部适用节点。unknown/限流/adapter错误不能算失败票。
4. 单独地区连续故障扩大检查最多1次/24小时；后续依靠当前小池恢复与冷却，不重复整区刷屏。
5. 至少 `max(2, ceil(非空地区数/2))` 个地区确认异常，或明确公共来源故障影响达到同等范围，才可申请全局扩大检查。先验控制目标/路径，不同视角分别计数；1个地区时整区检查就是最大范围。
6. 日检是异常发现抽样，**不是证明该地区所有节点均可用/均失败**。Google跨国只能由完整上档适用scope的业务失败证据授权，不能用50%阈值放宽。

日检轮换游标、故障计数、10分钟复核、24/72小时限制跨重启持久化。重复事件合并同一故障窗口；调度重启不从头全扫。

## 3. 主力故障与稳定切换

普通硬故障需同视角2次确认、间隔至少30秒；可验证的服务拒绝按adapter分类，401/403/429/挑战页面不直接等价节点断线。当前首备合格就停止扩大，不测完所有节点才恢复业务。

每个故障窗口先试当前节点，再按已有质量顺序复核最多2个备用、每个最多2个小请求；单轮墙钟≤30秒。没有结果按1、5、15分钟退避分批继续已授权剩余候选，且同地区检查受24小时限制。所有预算/租约共享，未知/执行器异常不能清空原池。

| 状态 | 自动动作 |
| --- | --- |
| 当前健康 | 保持当前；周排名更好也不换，不主动抢回原节点 |
| 当前失败、同档备用合格 | 修改现有select/受管选择并读回；记录旧/新NodeKey、证据/原因、scope和时间 |
| 同档仅有未测候选 | 有界复核并逐批推进；状态为恢复中，不把unknown当失败，也不等用户点按钮才启动 |
| 同档已证明全部失败 | 普通业务按其地区政策找下一档；Google严格走§4；不转DIRECT |
| 所有适用候选明确失败 | 业务不可用，继续按退避恢复；**国内DNS/DIRECT保持工作**，不因海外节点故障修改国内路由 |
| 控制/探测器故障 | 保留最后选择为未确认，暂停自动接受、诊断自身；不将正常节点全淘汰 |

普通故障切换后30分钟最短保持；正常恢复不主动抢回，下一周只更新候选。30分钟内新选节点也确认失效时允许继续救援，不能为防抖固定在坏节点；仍不重复已确认失败的A/B，最多3次切换/业务/10分钟，随后进入有界搜索与告警，不在两点间循环。手动锁保护用户显式选择，但UI必须说明锁会暂停该scope自动切换；旧持久锁保留，不能静默删除。

上游IP轮换不由UID稳定性掩盖；出口冲突使对应业务/会话证明失效，按相同有界流程重评。节点别名不随每天测速变化，分类/状态更新用标签，避免订阅与手选标识反复变化。既有健康连接不批量终止、不清空全屋conntrack。

**慢节点也需要可观察证据。** 小响应通过不代表视频持续传输合格。已有播放/传输异常事件，或当前媒体路径连续两次小探针超过其周基线的3倍且超过2秒时，仅对该当前路径启动一次受控传输样本：最多1MiB、8秒，固定版本受控资源、严格流式截断；30分钟内最多一次，每天最多8次、每7天最多64MiB，计入共享总池。相隔至少30秒的两次样本均低于已声明业务最低速率，且同视角控制正常，才判为质量降级，并按现有候选复核同地区备用。没有可靠传输观测的平台显示覆盖缺口，不声称204检测已解决播放卡顿；不因单次慢样本跨Google地区档位。该条件检查不恢复全节点定时下载，首次没有有效周基线时只消费可信业务异常事件。

## 4. Google严格档位与恢复

唯一地区顺序仍为 **US→SG→JP**，各来源同样适用，所有Google业务共用选择路径；任一合格US可用就用US。日检样本坏、仅主备坏、预算不足、unknown不证明整US耗尽。

跨档恢复任务使用完整已授权、协议适用Google候选scope/NodeKey/path/service版本，分批复核全部上档候选；任一个通过就停在该档。完整失败证明最长有效24小时，scope/revision/路径变化立即失效。不是要求做全产品信誉/播放深检，而是做相应Google资格所需的最小充分检查；检测器若没有判定能力就不伪造耗尽。

已降SG/JP时：每300秒当前路径哨兵可附带**1个最高优先上档恢复候选**，纳入预算；日检对失败上档全部候选做必要复核以刷新/推翻耗尽证据。发现合格US恢复，经2次服务成功且间隔10分钟确认后优先回US；SG优先于JP同理。Google档位回升是普通“健康不抢回”的唯一业务优先级例外。证明过期且复核未完成时保留最后合规选择为待核验，不扩大到更低档；UI显示证据年龄，不声称实时知道未观察节点的状态。

所有三档失效仅导致Google业务不可用；**不使国内走代理，不更改国内DNS**。核心整体故障才触发§7的原生救援，该救援已获用户选择，不能和普通Google降档混淆。

## 5. 不同设备怎样执行，避免中心发布代替实际切换

**R6S：**本地受管恢复执行器消费02纯planner合同，控制器仅改允许列表内的业务select，读取实际选择确认；不靠生成新YAML触发常规恢复。NAS负责深检、地区日检和计划供给；NAS不可达时R6S可用已签名、未过期的本地候选、预算与有限本地探针继续恢复。控制器密钥仅受限存储，管理端口不向WAN开放。核心外守护独立运行。

**主用Stash Android/macOS/iOS：**逐平台开发/验收版本化设备内恢复执行器；有cron/本机HTTP API的版本使用脚本、`X-Stash-Selected-Proxy`指定叶的HTTP复核与`PUT /proxies/{name}`选择，随后GET读回，状态/冷却本机持久。iOS/macOS官方能力不是Android已装版能力证明；通过实际版本探测再选择该平台adapter。蜂窝网络不要求NAS反向连接手机，不开放公网控制端口。首次安装一次配置本机secret与能力验收；secret留本机，不进公共脚本/订阅/日志。脚本与恢复输入分别版本化，私密manifest包含完整候选scope、到期时间、节点标识和service adapter能力。AppleTV只验家庭透明，不强制Stash tvOS；历史客户端配置保留兼容。

官方原语依据：[Stash HTTP API](https://stash.wiki/en/features/http-api)、[定时任务](https://stash.wiki/en/script/scheduled-tasks)、[脚本接口](https://stash.wiki/en/script/syntax-and-interface)。这些原语组合为本项目待开发功能，尚未在用户设备验证。普通native fallback只有传输健康含义，不承担完整Google跨档判定。

**最低能力是发布门槛**：设备不支持cron/本机鉴权/强制叶/选择读回时，先升级至经本项目测试的版本并重验；不将“只会同档fallback/等用户手切”标成本次无人干预目标已完成。升级仍不满足则该设备保留旧配置且阻塞其自动恢复推广，报告准确原因，不静默降级成DIRECT。

Stash VPN进程被系统停止/挂死时，其内部脚本不能救自己；家庭网络的基础上网由R6S外部守护保障。手机蜂窝的系统VPN崩溃恢复取决于实际系统/按需连接能力，04必须真实验收；缺能力不能虚构iOS后台守护。应用内账号风控、加密DRM与任意视频片段故障没有通用可观测接口，HTTP小探针只能覆盖声明的服务阶段；保留“一键该业务异常”作为额外入口，不能把无法观察的故障计为已自动修复。

## 6. 预算与扩大检测停止线

| 范围 | 连续7天请求/应用层读写上限 | 说明 |
| --- | --- | --- |
| NAS及共享受管worker总池 | 30000 / 2.5GiB | 取代旧10000/1GiB；纳入全部observer，不免费乘视角；足以覆盖例行8000、扩大预留8000及小检查，防止子预算之和挤掉恢复额度 |
| 其中例行深检 | 8000 / 768MiB | 原预算不变 |
| 其中故障扩大检查预留 | 8000 / 768MiB | 地区与全局共用；预算预演自动消费已授权预留，不每次等人工批准 |
| 其中地区日检 | 512 / 16MiB | 7地区×3候选×2请求×7天通常294请求；复核另按事件/扩大池结算 |
| 其中当前路径哨兵 | 10000 / 96MiB | 是子上限，不能与其他子池相加绕总池；最多4当前路径，Google上档候选也计入 |
| 其中定向事件恢复 | 512 / 32MiB | 重复事件合并，扩大scope改记扩大池而非伪装普通事件 |
| 其中当前媒体质量复核 | 64 / 64MiB | 仅满足§3触发条件的当前路径；不能独立于总池额外消费 |
| 每台Stash本地执行器 | 10000 / 96MiB估算 | 按设备预算与家庭汇总显示；不复用NAS视角。Stash HTTP脚本无已核实流式硬截断能力，只用受控小响应/超时，字节为估算而非供应商硬配额 |

全局/来源/故障域并发与速率继续复用工程规范：4节点并行、同故障域1、全局1请求/s、单服务0.2请求/s；不是为了用完预算持续发请求。响应小探针≤8KiB、connect≤4秒、单次≤6秒；深检保留其已声明大响应上限。实际节点数与adapter请求数在preview重算，额度不足就分批恢复/待额度释放并告警，不无上限重试。住宅仍需独立探测授权与硬配额，默认零请求。

子预算不是相互预留，例行深检8000的额度优先于无故障哨兵；必要恢复使用扩大检查预留，预算按已承诺事件排队。总额度即将不足时先降低健康哨兵频率并告警，不能停掉本地国内救援/国内DNS，也不能为省请求把unknown改成all_failed。新上限是设计授权额度，不是本轮已消耗流量。

## 7. 国内独立与全屋救援

海外单节点/全部节点/地区节点失效或变慢，都只能影响其代理业务：国内默认DNS、节点bootstrap、本地服务、DIRECT连接不排队等待节点测试、控制器、NAS或海外DoH。核心还健康时国内DIRECT照常；所有节点坏不等于核心坏，不能把全部连接硬送到坏节点。

核心退出、挂起、透明接管残留、本地核心DNS失效时，R6S独立procd守护进入`BASIC_WAN`：8秒内撤本owner失效接管、10秒内国内新源端口/冷DNS连接恢复；独立DNS继续工作，海外允许原生尝试并明确告警。单一海外服务或Google全档失败不触发该模式。正常恢复连续5次本地成功并冷却60秒才接管。具体本地时钟、共享deadline、DNS/nft原子切换与故障矩阵见稳定性补充/04。

## 8. 原任务落点与必测反例

02/Task2–4负责持久调度、配额、视角；Task5–7负责服务证据/状态机/不切健康出口/Google完整scope；Task9负责禁止隐形递归测速；Task14提供安全DTO/API。04.2/4/7/10–11负责R6S与Stash执行器、真实切换/故障/休眠验收；03展示分级任务、阈值、覆盖/预算与切换原因。脚本输出是独立受管恢复产物，不重新启用全局HTTP重写模块。

必测：日检2/3通过不扩大、1/3连续两轮才整区；当前主力坏但地区2/3好仍切备用；同IP三协议只算一个故障域；目标/路径故障不淘汰全库；多个地区失效先诊断控制面；健康一周出口不变；第二个新主也坏不被30分钟防抖卡死；Stash蜂窝NAS不可达仍本地切换；US第三台好不降SG；上档unknown不越档；预算跨重启不清零；核心与全部节点分别故障时国内均可访问。
