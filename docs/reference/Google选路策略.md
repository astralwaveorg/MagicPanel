# Google 全业务的地区优先与回退策略

> Google 按 **美国 → 新加坡 → 日本** 设定地区优先级。生产订阅已提供这三个档位；跨地区自动回退仍须完成真实观测与客户端验收。

## 1. 选择规则

1. 覆盖家宽/住宅、自建机房、机场所有已授权来源。
2. 先评估美国候选。美国优先使用通过业务检测的自建节点，其次是通过检测的其他美国节点。同一来源档内按服务可用性、信誉、稳定性与性能选择。
3. 只有全部适用美国候选已确认不可用，才进入新加坡；新加坡同样全部不可用后，才进入日本。
4. 新加坡或日本延迟更低、吞吐更高、来源更贵，都不允许越过仍可用的美国候选。IP 质量用于档内排序；不能仅因“机场比较脏”就把尚可用的美国节点全部排除后声称美国已失败。
5. 三档均无可用候选时明确显示 Google 不可用，不在普通选路中加入其他国家、DIRECT 或 COMPATIBLE。整台网关核心故障的基础联网政策是另一状态，另见生产迁移设计；不能把美国节点故障当作全屋放行的触发条件。

“合格”由启用/授权、协议支持、已确认地区和所选业务要求决定。国家看目标范围的实际出口，不只看节点名或入口 IP；按目的站分流/WARP、多跳、IPv4/IPv6 与轮换资源分别留证。质量信号未知不是低分证明，认证所需/限流/挑战也不能不分原因统记节点断线。

## 2. 怎样证明“美国全部失败”

候选集合和证据版本必须冻结，报告列出美国应评估总数、成功、明确失败、未知、过期和跳过。未测、预算不足、被取消、适配器整体故障、少量主备失效都不等于全部美国失败。发现未覆盖美国候选时先复核或告警，不能自动越级。

在「构建发布 → 详情 → Google 线路检测」可查看该份订阅在构建时各地区的候选数量、通过、确认不可用、结果不明确和无有效结果数量。这份记录不表示客户端已经切换线路。

普通 204 失败/成功不等于 Google 业务失败/成功。Google 关键项目与判据登记在服务目录，保存部分可用和缺口，不从一个产品的含糊 403 推断所有 Google 产品都失效。单一出口不能同时覆盖所有所需业务时，展示覆盖缺口；新增细分路由需要单独受管设计，不暗增一排供应商前台组。

观测程序用独立保存的 Ed25519 私钥签署路径回执；面板仅登记公钥。回执必须绑定观测者、配置版本、适用范围、观测时间、一次性编号和证据摘要。旧回执、过期回执及密钥轮换前的回执不参与选路。签名只验证来源和内容完整性；仍须由实际探测证明出口及业务状态。任务内逐项执行，请求失联后保留失败记录，不重发同一个项目。

每周深检给出地区内完整候选与计划。客户端只检查当前小池时，不能因该小池失效就声称整档耗尽：默认只在已选地区内恢复；跨地区由中心完整证据和已启用的有界复核决定。若要让客户端跨区自主 fallback，必须另证实它覆盖完整适用地区候选和正确可用性语义，不能简单把三个 url-test 组串起来就作保证。

## 3. 业务覆盖与规则优先

Google 归属规则早于宽泛 AI、媒体、开发、云服务商和国内泛集合。Gemini 归 Google 路径，保留后台 AI 能力矩阵，不新增 Gemini 专属前台组；通用 AI 组的地区变化不能绕过 Google 顺序。Gmail、YouTube 及其账号/OAuth、API、静态资源、图片、视频 CDN、邮件协议、FCM 推送、Meet 媒体等均遵循本策略。

YouTube 的流量成本比较仅在当前应使用的地区内进行，不能为省流量提前从美国换新加坡。Google 的 AI 服务不使用成本排序。研究文档列出完整产品族回归目录与来源；不能只覆盖三张首页，也不能把整个 Google ASN 或全部第三方云客户误当 Google 自营业务。已有明确 REJECT 仍拒绝，放行流量再选地区。

通用健康探针推荐使用受控非 Google 目标，减少把 Google 专项可用性与基础连通混淆；**允许并需要对美国、新加坡、日本候选分别进行有界 Google 专项检测**。此前“非美国节点不得访问任何 Google 探针”的解释撤回。

## 4. 验收反例

| 输入 | 期望 |
| --- | --- |
| 一个美国可用，多个新加坡/日本更快 | 美国仍胜出 |
| 选中美国主备失败，但还有未核对美国候选 | 不能自动切新加坡；提示/执行已启用的地区复核 |
| 所有美国明确失败，新加坡可用 | 新加坡；保存美国耗尽证据与下一档选择理由 |
| 所有美国、新加坡明确失败，日本可用 | 日本 |
| 美国适配器整体异常、429 或预算未覆盖 | 不认定美国整档失败；熔断淘汰，保留可信计划/告警 |
| 三档全部明确失败 | Google 业务明确不可用，不把普通业务 fallback 变成 DIRECT |
| Gemini 命中宽泛 AI 或 YouTube 命中宽泛媒体 | 校验/解释指出冲突，修正后遵从相同 Google 地区顺序 |

此处是有限、可验证的选路规则，不把静态名单或周样本宣称为所有未来服务永久可用。阶段、设备与故障恢复的实际能力应如实显示；路由器所有写操作仍最后进行。
