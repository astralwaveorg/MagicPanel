## 配置全景

面板里可配的东西一共十一类，按「先定大框架、再填内容」理解最省事：

| # | 配置 | 决定什么 | 改完要不要重新发布 |
| --- | --- | --- | --- |
| 1 | 节点来源 | 有哪些节点、什么时候更新、哪些留 | 要 |
| 2 | 本地节点 | 自己加的单个节点 | 要 |
| 3 | 规则来源 | 域名 / IP 清单 | 要 |
| 4 | 策略组 | 流量怎么分组 | 要 |
| 5 | 分流规则 | 什么流量走哪组 | 要 |
| 6 | 引擎平台 | 一类客户端的标识与专属扩展 | 要 |
| 7 | 引擎默认配置 | 这一类引擎的顶层键基线 | 要 |
| 8 | 引擎平台配置 | 某个「引擎+平台」的顶层键 | 要 |
| 9 | 设备独立配置 | 某台设备的个性化 | **不用**，分发时实时叠加 |
| 10 | 拓展模块 | 可复用的 YAML 片段 | 要 |
| 11 | 设备 | 每台机器的订阅地址 | 不用（地址即刻生效） |

**判断要不要重新发布**：只有第 9 项（设备独立配置）和第 11 项（设备）是分发时实时生效的，其他都要重新构建发布。

## 产物结构

客户端拿到的 `config.yaml` 由四层合并而成，优先级由低到高：

```text
① 基础配置      引擎默认配置 → 引擎平台配置 → 设备独立配置
② 结构化内容    节点 / 策略组 / 分流规则（服务端生成，任何配置层都不许覆盖）
③ 拓展模块      启用的 YAML 片段，与引擎匹配后深度合并
④ 平台扩展      单个引擎平台专属的 YAML 片段，最后应用
```

产物里有哪些段（以 Stash 为例）：

| 段 | 内容 | 谁维护 |
| --- | --- | --- |
| 基础键 | `mixed-port`、`mode`、`log-level`、`allow-lan`、`ipv6`、`profile`… | 基础配置三层 |
| `dns` | DNS 解析、Fake-IP、策略 | 基础配置 / 拓展模块 |
| `tun` | 接管模式 | 基础配置 / 拓展模块 |
| `proxies` | 节点（含本地节点 `名称 (类型)`） | 节点来源 / 本地节点 |
| `proxy-groups` | 策略组 | 策略组页 |
| `rule-providers` | 规则集引用 | 规则来源页 |
| `rules` | 分流规则 | 分流规则页 |
| `hosts` | 静态域名解析 | 基础配置 / 平台扩展 |
| `mtproto` | Telegram MTProto（仅 Stash） | 设备独立配置 |
| `http` / `cron` / `script-providers` | Stash 专属 | 拓展模块 / 平台扩展 |

**五类键任何配置层都不许写**：`proxies`、`proxy-providers`、`proxy-groups`、`rule-providers`、`rules`。服务端硬校验，写了直接被拒。

## 基础配置三层

### 键与作用域

| 层 | 存哪 | 生效时机 |
| --- | --- | --- |
| 引擎默认配置 | `base_configs`，`engine=<引擎>`、`platform=''`、`device_id=0` | 固化在构建快照 |
| 引擎平台配置 | `base_configs`，`engine`、`platform` 有值、`device_id=0` | 固化在构建快照 |
| 设备独立配置 | `base_configs`，`device_id>0` | 分发时实时叠加 |

**只存与上层不同的差异**：每层存的是「这一层相对上层的差量」，不是完整配置。

### 列表的合并语义（最容易踩）

| 层 | 语义 | 例子 |
| --- | --- | --- |
| 引擎默认配置 | **整体替换** | 上层 `dns.fake-ip-filter: [a, b]`，这一层写 `[c]` → 结果就是 `[c]` |
| 引擎平台配置 | **整体替换** | 同上 |
| 设备独立配置 | **只记新增，分发时追加** | 上层 `[a, b]`，这一层写 `[c]` → 结果 `[a, b, c]` |

设备独立配置用追加语义，是为了「给这台机器加一条过滤」不必把整份列表复制一遍。

### 伪键

| 伪键 | 作用 | 出现在 |
| --- | --- | --- |
| `_direct_domains` | 生成置顶的 `DOMAIN-SUFFIX,<域名>,DIRECT` 规则 | 引擎默认配置 / 引擎平台配置 / 设备独立配置 |
| `_fake_ip_filter` | 写进 `dns.fake-ip-filter` | 同上 |
| `_panel_direct_rule` | 面板域名强制直连（置顶 `DOMAIN-SUFFIX,<面板域名>,DIRECT`） | 同上 |

伪键只存在于配置层，编译时会被翻译掉，产物里不会出现。

### 常用顶层键

| 键 | 说明 | 备注 |
| --- | --- | --- |
| `mixed-port` | 混合端口 | |
| `mode` | `rule` / `global` / `direct` | |
| `allow-lan` | 允许局域网连接 | MTProto 依赖它 |
| `ipv6` | 是否启用 IPv6 | |
| `log-level` | 日志级别 | |
| `profile` | `store-selected` 等 | |
| `dns.enable` | Mihomo 内核接管 DNS | Stash 由客户端接管 |
| `dns.nameserver-policy` | 按域名指定 DNS | 设备独立配置常用 |
| `tun` | Mihomo 的 TUN 模式 | 设备独立配置常用（桌面机） |
| `hosts` | 静态解析 | Mac mini 连家里 NAS 用 |
| `mtproto` | Telegram MTProto | **仅 Stash**；`port` / `secret` / `ipv6` / `dc-config-url` |

### 预设

`base_config.PRESETS` 里内置（**基础配置**的预设，经 `/api/v1/base-config/schema` 下发）：

| 预设 | 引擎 | 说明 |
| --- | --- | --- |
| Stash 官方完整默认 | stash | 按官方文档补全：DNS、嗅探、Geo、HTTP 引擎、Google 中国站重定向 |
| Mihomo 官方完整默认 | mihomo | 按官方文档补全：DNS、Geo、嗅探（HTTP 引擎是 Stash 专属） |
| 兼容现状（精简） | stash / mihomo | 精简版 |
| MTProto 代理（Telegram） | stash | 套用时现场生成 32 位十六进制密钥 |

**拓展模块**的预设是另一套，纯前端常量，在 `src/snippetPresets.js` 的 `SNIPPET_PRESETS`（服务端不提供预设接口）。

## DNS 段：防污染

DNS 段写在**引擎平台配置**层（5 个 Stash 平台 + 3 个 Mihomo 平台各一份），源码基线在
`server/app/services/base_config.py` 的 `_DNS_COMMON` / `STASH_DNS` / `MIHOMO_OFFICIAL`。

### 为什么不能直接用国内解析器

2026-10-25 从家里出口（R6S PPPoE，运营商直连）实测的结论：

| 通道 | 实测结果 |
| --- | --- |
| 明文 UDP（119.29.29.29 / 180.76.76.76 / 223.5.5.5 / 168.95.1.1） | 链路被注入，`www.google.com` 返回 104.244.42.197 这类假 IP |
| 国内 DoH（dns.alidns.com / 223.5.5.5 / doh.pub / dot.pub / 1.12.12.12 / 120.53.53.53） | 加密挡住了链路注入，但**解析器服务端自己投毒**：同一个端点从境外出口查也还是假 IP |
| 境外 DoH（1.1.1.1 / 8.8.8.8 / 9.9.9.9 / dns.google / quad9 / dns.sb / adguard / OpenDNS） | 国内直连一律超时或被重置 |

同一个解析器的 JSON 接口（`/resolve`）返回真 IP，而 DoH 线格式接口（`/dns-query`）返回假 IP——
客户端用的正是后者，所以**国内解析器在客户端里拿不到真 IP**。

### 现在的方案：境外 DoH 走代理

唯一能拿到真 IP 的路径是让 DNS 查询走代理出口：

| 引擎 | 写法 | 出处 |
| --- | --- | --- |
| Stash | `nameserver: [https://1.1.1.1/dns-query, https://8.8.8.8/dns-query]` + `follow-rule: true` | Stash 没有 Mihomo 的 `#策略组` 语法，只能开 `follow-rule` 让 DNS 查询按分流规则转发 |
| Mihomo | `nameserver: [https://1.1.1.1/dns-query#🚀 默认代理, …]` | 直接指定出口组，不需要 `respect-rules` |

配套的几条：

- **DNS 服务器一律写裸 IP 形式**。官方文档把「DNS 服务器地址是 IP 而不是域名」列为避免递归查询的前提
  （Stash 文档「DNS 查询跟随规则」一节），写域名会多一层引导解析。
- `default-nameserver` 只负责解析 DoH 服务器的域名，官方要求必须是纯 IP，现在用 `119.29.29.29` / `180.76.76.76`。
- `proxy-server-nameserver` 解析节点域名，是**独立链路、不跟随规则**，必须国内可达，现在用 `https://doh.pub/dns-query` + `119.29.29.29`。
- `fallback` / `fallback-filter` 给敏感域名留一条备用解析器（Quad9），过滤条件只用 `ipcidr` + `domain`，
  **不用 `geoip` 判定**：主 DNS 已经是干净的境外解析器，没有"国内污染值"要筛，用 geoip 只会多一个 geo 数据依赖。
- 国内域名仍然走国内解析器（`nameserver-policy` 里按 `rule-set:<集合>` 和 `+.cn` 指到 `doh.pub`），
  避免国内站点的 CDN 解析被境外出口改写。`doh.pub` 与 `alidns` 实测返回同一批国内 CDN 节点。

### 改 DNS 段时必须同时成立的前提

1. 规则里有 `IP-CIDR,1.1.1.1/32` / `8.8.8.8/32` / `8.8.4.4/32` / `1.0.0.1/32` → `🚀 默认代理`
   （`follow-rule` 靠这几条把 DNS 查询送进代理；删掉这几条，DNS 直接超时，全网解析失败）。
2. 规则集 `dns-direct`（国内 DNS 直连域名，含 `doh.pub`）让国内解析器的连接保持直连。
3. `nameserver-policy` 里的 `rule-set:<name>` 要**逐个集合写成独立的键**。
   `rule-set:cn,cn-services,ai-cn` 这种逗号合并写法是 Stash 专有扩展，Mihomo 不认，
   合并键在 Mihomo 客户端上静默失效，国内域名会全走境外解析器。

### 怎么验证

DNS 段改完，静态校验查不出问题（Stash 目标只做静态校验），要真跑：

```bash
# 用真实产物在 mihomo 上实跑（Stash 产物剥掉 Stash 专有段，follow-rule → respect-rules）
mihomo -d /tmp/dnstest -f /tmp/dnstest/config.yaml
dig @127.0.0.1 -p 1053 www.v2ex.com A +short        # 期望 172.66.133.207（真 IP）
dig @127.0.0.1 -p 1053 www.baidu.com A +short       # 期望国内 CDN（如 180.101.49.44）
```

日志里 `[DNS] ... from https://1.1.1.1:443/dns-query` 表示走了境外 DoH，
`from https://doh.pub:443/dns-query` 表示命中了国内策略。

## 节点来源

`base_configs` 之外的表：`sources`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `name` | 来源名 | 必填 |
| `url` | 订阅地址（加密存储） | 必填 |
| `enabled` | 是否参与分发 | true |
| `filter` | 节点过滤正则 | 空 |
| `ua` | 抓取时的 User-Agent | `Stash` |
| `interval` | 抓取间隔（秒），0 = 关自动抓取 | 21600 |
| `test_interval` | 测速间隔（秒），0 = 关自动测速 | 21600 |
| `client_interval` | 客户端更新间隔，0 = 跟随抓取间隔 | 0 |
| `auto_fetch` | 自动抓取开关 | true |
| `auto_test` | 自动测速开关 | true |
| `allow_private` | 允许内网地址节点 | false |
| `filter_unavailable` | 只分发可用节点 | false |
| `proxy_url` | 抓取走代理的地址（加密存储；留空 = 直连） | 空 |

**要点**

- 抓取失败时用上一次成功的快照继续服务。
- `filter_unavailable` 打开后，抓完自动补测；自动构建发布要求来源有可用测速结果。
- 节点来源整体被「过滤正则」筛掉的节点不会进产物。
- 删来源前要先看策略组有没有引用它（有引用会被拦下）。
- `proxy_url` 非空时抓取经该代理出网（服务端出不去机场订阅站时的兜底），
  界面默认给 `http://10.0.1.8:7890`，可以改。
- **这个地址是 Mac mini 上的 Stash 混合端口**，而面板本身跑在 NAS 上，
  所以必须写内网地址 `10.0.1.8`；写 `127.0.0.1` 会连到 NAS 自己、抓取全部失败。
  详见[环境与地址速查](reference/环境与地址.md)。

## 本地节点

表：`local_nodes`。

| 字段 | 含义 |
| --- | --- |
| `name` | 节点名（产物里是 `名称 (类型)`） |
| `node_type` | 本地 / 自建 / 家宽 / 机房 / 专线 / 中转 / 落地 |
| `protocol` | 协议（决定参数表单） |
| `server` / `port` | 地址与端口 |
| `params` | 协议参数（**加密存储**） |
| `extra_yaml` | 额外 YAML 片段 |
| `enabled` | 是否写入产物 |

**要点**

- 协议不同参数不同（hysteria2 要 `auth`、trojan 要 `password` + `sni`…），以 `/api/v1/local-nodes/schema` 返回的表单为准。
- 启用后**不会自动进任何策略组**，要去策略组里勾选。
- 停用的节点不写入产物；策略组引用了停用节点时构建会给出警告。

## 规则来源

表：`rule_providers`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `name` | 集合名 | 必填 |
| `kind` | `remote`（远程）/ `inline`（内联）/ `repo`（仓库托管） | remote |
| `url` | 远程地址（加密存储） | 远程必填 |
| `repo_path` | 仓库内相对路径，如 `rule/magic-chat.yaml` | 仓库来源必填 |
| `inline_content` | 内联内容 | 内联必填 |
| `behavior` | `domain` / `ipcidr` / `classical` | domain |
| `format` | `yaml` / `text` / `mrs` | yaml |
| `interval` | 抓取间隔（秒） | 86400 |
| `client_interval` | 客户端更新间隔 | 0 |
| `proxy_url` | 抓取走代理的地址（加密存储；留空 = 直连） | 空 |
| `enabled` | 是否参与分发 | true |

**要点**

- 分流规则用 `RULE-SET,<集合名>` 引用；引用了**停用或不存在的集合**，这条规则会被剔除。
- `proxy_url` 非空时抓取经该代理出网，界面默认给 `http://10.0.1.8:7890`。
  这是 Mac mini 上的 Stash 混合端口；面板跑在 NAS 上，必须用内网地址，
  不能写 `127.0.0.1`（详见[环境与地址速查](reference/环境与地址.md)）。
- 集合名不能和已有集合重名。
- 内联集合在页面里直接编辑内容，格式与远程一致。
- **仓库托管（`kind='repo'`）**：内容由「自主维护」页同步写入，界面改不动；
  启用状态仍归面板。切换前后的产物逐字节一致（渲染层不读 `kind`，
  分发端点只读 `content`）。

## 策略组

表：`proxy_groups`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `name` | 组名 | 必填 |
| `type` | `select` / `url-test` / `fallback` / `load-balance` / `relay` | select |
| `hidden` | 是否隐藏 | false |
| `use_sources` | 聚合哪些节点来源 | 空 |
| `local_nodes` | 勾选哪些本地节点 | 空 |
| `proxies` | 直接列出的节点 / 其它组 | 空 |
| `filter` | 节点过滤正则 | 空 |
| `url` | 测速地址 | `https://www.gstatic.com/generate_204` |
| `interval` / `timeout` / `tolerance` | url-test 的间隔 / 超时 / 容差（毫秒） | 600 / 8000 / 150 |
| `lazy` | 延迟到被使用才测速 | true |
| `strategy` | load-balance 分配策略：一致性哈希 / 轮询 / 粘性会话 | 空 |
| `local_first` | 本地节点优先 | false |
| `targets` | 适用引擎平台（`["*"]` = 全部） | `["*"]` |
| `devices` | 适用设备（`["*"]` = 全部） | `["*"]` |

**要点**

- 组名会出现在产物里，命名要能一眼看懂用途。
- 引用了不存在的来源 / 节点 / 其它组会被拦下。
- 空组会自动留占位节点，避免客户端把空组改写成别的。
- `targets` 与 `devices` 是**交集**关系：两个都填时，设备必须同时在指定平台上。
- 适用范围多选里的 **「包含所有」**（内部存为 `["*"]`）表示全部：节点来源就是所有来源
  （以后新增的来源自动进来），引擎平台 / 设备就是全部。逐项选满时会自动归一成「包含所有」；
  显式传空数组表示不适用任何平台 / 设备。
- `relay` 组只能用固定成员：不能用节点来源或过滤正则，且至少 2 个成员组成转发链。

## 分流规则

表：`rules`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `type` | 规则类型（见下） | 必填 |
| `value` | 匹配内容 | 必填 |
| `target` | 命中的策略组或 `DIRECT` / `REJECT` | 必填 |
| `enabled` | 是否生效 | true |
| `no_resolve` | IP 字面量规则不触发解析 | false |
| `note` | 备注 | 空 |
| `targets` | 适用引擎平台（`["*"]` = 全部） | `["*"]` |
| `devices` | 适用设备（`["*"]` = 全部） | `["*"]` |

**规则类型分两层校验**（`server/app/config.py`）：

1. **创建时**只认全局 13 种（`config.RULE_TYPES`，`routers/policy.py`）：`DOMAIN-SUFFIX`、`DOMAIN`、`DOMAIN-KEYWORD`、`DOMAIN-REGEX`、`IP-CIDR`、`IP-CIDR6`、`GEOIP`、`GEOSITE`、`RULE-SET`、`SRC-IP-CIDR`、`DST-PORT`、`PROCESS-NAME`、`MATCH`。界面下拉就是这 13 种。
2. **构建时**再按引擎官方白名单复查（`config.STASH_RULE_TYPES` / `config.MIHOMO_RULE_TYPES`）。超出该引擎白名单的类型客户端加载会失败。

`no-resolve` 只对 `IP-CIDR`、`IP-CIDR6`、`GEOIP`、`RULE-SET`、`SRC-IP-CIDR` 有效。

**要点**

- 规则按 `sort` 排序，**从上往下匹配，命中即停**；`MATCH` / `FINAL` 是兜底，永远在最后。
- 兜底之后还有规则 = 那条规则永远不生效（数据自检会报出来）。
- 规则的 `targets` / `devices` 与目标组的 `targets` / `devices` 必须有交集，否则这条规则会被自动剔除。

## 引擎平台

表：`targets`。

| 字段 | 含义 |
| --- | --- |
| `name` | 平台名（如 `Stash-iOS`），会拼进产物文件名 |
| `engine` | `stash` / `mihomo` |
| `platform` | `ios` / `macos` / `tvos` / `windows` / `android` / `linux` |
| `description` | 说明 |
| `extra_yaml` | 该平台专属的 YAML 片段，最后应用 |

**要点**

- `(engine, platform)` 唯一，重复写入返回 409。
- 名称只能含字母、数字、下划线、短横线。
- 删平台前必须指定迁移目标，挂在它下面的设备会一起搬过去。

## 拓展模块

表：`snippets`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `name` | 模块名 | 必填 |
| `category` | 分类（general / dns / panel / script / rewrite） | general |
| `engine` | `stash` / `mihomo` / `all` | all |

**要点**

## 设备

表：`devices`。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `name` | **文件名**（产物文件名就是 `<name>.yaml`） | 必填 |
| `platform` | 平台标签（随所选引擎平台自动带出，不参与文件名） | 必填 |
| `target_id` | 挂在哪个引擎平台 | 必填 |
| `env` | 订阅环境 `production` / `testing` | production |
| `note` | **设备名**（后台与门户展示用） | 空 |

**要点**

- 订阅令牌是自动生成的，数据库里存哈希 + 加密副本；`轮换令牌` 后旧地址立即失效。
- 设备独立配置的键是 `(engine, platform, device_id)`——**设备换平台或平台改引擎时要自动换键**（服务端已处理）。
- 设备删了，它的订阅地址和设备独立配置一起清掉。

### 接口

全部接口在 `/api/v1/**`，写操作需要 `X-CSRF-Token`（登录时返回）和会话 Cookie。

```bash
BASE=https://magichub.top:8443
# 登录，取 csrf_token
CSRF=$(curl -s -X POST $BASE/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"astral","password":"******"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["csrf_token"])')
# 下面所有请求都带上：-b cookie.txt -H "X-CSRF-Token: $CSRF"
curl -c cookie.txt -s -X POST $BASE/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"astral","password":"******"}' > /dev/null
```

**改配置的常用请求**：

```bash
# 新增/更新分流规则
curl -b cookie.txt -X POST $BASE/api/v1/rules -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{"type":"DOMAIN-SUFFIX","value":"example.com","target":"🚀 默认代理","targets":["Stash-macOS"],"devices":["*"]}'

# 调整策略组
curl -b cookie.txt -X PUT $BASE/api/v1/groups/3 -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' -d '{"name":"🚀 默认代理","type":"select","use_sources":[1,2]}'

# 改某台设备的独立配置（读出生效值 → 改 → 写回）
curl -b cookie.txt -s "$BASE/api/v1/base-config?engine=stash&platform=ios&device_id=1" \
  -H "X-CSRF-Token: $CSRF" > /tmp/layer.json
# 编辑 /tmp/layer.json 里的 "content"（YAML），再：
curl -b cookie.txt -X PUT $BASE/api/v1/base-config -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{"content":"mtproto:\n  port: 5753\n  secret: 0123456789abcdef0123456789abcdef\n"}' \
  --get --data-urlencode 'engine=stash' --data-urlencode 'platform=ios' --data-urlencode 'device_id=1'
```

接口清单（122 个）见 `docs/development/接口清单与安卓客户端说明.md`。

### 直接改库

**尽量别这么做。** 真要改：

```bash
ssh archon@10.0.1.2
docker exec magicpanel python3 -c "
import sqlite3; c = sqlite3.connect('/app/data/magicpanel.db')
print(c.execute('SELECT id, name, engine, platform FROM targets').fetchall())
"
```

`archon` 是用户名，NAS 的主机名是 `Altair`；`10.0.1.2` 与 `10.0.1.8` 分别对应 NAS 与 Mac mini，
见[环境与地址速查](reference/环境与地址.md)。

改完必须：

1. `VACUUM` 或至少 `PRAGMA wal_checkpoint(TRUNCATE)`（WAL 模式）。
2. 重新构建发布（快照里固化了旧数据）。
3. 跑一次数据自检。

线上库结构由 `server/app/db.py` 的 `SCHEMA` + 迁移定义，**改结构要走代码迁移，不要手动 `ALTER TABLE`**。

**代码改动**：

```bash
DEPLOY_PROXY=http://10.0.1.8:7890 bash scripts/deploy.sh
```

`DEPLOY_PROXY` 指向 Mac mini 上的 Stash 混合端口。它注入到 NAS 端的构建过程，必须用内网地址 `10.0.1.8`。

**回滚**：面板「构建发布 → 回滚至生产」；代码问题用 `git revert` + 重新部署。

## 改配置的禁忌

1. **不要在配置层写那五个结构化键**（`proxies`、`proxy-providers`、`proxy-groups`、`rule-providers`、`rules`），会被硬拒。
2. **不要在兜底规则后面加规则**，那条规则永远不生效。
3. **不要用超出引擎白名单的规则类型**，客户端会加载失败。
4. **不要给 Mihomo 设备加 `mtproto`**，Mihomo 没有这个能力。
5. **不要建两个同「引擎+平台」的引擎平台**，写入会 409。
6. **不要手动改线上数据库结构**，走代码迁移。
7. **不要把凭据写进仓库**，`scripts/check_secrets.py` 会拦。
8. **改引擎默认配置后要核对官方文档**，`scripts/check_engine_defaults.py` 会逐键对账。
9. **别把设备独立配置当完整配置写**：它只记新增项，写全量会导致上层内容被当成"这一层特有"。
10. **改完记得发布**：配置不发布，客户端拿到的还是旧的。
