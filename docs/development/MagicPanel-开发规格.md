# MagicPanel 远程配置管理：实现规格

日期：2026-10-19；状态：**已实现，本文描述当前代码的实际行为**。本文取代早期方案稿《Remote-Config-Console》，选型背景见[客户端选型与兼容性](../network/Client-Selection-and-Compatibility.md)。

MagicPanel 是家庭自用的代理订阅配置管理服务：一份策略、按目标编译、各设备用固定地址拉取。多位维护者共享同一份数据，账号只用于访问控制，不做资料隔离。

## 边界

- 不开发代理内核，不做流量中转，不提供旁路由或透明代理。
- 不依赖 Stash iCloud 同步；远程完整配置 feed 是唯一权威来源。
- 完整配置的变更走“候选构建 → 通道发布”；节点来源与规则来源的快照独立抓取、独立更新、独立验收。
- HTTP 200 只代表下载成功，不代表客户端已加载、VPN 已启动或规则已生效。服务器只记录下载事实，不推断设备状态。

## 技术栈与目录

| 层 | 实现 | 说明 |
| --- | --- | --- |
| 管理界面 | Vue 3 + Vite + Element Plus | 中文界面，桌面与移动端自适应 |
| API 与分发 | FastAPI（Python 3.12+） | 生产模式直接托管前端构建产物 |
| 数据 | SQLite（WAL） | 单实例单写入；运行数据在 `data/`，不进 Git |
| 配置渲染 | PyYAML | 按目标引擎生成方言 |
| 凭据加密 | cryptography（Fernet） | 订阅地址与节点快照加密落盘，主密钥在 `data/secret.key` |

```text
server/app/            # FastAPI 应用
  routers/             # auth / sources / rule_providers / policy / targets_devices / builds / feed / portal / snippets / misc
  compiler/            # render.py（按目标渲染）、validate.py（静态校验）
  services/fetcher.py  # 受限抓取（SSRF 防护、大小与超时限制）
  security.py          # 口令散列、令牌、Fernet 加密、审计写入
  db.py                # SQLite 连接与建表
server/tests/          # pytest 端到端用例
src/                   # Vue 前端（/portal 为独立展示页，不经后台布局）
scripts/dev.cjs        # npm run dev：同时启动 API 与 Vite
scripts/package.sh     # 打包可部署产物
data/                  # 运行数据（数据库、密钥、构建产物），已 gitignore
```

开发：`npm install && npm run dev`（前端 7100，API 8000，已配置代理）。生产：根目录 `Dockerfile` + `docker-compose.yml` 一条命令部署（见[部署文档](../deployment/1Panel-Docker-部署.md)），或 `scripts/package.sh` 产出裸机压缩包，解压后 `./run.sh` 启动。两种方式均以 `--proxy-headers` 启动，信任反代的 `X-Forwarded-*` 头生成订阅地址。

## 数据模型

| 表 | 要点 |
| --- | --- |
| users / sessions | 维护者账号（PBKDF2-SHA256），门户 PIN 散列存于 `users.portal_pin_hash`；会话只存令牌摘要，含独立 CSRF 令牌 |
| sources（节点来源） | 订阅地址 Fernet 加密（`url_enc`）；最近一次成功快照加密留存；失败不覆盖旧快照；`filter_unavailable` 控制是否只分发可用节点；`test_results` 记录逐节点测速结果；`interval` 为抓取间隔、`test_interval` 为自动测速间隔（0 = 关闭）；`auto_fetch` 关闭后只使用本地快照（定时抓取与一键抓取跳过，仍可测速）；`auto_test` 关闭后不执行定时自动测速（仍可一键/单条手动测速）；`last_attempt_at` / `test_attempt_at` 记录最近一次尝试（含失败），供定时任务判断到期 |
| rule_providers（规则来源） | 远程 / 内联两类；behavior、format、规则数与摘要；`interval` 为远程抓取间隔，`last_attempt_at` 记录最近尝试（含失败） |
| local_nodes（本地单节点） | 手动填写的服务器、协议与参数；`params_enc` / `extra_yaml_enc` 加密落盘；产物中使用 `[单] 名称`，顶层 `proxies` 直接写入；Stash 与 Mihomo 的协议键名分别渲染 |
| base_configs（产物基础配置） | YAML 文档，定义产物的顶层全局键（端口、模式、日志、IPv6、profile、DNS 及任意自定义键）；按 `engine` + `platform` + `device_id` 存放，构成**三层联动**：内置默认（程序内置，只读）→ 通用配置（按「引擎 + 平台」，与引擎平台一一对应）→ 设备专属（按设备）；每层只存与上层不同的差异；引擎与平台两级随构建快照固化，设备级在分发时叠加 |
| proxy_groups（策略组） | select / url-test / fallback；成员引用、节点来源、本地单节点 ID、过滤正则、测速参数 |
| rules（分流规则） | 有序、首条匹配；RULE-SET 引用规则来源；MATCH 兜底 |
| snippets（功能模块） | 脚本 / 复写 / 面板 / DNS / 通用五类 YAML 片段，按适用引擎（stash / mihomo / all）在构建时合并 |
| targets（引擎平台） | 一个引擎平台 = 引擎（Stash / Mihomo）+ 平台（iOS / macOS / tvOS / Windows / Android / Linux），对应一类客户端；`name` 建议写成「引擎-平台」（如 `Stash-macOS`）；另含平台扩展 YAML（顶层整键覆盖）；`sort` 控制界面展示顺序 |
| devices（设备） | `name` 是下载配置文件名（唯一，写入 `Content-Disposition`）；`note` 是用户可读的设备名，后台与门户优先展示，留空回退文件名；绑定引擎平台与通道；令牌存 SHA-256 摘要、前 10 位指纹与 Fernet 加密副本（`token_enc`，用于后台与门户重新展示地址） |
| builds（候选构建） | 不可变策略快照 + 逐目标校验结果；产物落盘 `data/builds/<id>/<目标>.yaml`；可删除非活跃构建，删除时一并清理产物与发布历史 |
| releases / pointers | 发布历史与通道指针；发布只移动指针，原子生效；指针同时记录最近一次发布的 `released_at` / `operator` / `action` / `reason`，供界面展示当前版本来源；发布历史只保留最近 10 条（完整操作仍在审计日志） |
| audit | 维护操作与设备下载记录；不含令牌与凭据 |
| automation_runs | 自动任务运行记录：触发方式（manual / scheduled）、时间与完整 summary JSON；最多保留 50 条 |
| settings | 对外基础地址、会话有效期、更新提示间隔，以及自动任务的开关、构建间隔、自动发布通道等 |

## 编译与校验

1. 构建时把来源、规则来源、策略组、规则、目标固化为 JSON 快照（`policy_sha` 为内容摘要），后续修改策略不影响已生成的构建。
2. 逐目标渲染：Mihomo 的节点来源鉴权键为 `header`，Stash 为 `headers`；DNS 段只发给 Mihomo（Stash 由客户端接管 DNS）；启用的功能模块按合并顺序与引擎匹配后深度合并（字典递归、列表追加、标量覆盖），目标扩展 YAML 最后应用、优先级最高。
3. 产物分四层合并（优先级由低到高）：① 基础配置（内置默认 → 通用配置（引擎+平台）→ 设备专属，来自「产物配置」页；引擎与平台两级固化在构建快照里，设备级在分发时叠加）② 结构化内容（节点、策略组、规则，恒由服务端生成，基础配置与扩展都不得覆盖）③ 功能模块（可复用片段）④ 引擎平台扩展（单平台覆盖）。订阅来源仍以 `{FEED}` 占位；本地单节点直接写入顶层 `proxies`，名称为 `[单] 名称`，因此构建产物与 builds 快照会包含本地节点凭据，只能在管理端预览。
4. 策略组的 `local_nodes` 保存本地节点 ID；渲染时解析为 `[单] 名称` 并追加到该组 `proxies`。停用的本地节点不写入产物，策略组引用停用节点时给出警告。
5. 引擎方言差异（依据 Stash 与 Mihomo 官方文档）：远程代理集 —— Stash 用 `headers` + `benchmark-url` / `benchmark-timeout`，Mihomo 用 `header` + `health-check`；策略组 —— Stash 无 `url` / `timeout`（测速参数来自节点与集合级 `benchmark-url`），`load-balance` 的 `strategy` 只输出 `consistent-hashing` / `round-robin`，Mihomo 另支持 `sticky-sessions`；本地单节点 —— Stash 的 Hysteria2 用 `auth` + `up-speed` / `down-speed`、TUIC 必须带 `version`，Mihomo 用 `password` + `up` / `down`；`udp` 只在官方有文档的引擎输出。
6. 静态校验：YAML 往返、策略组引用存在性、循环引用检测、空组、本地节点引用、规则目标存在性、RULE-SET 引用、正则合法性、兜底 MATCH 存在、重复规则提示。任一错误使构建失败且不可发布。
7. 基础配置保护：基础配置、目标扩展与设备专属扩展都不得写入 `proxies` / `proxy-providers` / `proxy-groups` / `rule-providers` / `rules`（列表是“追加”语义，写在兜底规则之后永不生效且会绕过引用校验）。
7.1 平台差异化：策略组与分流规则可标注「适用引擎平台」（空 = 全部）；渲染时按目标过滤，被过滤掉的组其引用它的规则自动剔除并记入构建告警；兜底规则 `MATCH`/`FINAL` 永远保留，其目标组被限定到其它目标时强制保留。
7.2 平台能力裁剪：iOS / Android / tvOS 剔除 `PROCESS-NAME` / `PROCESS-PATH`（这些平台不提供进程信息，规则必然不命中），裁剪条数写入构建告警。
8. 面板域名置顶直连规则（`DOMAIN-SUFFIX,{FEED_HOST},DIRECT`）由基础配置里的应用级伪键 `_panel_direct_rule` 控制（默认开启，伪键不写入产物）；`空组保护` 占位节点（`http://127.0.0.1:1`，永远连不通）恒定注入自动组末尾，属安全兜底（防客户端把空组改写成 DIRECT），不提供开关。
9. 个人配置（同样用伪键，不写入产物）：`_direct_domains` 生成置顶的 `DOMAIN-SUFFIX,<域名>,DIRECT` 规则（排在用户规则之前，保证先生效；域名自动去空白、转小写、去通配前缀并去重）；`_fake_ip_filter` 写入 `dns.fake-ip-filter`（Mihomo 替换内置列表；Stash 仅在配置了该列表时才下发 dns 段）。
10. 校验边界：Mihomo 目标在测速核心已安装时追加官方配置检查（`mihomo -t -f`，`{FEED}` 占位替换为回环地址，不发生真实请求），通过标记为“核心校验通过，实机行为待验收”；Stash 没有官方无头校验工具，结果只能标记为“静态通过，实机待验收”。

## 节点测速与不可用过滤

- 测速由固定版本的 Mihomo 核心（当前 v1.19.32）执行，与 Clash 系客户端同一机制：以节点快照生成临时配置启动本地核心（仅监听 127.0.0.1），经 external-controller 逐个发起 delay 测试（通过节点请求 `generate_204`，超时 5 秒，并发 16），结束后进程立即退出、临时目录删除。
- 协议兼容性由核心承担：SS / VMess / VLESS / Trojan / Hysteria2 / TUIC 等 Mihomo 支持的协议都能测；服务自身不实现任何代理协议。
- 结果口径必须如实理解：它反映**本服务器所在网络**到节点的连通性与延迟，不等于带宽、流媒体解锁能力，也不代表客户端所在网络的结果；UDP 行为未单独验证。
- 开启“只分发可用节点”后，feed 的节点子资源只包含测速通过的节点；订阅重新抓取后旧测速结果作废，并会在同一轮调度中立即补测（无需等满测速间隔）。未测速的节点按不过滤处理，因此自动发布前会检查这类来源是否有可用测速结果。
- 核心安装有两种方式：在线安装先经 releases/latest 重定向解析最新版本再下载（解析失败回退到内置版本；httpx 失败时回退系统 curl，可配置一次性代理“核心下载代理”，测速本身不经代理）；本地上传安装接受 .gz / .zip / 裸二进制（≤ 100 MB），按魔数识别格式并自动解压，zip 内取 mihomo 开头的条目。两种方式都做 `-v` 执行校验后原子替换，上传安装不校验版本、可用于升级或降级。安装后记录版本输出与 SHA-256 摘要供人工核对。amd64 平台固定下载 GOAMD64=v1 变体（不带后缀的包实为 v3，低功耗 CPU 无法运行；拨测对指令集不敏感）。
- 构建产物引用的是 feed 子资源地址，过滤生效不需要重新构建或发布。

## 发布流水线

```text
编辑策略 → 创建候选构建（固定快照、逐目标渲染、静态校验）
→ 发到候选通道（单设备试用）→ 发布稳定 → 设备随后拉取
```

- 通道只有 stable / candidate 两条；设备各自绑定通道，候选通道用于灰度。
- 回滚即把通道指针移回任一成功的历史构建；客户端下次拉取才生效，已建立的连接不受影响。
- 节点来源与规则来源的快照更新不触发构建；它们经 feed 子资源独立分发，设备按 provider 自身的 interval 更新。
- 历史构建可删除：删除前校验通道指针，仍被稳定或候选通道引用的构建拒绝删除；非活跃构建删除时同时清理 `data/builds/<id>/` 产物与其发布历史记录。

## 批量操作与引用校验

节点来源、规则来源与构建列表统一提供选择列与工具栏批量操作：

- **一键抓取**：节点来源页抓取全部来源，但跳过关闭了 `auto_fetch` 的本地快照来源；规则来源页只抓取远程来源（内联来源无需抓取）。前端以最多 3 个并发逐个调用单条 refresh 接口，显示完成进度；失败来源保留最近一次成功快照。
- **一键测速**：节点来源页可对全部有快照的来源顺序执行测速（包括关闭自动抓取的本地快照来源），避免同时启动多个 Mihomo 核心；也可勾选后“测速选中”；显示完成进度，核心未安装时先提示安装。
- **批量修改间隔**：节点来源可同时修改抓取间隔与自动测速间隔；规则来源修改抓取间隔。弹窗内输入秒数或选择 15 分钟 / 1 小时 / 6 小时 / 1 天 / 7 天预设。抓取间隔同时写入后续构建产物，由客户端按 provider 间隔更新。
- **批量删除**：先确认，再逐项校验引用；被引用的项目保留，其余删除，结果通过对话框列出未删除项及原因。
- **规则来源检索**：支持按名称或 URL 模糊搜索；表格分页，可选每页 10 / 20 / 50 / 100 条，并提供页码跳转。搜索或翻页时清空当前选择，避免批量操作作用到不可见条目。
- **URL 展示**：规则来源表格不再平铺长 URL，改为“复制 URL”按钮；复制成功后弹窗展示完整 URL，剪贴板不可用时也保留可手动选择的文本。

引用规则：节点来源被策略组 `use_sources` 引用时不可删除、不可重命名；规则来源被任意 RULE-SET 分流规则引用时不可删除、不可重命名（含已停用规则，因为重新启用后会再次生效）；构建仍被通道指针引用时不可删除。单条删除与编辑同样执行这些校验，并返回明确原因。

## 服务端定时任务（自动发布）

`server/app/services/scheduler.py` 在应用进程内运行一个后台循环，默认每 30 秒检查一次到期项目；Docker 单实例部署下不存在多进程重复调度。可用环境变量 `MAGICPANEL_SCHEDULER=0` 关闭自动启动，日常开关在“自动发布”页面。

- **总开关**：`scheduler_enabled`。关闭后循环仍在，但不执行抓取、测速和构建。
- **抓取节点来源**：`auto_fetch_sources`，只处理启用且 `auto_fetch=1` 的来源，按每个来源的 `interval` 判断到期；从未成功抓取的来源会立即到期。失败也推进 `last_attempt_at`，避免每个 tick 重试；失败时保留旧快照。关闭 `auto_fetch` 的来源不参与定时抓取和一键抓取，构建与分发继续使用本地快照。
- **抓取规则来源**：`auto_fetch_rules`，只处理启用的远程来源，按 `interval` 与 `last_attempt_at` 判断到期。
- **自动测速**：`auto_test_sources` 总开关 + 每个来源的 `auto_test` 开关，按 `test_interval` 判断（0 = 不自动测速）；需要有节点快照且测速核心可用。`test_attempt_at` 记录失败尝试，核心不可用时跳过且不误报。启用“只分发可用节点”的来源在抓取成功后会把 `test_attempt_at` 置空，调度器在同一轮抓取后立即补测；其他来源仍按自己的测速间隔执行。关闭 `auto_test` 的来源不参与定时测速，但仍可一键测速或单条手动测速。
- **发布前测速门禁**：自动发布前检查所有启用的、开启“只分发可用节点”的来源，必须存在最近一次抓取之后的测速结果，且至少有一个节点可用；否则只记录等待原因，不创建构建、不移动通道指针。测速完成后下一轮自动重试。未开启“只分发可用节点”的来源不参与该门禁，也不会被过滤。
- **自动构建**：`auto_build_enabled`，每 `auto_build_interval_hours` 小时检查一次（默认 1）。只有当前策略快照的 `policy_sha` 与**目标通道当前指向的构建**不同才创建新构建——比较"最近一次成功构建"会让"构建成功但没发布出去"的新产物永远无法上线；没有引擎平台时暂不推进检查时间，添加后可尽快自动构建；自动发布到稳定通道前要求每个 Mihomo 目标都通过了 `mihomo -t` 核心校验。
- **自动发布**：`auto_publish_enabled` + `auto_publish_channel`（stable / candidate），只发布校验全部通过的构建。默认发布到稳定通道；失败的构建不会覆盖当前通道。
- **手动触发**：`POST /api/v1/automation/run` 在后台强制执行一轮，忽略到期时间和总开关，但仍尊重各来源的 `auto_fetch` / `auto_test` 与全局功能开关；状态通过 `GET /api/v1/automation/status` 查看。每次手动运行都会写入 `automation_runs`，并通过 `GET /api/v1/automation/runs` 展示；审计日志同时记录“手动触发自动任务”（含 mode=force）和“手动自动任务运行完成”（含各项计数、构建、发布、错误摘要）。
- **失败语义**：单个来源抓取、测速或构建失败只记录错误并继续其他项目；失败状态会先提交再返回，避免事务回滚丢失。
- **发布历史**：`releases` 只保留最近 10 条（约每日两次发布 5 天），更早的发布仍可在审计日志中追溯。

### 推荐节奏

| 项目 | 推荐值 | 说明 |
| --- | --- | --- |
| 节点来源抓取间隔 | 4–6 小时 | 服务端快照的新鲜度 |
| 节点自动测速间隔 | 6–12 小时 | 避免频繁启动测速核心 |
| 规则来源抓取间隔 | 12–24 小时 | 规则变化通常不频繁 |
| 自动构建检查 | 1 小时 | 仅在策略变化时真正构建 |
| 客户端完整配置更新 | 24 小时 | 设置中的 `profile-update-interval` |
| 客户端 provider interval | 与抓取间隔相近 | 节点/规则子资源独立更新，不受完整配置 24 小时限制 |

客户端拉取完整配置的周期与 provider 子资源周期相互独立：即使完整配置每天只拉一次，节点与规则子资源仍可按各自的 interval 更新；但服务端必须先抓取，客户端才能拿到新快照。

## 门户展示页

根路径 `/` 是独立于后台布局的门户展示页（管理端在 `/admin`），供快速查看与复制订阅地址，移动端自适应：

- 凭 4 位 PIN 进入；PIN 与维护者账号绑定（`users.portal_pin_hash`，只存散列），每位维护者在“设置”中管理自己的 PIN，任一有效 PIN 都可进入，撤销某人的 PIN 不影响其他人；全部撤销后门户页即关闭。PIN 连续输错 5 次锁定 10 分钟（单进程内存计数，任一 PIN 变更时重置）。
- 已登录的维护者访问门户免 PIN（`POST /api/v1/portal/data` 先识别会话 Cookie，无会话且无 PIN 时返回 401，提示输入 PIN 或登录）；门禁页提供“维护者登录”入口，内容页对维护者显示“管理后台”入口、对访客显示“退出查看”。
- PIN 只是查看门槛：订阅链接本身的安全性由地址中的高熵令牌承担，客户端拉取 feed 不需要 PIN。PIN 泄露不等于凭据泄露，撤销并重设即可。
- 展示内容：核心配置（设备订阅地址，按引擎分组，支持复制与二维码）、客户端资源（Stash / Mihomo / Clash Verge Rev / FlClash 官方入口）、分流规则（仅个人维护的非 RULE-SET 规则，点击复制）、已启用的功能模块（按分类，仅名称与备注）、各平台导入指引、连通性自检入口。
- 门户数据接口 `POST /api/v1/portal/data` 校验 PIN 后返回上述内容；没有任何维护者设置 PIN 时返回 404，门户页等同关闭。

## 安全模型

- 会话使用 HttpOnly + SameSite=Lax Cookie；写操作要求 `X-CSRF-Token` 与会话匹配。管理接口不开放 CORS。
- 订阅地址、节点快照、设备令牌副本用 `data/secret.key` 的 Fernet 密钥加密；主密钥不进入备份导出文件，需另行保管。
- 本地单节点的协议参数与高级 YAML 同样加密落盘（`params_enc` / `extra_yaml_enc`）；构建快照 `builds.snapshot` 可能含这些凭据，因此以 `enc:v1:` 密文存储（启动时迁移历史明文行，幂等），密文与 `data/secret.key` 绑定。
- 产物文件本身必然含本地单节点凭据（客户端要用），只应在管理端预览，不做公开分发。
- 抓取默认仅允许 http/https 且拒绝环回 / 私网 / 保留地址；确需内网订阅须在来源上显式开启。单资源上限 10 MB、超时 20 秒、最多 3 次重定向。
- 核心校验用固定工作目录 `data/core-work/`：Geo 数据（`geosite.dat` / `geoip.dat` / `country.mmdb`）放在这里即可复用。配置里出现 `geosite:` / `geoip:` 引用而本地缺数据时，校验会**立即失败并给出可执行提示**（核心默认联网下载，境内常挂起）。安装脚本：`scripts/fetch_geo_data.sh`。
- 令牌由密码学安全随机数生成；泄露后的处置是轮换或删除设备，已下发的节点凭据需联系机场重置。
- 备份导出为 JSON（含加密态数据与令牌摘要）；恢复会覆盖全部数据，需 `confirm=true` 并重新登录。

- “审计日志”页支持勾选批量删除与一键清空。
- “节点来源”页提供“添加订阅”与“添加节点”两个入口。本地单节点协议从服务端 schema 动态渲染：协议、加密方式、传输方式、TLS、UDP 等能选择的一律用下拉/开关，其余字段用输入框；另提供高级 YAML 处理协议差异。节点名以 `[单] 名称` 展示并写入产物，策略组编辑中可按名称勾选本地节点。

- “构建发布”页顶部展示稳定 / 候选通道当前使用的构建号、策略摘要、发布或回滚时间、操作人以及自动 / 手动标签；自动发布完成后指针移动到新构建，旧构建仍保留用于回滚。
- “自动发布”页集中配置自动抓取、自动测速、自动构建与发布通道，并展示最近一轮执行结果、最近 10 次运行记录（手动 / 定时、操作人、结果摘要）和最近 10 条**自动**发布记录（`GET /api/v1/releases?auto_only=true`，手动发布不出现在该页）；构建发布流程在自动模式下合并为一次“构建成功即发布”的动作。“立即运行一次”强制忽略到期时间，前端会轮询状态直到运行结束并刷新记录。
- 术语固定：节点来源、规则来源、策略组、**引擎平台**（= 引擎 + 平台，对应一类客户端）、候选构建、发布、稳定 / 候选通道、功能模块。

## 已知边界与后续

- 定时任务为单进程内后台循环，依赖 Docker 单实例部署；不要对同一数据目录启动多个带调度器的实例。调度器不持久化“正在运行”状态，容器重启后按 `last_attempt_at` / `last_fetched_at` 继续判断到期。
- 自动构建只在策略快照变化时执行（与目标通道当前指向的构建比较）；如果希望固定周期生成一次构建（即使策略未变化），需要另行调整，但通常只会产生重复产物。
- 测速只反映服务器侧网络的连通性；客户端侧是否可用仍以实机为准。
- 设备“最近下载”只证明下载成功，不证明客户端已加载或规则已生效。
- WebDAV 备份推送为预留方向，尚未实现。

### 基础配置三层级联（补充：内置默认可改）

| 层级 | 存储位置 | 语义 |
|---|---|---|
| 内置默认 | 源码 `PRESETS` + `base_configs` 中 `(engine, "", 0)` 的差异 | 源码出厂值即底座；用户改动只以"与出厂值的差异"单独保存，不污染源码 |
| 通用配置 | `(engine, platform, 0)` | 覆盖内置默认，作用于该引擎+平台的全部设备 |
| 设备专属 | `(engine, platform, device_id)` | 只影响这一台设备 |

- 写内置默认时，服务端拿**源码出厂值**做 diff，只保存不同的键；
- "恢复出厂"= 删除 `(engine, "", 0)` 这条记录，出厂值回到源码原样；
- 内置默认被改动后，通用配置与设备专属都会继承新的出厂值；
- 前端在修改内置默认前必须弹出影响面警告（确认框），并提供「源码编辑」入口。
