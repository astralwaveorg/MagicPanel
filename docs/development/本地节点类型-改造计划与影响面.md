# 本地节点「节点类型」改造 · 修改计划与影响面

> 编写日期：2026-10-21
> 目标：本地节点新增「节点类型」属性，导出到设备的节点名统一为 `原名称 (类型)`，取代旧的 `[单]` 前缀。

---

## 一、现状盘点

### 1.1 数据与后端

| 位置 | 现状 |
| :--- | :--- |
| `local_nodes` 表 | `id / name / protocol / server / port / params_enc / extra_yaml_enc / enabled / sort / created_at / updated_at`，**无类型字段** |
| `server/app/services/local_nodes.py` | `MARK = "[单]"`；`marked_name(name) → "[单] {name}"`；`render_proxy()` 用它作为产物 `proxies[].name` |
| `server/app/routers/local_nodes.py` | `_public()` 返回 `marked_name`；创建/更新时用 `marked_name` 与策略组名做重名拦截 |
| `server/app/compiler/render.py` | 组内注入本地节点时同样用 `marked_name`，与 `render_proxy` 对齐 |
| `server/app/routers/builds.py` | `collect_snapshot()` 收集本地节点时**没有**类型字段（渲染层取不到类型） |
| `server/app/compiler/validate.py` | 策略组成员校验只涉及组名/内置目标/空组保护，**不涉及**本地节点名 → 不受影响 |

### 1.2 前端

| 位置 | 现状 |
| :--- | :--- |
| `src/views/Sources.vue:155-189` | 区块标题「本地单节点」，提示「以 [单] 前缀写入产物」；表格「名称」列显示 `marked_name` |
| `src/views/Sources.vue:191-254` | 编辑弹窗：名称（半宽）/协议/端口一行；「启用（停用后不写入产物）」复选框 |
| `src/views/Groups.vue:124,231,334` | 策略组成员选项与展示都用 `marked_name` |
| `src/views/Builds.vue:189` | 产物预览说明写「本地单节点的凭据…」 |

### 1.3 线上数据核查（决定风险等级）

| 核查项 | 结果 |
| :--- | :--- |
| 本地节点名称 | 6 个，名称**干净**（`🇺🇸 美国机房 01` 等，无 `[单]` 前缀——前缀只在渲染期拼接） |
| 策略组如何引用本地节点 | 按 **ID**（`proxy_groups.local_nodes`），不是按名字 → **改名不影响引用** |
| 策略组成员里是否有 `[单] xxx` | 无（`proxies` 只存组名/DIRECT/REJECT/空组保护） |
| 基础配置里是否引用 `[单] 名字` | 无（9 条 base_configs 均无此类引用） |
| 客户端 | Android 只是 WebView 壳，不解析节点名 |

> 结论：**本次改造不触碰任何持久化的名字引用**，风险主要在"产物里的节点显示名变了"。

## 二、目标模型

```
节点类型（node_type）：本地 / 自建 / 家宽 / 机房 / 专线 / 中转 / 落地（单选，可搜索）
产物节点名：f"{原名称} ({节点类型})"      # 类型为空时不加括号
```

* `local_nodes.name` 存**纯名称**（不含类型、不含前缀）。
* 类型后缀的作用：与远程订阅节点**区分**，避免同名节点在客户端里撞车。
* 旧 `[单]` 前缀逻辑整体作废。

## 四、影响范围与风险

| # | 影响 | 处置 |
| :--- | :--- | :--- |
| 1 | **产物里的节点显示名变化**：`[单] 🇺🇸 美国机房 01` → `🇺🇸 美国机房 01 (机房)` | 不影响连通性；客户端会短暂"丢失"上次选中的节点（名字变了），下次拉取后恢复。已在报告与上线说明中标注 |
| 2 | 策略组引用 | 按 ID 引用，**不受影响**（线上已核实） |
| 3 | 基础配置里手工写死 `[单] 名字` | 线上未发现；如有个案需手工改名 |
| 4 | 名称唯一性 | `local_nodes.name` 仍是 UNIQUE；`display_name` 因此也唯一，不会在客户端撞名 |
| 5 | 迁移时清理前缀可能造成重名 | 迁移前先检测，冲突时保留带前缀的旧名并写审计日志，不静默丢数据 |
| 6 | 历史构建快照无 `node_type` | 旧快照重渲染时名称无后缀（历史产物本身不变，符合"快照不可变"） |
| 7 | 客户端名称长度 | Stash / Mihomo 对 proxy 名称无长度硬限制，`名称 (类型)` 只多几个字符 |
| 8 | Android 客户端 | 纯 WebView，不受影响 |

## 五、实施顺序

1. 数据层：SCHEMA + 迁移（`db.py`）

4. 前端：`Sources.vue`、`Groups.vue`、`Builds.vue`
5. 测试：既有用例更新 + 新增专项用例 → `pytest` 全绿
6. 文档同步
7. 部署 NAS（迁移自动执行）→ 重建并发布一次生产版本 → 线上验证

### 6.3 需要注意的事

* 产物里的节点显示名变了，客户端（Stash / Mihomo）里「上次选中的节点」会短暂回到默认，
  下次拉取后恢复；不影响连通性。
* 线上 6 个节点类型目前都是默认的「本地」。可以在「节点来源 → 本地节点」里按实际情况
  改成 家宽 / 机房 / 专线 等，保存后重新构建发布即可生效。
