# 策略组全面优化（2026-10-21）

目标：**人在杭州，境内直连不丢包，境外全部可达，各业务走最合适的线路**。
改动全部通过管理端 API 完成（每步都有审计），上线构建 `#40`。

## 改前的主要问题

| 问题 | 现象 |
|:---|:---|
| **三个空壳手动组** | `白月光手动` / `牛逼手动` / `神龙手动` 的成员只有 `美国优先` 一个 —— 根本没法"手动选节点"，点进去只有一项，等于废组 |
| **本地节点没进区域组** | 本地 🇭🇰 香港机房（实测 215ms）、🇯🇵 日本机房（705ms）只在 `美国自动` 里出现过；`香港自动` / `日本自动` / `日韩自动` / `全球自动` 全都没带上它们，最快的几个节点等于白放着 |
| **没有全局容错** | 只有一个 `美国优先`（fallback），而且名字与实际顺序不符：它其实是"美国优先、其次日本"，被当全局兜底用时语义不对 |
| **`手动选择` 是个大杂烩** | 334 个节点平铺在一个下拉里（3 家机场 + 6 个本地节点），没有分组，用户要在一堆名字里翻 |
| **服务组成员没按业务排** | `人工智能` / `海外媒体` / `YouTube` 等组的成员顺序与业务特性无关（例如流媒体里香港排前面，而 Netflix 港区没有片） |
| **规则顺序偏尾** | `ads` 排在第 65 位（业务规则之后）；`developer.apple.com` 指向 `节点选择`，而它在国内本来就该直连 |

### 为什么这样排

- **默认线路 = `故障转移`**：杭州出发先走香港（本地机房 215ms），香港整体不可用时自动切日本、新加坡、美国、台湾；任何一个区域都还有能用的节点就不会断。
- **AI 类走"美国优先"**：OpenAI / Claude / Gemini 对香港、新加坡 IP 限制多，美日 IP 最稳，顺序是 美 → 日 → 新 → 自动。
- **Google 加台湾**：台湾 IP 在 Google 上通常比香港更干净。
- **YouTube 首选日本**：日本节点对 YouTube 的视频 CDN 命中更好，香港反而绕。
- **流媒体（Netflix / Disney+）首选新加坡**：港区没有 Netflix 订阅内容，新日美台依次兜底。
- **开发 / 技术社区首选港日**：GitHub、npm、pypi 这类在港日节点上最快，不需要绕美国。
- **社交首选新加坡 / 日本**：Telegram、Discord 在这几个地区的 IP 上最干净。
- **苹果服务默认直连**：Apple 在国内可直连，保留 `节点选择` 作为兜底。
- **广告拦截提前**：从第 65 位提到第 18 位，先于所有业务分流生效。

### 规则顺序（131 条）

```
面板自身域名 → DIRECT            （面板/订阅域名必须直连，否则节点挂了连不上面板）
局域网 / 私有地址 → DIRECT
BT / PT / trackers → DIRECT       （P2P 不走代理）
ads → 广告拦截                     （提前到所有业务分流之前）
国内 AI（ai-cn、DeepSeek、豆包、Kimi…）→ DIRECT
国外 AI → 人工智能
Google → 谷歌服务
YouTube → YouTube
流媒体 → 海外媒体
GitHub / 镜像站 / 包管理 → 开发服务
技术社区 → 技术社区
社交 → 社交软件
游戏（国内下载先直连）→ 游戏平台
Apple / 微软国内 → 苹果服务 / DIRECT
cn、cn-ip → DIRECT
日韩服务 → 日韩自动
MATCH → 节点选择
```

另外把 `developer.apple.com` 的目标从 `节点选择` 改成 `苹果服务`（默认直连）——它在国内本来就直连，绕代理没有意义。
