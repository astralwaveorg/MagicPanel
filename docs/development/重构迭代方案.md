# 重构迭代方案

> 状态：**设计讨论稿**，尚未开发。确认后作为开发依据。
> 起草：2026-10-25
> 配套文档：[自主维护-设计方案](自主维护-设计方案.md)（本迭代第三块的详细设计）

## 零、迭代概览

本轮是三块改动合在一起的一次迭代，不只是加一个功能。

| 块 | 内容 | 性质 | 详细设计 |
| --- | --- | --- | --- |
| 一 | **菜单重排 + 页面改名**：侧边栏从 13 项调成 12 项并重排；「产物配置 → 基础配置」「功能模块 → 拓展模块」「设置 → 系统设置」；「引擎平台」并入「基础配置」页 | 信息架构重构 | 本文档 §一 |
| 二 | **构建发布与自动发布合并**：一个页面两个 tab；详情抽屉改成「发布测试」+「一键发布」两个按钮 | 功能合并 | 本文档 §二 |
| 三 | **自主维护**：把 magic-sets 从 submodule 变成运行时可配置、可替换的数据层，管理仓库全部文件 | 新功能 | [自主维护-设计方案](自主维护-设计方案.md) |

三块的耦合点：块一的菜单里有块三的入口（自主维护）；块二的 tab 合并会改动路由，需要与块一的路由重定向一起做。

### 1.2 「引擎平台」并入「基础配置」

引擎平台不再有独立菜单项，改为「基础配置」页的**第一个 tab**：

```
基础配置
├── tab1  引擎平台    （原 Targets.vue：Stash/Mihomo × 各平台的目标清单与排序）
└── tab2  产物配置    （原 ArtifactConfig.vue：引擎默认/平台/设备三层配置）
```

理由：引擎平台是产物配置的骨架——每个目标对应一类客户端，产物按目标编译；没有目标就没有产物（构建会直接报「尚未配置任何引擎平台」）。放在同一页比拆两页更符合认知。

tab 的切换用 query 参数（`?tab=targets` / `?tab=artifact`），这样两个 tab 各自可直达、可收藏。

## 二、构建发布与自动发布合并

### 2.1 页面结构

「构建发布」页用 tab 切换两个面板：

```
构建发布
├── tab「构建」      原 Builds.vue：构建列表 + 详情抽屉 + 发布历史
└── tab「自动发布」  原 Automation.vue：定时任务配置 + 运行记录 + 最近自动发布
```

实现：`Automation.vue` 的内容整体搬进 `components/AutomationPanel.vue`（只去掉页面标题那一行），`Builds.vue` 外层加 `el-tabs`，两个面板用 `v-if` 懒挂载（自动发布面板不需要每次都渲染）。

tab 值走 query：`/admin/builds`（默认构建）、`/admin/builds?tab=auto`。

### 2.2 详情抽屉的两个发布按钮

抽屉右上角（构建信息下方、目标卡片上方）放两个按钮：

| 按钮 | 行为 | 适用状态 |
| --- | --- | --- |
| **发布测试** | 只发布到测试通道。已构建/已下线 → 测试中 | 已构建、已下线 |
| **一键发布** | 同时发布到测试与生产两个通道，一步到位。已构建/已下线 → 生产中（测试通道同时指向它） | 已构建、已下线 |

按钮本身不加 tooltip 说明文案。

**确认框仍需要**（这是操作警示，不是按钮解释）：

- 发布测试：「确定将构建 #N 发布至测试环境吗？当前测试版本（#M）将被转为已下线。」
- 一键发布：「⚠️ 确定将构建 #N 同时发布至测试与生产吗？这会影响所有线上设备，当前生产版本（#M）将被转为已下线。」

已在测试通道（TESTING）或已下线（OFFLINE）且只回滚生产的场景，保留原有的「发布至生产」「重新测试」「回滚至生产」按钮。

### 2.3 后端：一键发布端点

**好消息：核心逻辑已经存在。**

`releases.publish_build(conn, build, operator, reason, env=PRODUCTION)` 的实现（`server/app/services/releases.py:245`）：

> 规格要求"发布至生产"的来源状态必须是 TESTING 或 OFFLINE，
> 而自动任务与"保存并构建发布"要在同一轮里把新构建推上线，
> 因此这里先置 TESTING、再置 PRODUCTION，两步同处一个事务，状态原子切换。
> 两步算**一次**发布：发布历史只记最终那一条。

这正是「一键发布」需要的语义，且已满足：

- 同一事务内完成，状态原子切换 ✓
- 发布历史只记一条，不会一轮吃掉两条额度 ✓
- 来源状态 BUILT / OFFLINE 都允许（先置 TESTING 再置 PRODUCTION）✓

**只需新增一个端点**：

```python
@router.post("/builds/{bid}/publish-both")
def publish_both(bid: int, body: PublishBody, user=CurrentUser):
    """一键发布：已构建 / 已下线 → 测试中 + 生产中，一步到位。"""
    return _publish("both", bid, body.reason, user["username"])
```

`_publish` 里加一个分支：

```python
elif action == "both":
    result = releases.publish_build(conn, build, operator, reason,
                                    releases.Env.PRODUCTION)
```

前端调用 `POST /api/v1/builds/{id}/publish-both`。

**为什么不用现有端点组合**：`publish-to-prod` 走的是 `publish_to_production`，要求来源状态已经是 TESTING；从「已构建」直接调它会被状态机拒绝。前端串行调两个端点还会跨两个事务，中间态可被其它请求看到，且发布历史会记两条。

### 2.4 列表操作列统一

| 状态 | 现在的按钮 | 改成 |
| --- | --- | --- |
| 已构建 | 详情 / 发布至测试 / 删除 | 详情 / **发布测试** / **一键发布** / 删除 |
| 测试中 | 详情 / 发布至生产 / 下线 | 不变 |
| 已下线 | 详情 / 重新测试 / 回滚至生产 | 不变 |

「已构建」变成 4 个按钮，操作列宽度 `190 → 240`（移动端 `150 → 190`）。

### 2.5 自动发布 tab 的内容

原 Automation.vue 整体保留：

- 定时任务状态 + 「立即手动发布」按钮
- 抓取与测速配置
- 自动构建与发布配置
- 运行记录（最新 20 次）
- 最近自动发布（最新 20 次）

只把页面标题去掉（标题由外层 tab 提供），并在描述里把"自动发布"作为 tab 语境说清楚。

### 2.6 与自动任务的关系

服务端 scheduler 不动：自动构建发布走的是 `releases.publish_build(..., Env.PRODUCTION)`，与新的「一键发布」是同一套语义、同一套事务逻辑，行为一致。

界面上两者的区别：自动任务在后台按间隔执行；「一键发布」是人工即时触发。

## 三、自主维护（自主维护）

完整设计见 [自主维护-设计方案](自主维护-设计方案.md)，要点：

- magic-sets 从 submodule 变成运行时可配置、可替换的数据层（单仓库）
- 后台「自主维护」页是文件管理器：浏览、编辑、保存、提交、推送；12 小时自动拉取；合并冲突以手工编辑为主
- 规则集合（`rule/*.yaml`）自动引入为规则来源；脚本/重写片段需在「拓展模块」页显式引用
- 仓库托管实体的内容只读，改动只在自主维护页发生；启用状态归面板

## 四、实施顺序

按依赖关系分五步，每步可独立验证：

| 步 | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| 1 | **菜单重排 + 页面改名 + 文案替换 + 路由重定向** | — | 12 项菜单顺序与标题正确；旧链接跳转正常；首页同步；212 个后端测试通过 |
| 2 | **基础配置页加 tab，引擎平台并入** | 步 1 | 引擎平台的增删改查在 tab1 里完整可用；`/admin/targets` 跳转正常 |
| 3 | **构建发布合并 + 一键发布** | 步 1 | 两个 tab 切换正常；一键发布一次事务完成、发布历史只记一条；构建状态机不回退 |
| 4 | **自主维护（自主维护）** | 步 1（菜单位置） | 见自主维护文档 §十五 迁移路径 |

## 六、风险与取舍

| 风险 | 应对 |
| --- | --- |
| 一次改 12 个菜单项，用户找页面要重新适应 | 旧路径全部重定向，不产生死链；页面内标题同步改名 |
| 「设置」是常用词，全局替换会误伤 | 只改菜单标题与页面标题，其余不动 |
| 引擎平台藏进 tab 后不如以前显眼 | 放在「基础配置」第一个 tab；构建页与设备页仍有直达入口 |
| 一键发布绕过测试环节，可能误操作 | 保留确认框，明确警示影响范围；按钮只在「已构建/已下线」出现 |
| 合并后单页体积变大 | 两个面板用 `v-if` 懒挂载，自动发布面板不常驻渲染 |
| 步 4、5 涉及数据迁移 | 分批切换 + 逐批核对 + 一键回退（见自主维护文档 §九） |
