## 1. 产物现状分析（对照官方文档）

证据来源：Stash 官方（[example-config](https://stash.wiki/configuration/example-config)、[override](https://stash.wiki/configuration/override)、[proxy-groups](https://stash.wiki/proxy-protocols/proxy-groups)、[proxy-providers](https://stash.wiki/proxy-protocols/proxy-providers)、[proxy-benchmark](https://stash.wiki/proxy-protocols/proxy-benchmark)、[proxy-types](https://stash.wiki/proxy-protocols/proxy-types)、[dns-server](https://stash.wiki/features/dns-server)）与 Mihomo 官方（[config](https://wiki.metacubex.one/config/)、[dns](https://wiki.metacubex.one/config/dns/)、[proxies](https://wiki.metacubex.one/config/proxies/)）。线上产物样本：`Stash-macOS.yaml`（构建 #10，656 行）。

### 1.1 顶层键

| 现状 | 官方依据 | 处置 |
| --- | --- | --- |
| Stash 产物含 `mixed-port: 7890` | Stash 无端口键（官方：iOS/tvOS/Mac 默认 7890 由 App 提供，局域网共享是 App 开关） | **移出 Stash 默认**（进「官方精简预设」） |
| Stash 产物含 `allow-lan: false` | 同上 | 同上 |
| Stash 产物含 `profile.store-selected/store-fake-ip` | Stash 官方站全文 0 命中；Stash App 自行保存策略组选择 | 同上（Mihomo 保留） |
| `mode` / `log-level` / `ipv6` | Stash 官方有文档 | 保留（可编辑） |
| Stash 无 `dns` 段 | Stash 由客户端接管 DNS | 保留现状；**允许**用户在基础配置里显式写 dns（官方有 dns 章节），默认文档不含 |

### 1.2 远程代理集（proxy-providers）

现状：两个引擎**都**同时下发 `health-check`（Clash 系）与 `benchmark-url`/`benchmark-timeout`（Stash 系）。

| 键 | Stash 官方 | Mihomo 官方 | 处置 |
| --- | --- | --- | --- |
| `health-check` | 未在 Stash 文档出现 | 支持（enable/url/interval/lazy/timeout/expected-status） | **按引擎分叉**：Stash 不发，Mihomo 发 |
| `benchmark-url` / `benchmark-timeout` | 支持（集合级延迟测试参数） | 非 Mihomo 键 | **按引擎分叉**：Stash 发，Mihomo 不发 |
| `headers`（字符串值） | 支持，值可为字符串或数组 | Mihomo 用 `header`（值为数组） | 已有分叉，保持 |
| `url`/`path`/`interval`/`filter` | 支持 | 支持 | 保持 |

### 1.3 策略组（proxy-groups）

| 键 | Stash 官方 | Mihomo | 处置 |
| --- | --- | --- | --- |
| `url` / `timeout` | 策略组文档未列（Stash 的延迟测试 URL 来自**节点/集合级** `benchmark-url`） | 必需 | Stash 不发，Mihomo 发 |
| `interval` / `tolerance` / `lazy` / `hidden` / `filter` | 支持 | 支持 | 保持 |
| `strategy` | 支持 `consistent-hashing` / `round-robin` | 另支持 `sticky-sessions` | **Stash 也发**（且过滤掉 `sticky-sessions`） |
| relay | `benchmark-url`/`benchmark-timeout` | `url`/`interval` | 已有分叉，保持 |

### 1.4 本地单节点（功能性问题）

现状：本地节点渲染**只按 Mihomo/Clash 键名**，Stash 目标同样使用。

| 协议 | Stash 官方键 | Mihomo 键 | 现状 | 处置 |
| --- | --- | --- | --- | --- |
| Hysteria2 | `auth` / `up-speed` / `down-speed`（Mbps 整数）/ `obfs: salamander\|gecko` | `password` / `up` / `down`（"1000 Mbps" 字符串）/ `obfs: salamander` | 统一用 Mihomo 键 | **按引擎分叉**（功能性 bug：Stash 端 Hysteria2 认证字段名不对） |
| TUIC | `version`（4/5）必填 + `uuid`+`password`(v5) 或 `token`(v4) + `congestion-controller` | `uuid`/`password`/`congestion-controller`/`udp-relay-mode`/`reduce-rtt` | 缺 `version`，多了 `udp-relay-mode`/`reduce-rtt` | **按引擎分叉**（功能性 bug：Stash 端 TUIC 缺 version） |
| SS | `udp` 有文档 | `udp` 通用字段 | 一致 | 保持 |
| Trojan / AnyTLS / Snell / VMess / VLESS | `password`/`psk`/`uuid`、`sni`(trojan/hysteria2/tuic)、`servername`(vmess/vless)、`network`+`ws-opts`/`grpc-opts` | 同 | 一致 | 保持；`udp` 仅在官方有文档处输出 |

> 结论：6 个自建节点中 **3 个 Hysteria2 节点在 Stash 端目前是坏的**（认证字段名不匹配），TUIC 若使用同样有问题。

### 1.5 规则来源与规则

- Stash 官方**不推荐** `behavior: classical`（只能顺序匹配，显著增加耗时与内存），推荐 `domain`/`ipcidr`。
- 现状：生产里 `Google`、`GitHub` 两个规则来源是 `classical`，而参考配置里**同一上游 URL**（`MetaCubeX/meta-rules-dat` geosite）用的是 `domain` → 可安全改为 `domain`（有据）。
- `RULE-SET,cn,DIRECT` 捕获 `+.baidu.com`（已下载 `cn.yaml` 核实：第 13152 行 `+.baidu.com`、第 51 行 `+.baidu`、另有 `+.baidupcs.com`、`.bcebos.com`、`.bdstatic.com`）→ **百度网盘走直连**。

### 1.6 百度网盘专项（用户报障）

证据链：
1. `RULE-SET,cn,DIRECT` 在产物中位于 `MATCH` 之前，且 `cn` 规则集含 `+.baidu.com` → `pan.baidu.com`、`yun.baidu.com`、`pcs.baidu.com`、`d.pcs.baidu.com` 等**全部直连**。
2. 用户原始 Surge 配置同样把 baidu 直连（`DOMAIN-KEYWORD,baidu,DIRECT`），但在 Mac mini 的 Surge 上直连路径正常；现在改由 Stash 承载。
3. Stash 官方：**默认阻断经代理转发的 QUIC 流量**（让应用回退 TCP/HTTP2 以获得稳定吞吐），而 `direct` 类型的代理**始终不阻断**。即：直连路径上的 HTTP/3（百度网盘重度使用）不受阻断保护，若该直连链路 UDP/443 受限或被限速，网盘会出现打不开/卡住。

修复（可回滚、显式可见）：
- 新建策略组 **「百度网盘」**（`select`，成员：`节点选择`、`DIRECT`；默认第一项 = 节点选择 → 走代理，由 Stash 阻断 QUIC 并回退 TCP）。
- 在 `RULE-SET,cn,DIRECT` **之前**插入精确域名规则：`pan.baidu.com`、`yun.baidu.com`、`pcs.baidu.com`、`d.pcs.baidu.com`、`nd.pcs.baidu.com`、`baidupcs.com`、`bcebos.com`、`issuepcdn.baidu.com`、`bdstatic.com`、`baiduhstatic.com` → 目标「百度网盘」。
- 可选：追加 QUIC 拒绝规则 `AND,((NETWORK,udp),(DST-PORT,443),(DOMAIN-SUFFIX,baidu.com)),REJECT`（用户可自行决定是否需要；默认不启用）。

### 1.7 其它观察（不改，仅记录）

- `#SUBSCRIBED` 首行：服务端在**响应**里加（`feed.py:85`），不在磁盘产物里，**不影响构建 diff**；客户端保存副本时自己再追加一行 → 线上文件出现两条，属客户端行为，**保持不变**。
- `profile-update-interval` 响应头：取全局设置，与产物无关。

## 2. 产物可定制：基础配置层

### 2.1 定位（修正 v1 的立论）

- 顶层键**现在就能改**：发布目标 →「扩展 YAML」在渲染最后一步合并（字典递归、列表追加、标量覆盖），可覆盖任意顶层键。
- 现有入口的三个问题：① 隐蔽（藏在发布目标里、逐目标、原始 YAML）；② 没有默认值文档，用户不知道 Stash/Mihomo 各自支持什么；③ **能写 `rules`** —— 列表是**追加**语义，追加到 `MATCH` 兜底之后 → 永不生效，且绕过引用校验。
- 因此新层的价值是：**按引擎的全局基础配置 + 干净表单 + 官方精简预设 + 预览 + 结构键保护**，不是「首次获得该能力」。

### 2.2 分层与优先级（低 → 高）

| 层 | 内容 | 位置 | 可写结构键？ |
| --- | --- | --- | --- |
| ① 基础配置（新增） | 顶层全局键（端口/模式/日志/IPv6/profile/dns/任意自定义键） | 新表 `base_configs`（按引擎） | ❌ 拒绝并指向正确页面 |
| ② 结构化内容（现有） | `proxies` / `proxy-providers` / `proxy-groups` / `rule-providers` / `rules` | 业务表 | ❌ |
| ③ 功能模块（现有） | 可复用 YAML 片段 | `snippets` | ⚠️ 现状允许（保留，但文档提示列表为追加语义） |
| ④ 目标扩展（现有） | 单目标覆盖 | `targets.extra_yaml` | ❌ **本次新增保护**（现在可以写，会破坏兜底顺序） |

### 2.3 合并顺序（`render_target`）

```
cfg = 基础配置(core 键按固定顺序) + 基础配置(其余用户键, 字母序)
cfg["proxies"]         = [空组保护] + 本地单节点            # ② 覆盖
cfg["proxy-providers"] = {...}   # 仅当非空
cfg["proxy-groups"]    = [...]   # 仅当非空
cfg["rule-providers"]  = {...}   # 仅当非空
cfg["rules"]           = [置顶 DIRECT] + 用户规则
cfg["dns"]             = 基础配置的 dns（若非空映射）否则 Mihomo 默认段   # 位置与现状一致（末尾）
再合并 ③ 功能模块（按引擎匹配）
再合并 ④ 目标扩展（最高优先级）
```

**字节级兼容要求**：默认基础配置下，**Stash 产物与现状逐字节相同**（除 §1 明确的官方对齐改动外）。因此：
- 基础配置**从 snapshot 取**（不读实时表）→ 保持「构建 = 不可变快照」语义；
- 结构键**仅在非空时输出**（保持现状行为，避免多出空键）；
- `dns` 仍输出在末尾；
- 基础配置进入 snapshot 前**解析成 dict**（注释/空白/键序不参与 `policy_sha`）。

### 2.4 数据模型

```sql
CREATE TABLE IF NOT EXISTS base_configs (
  engine TEXT PRIMARY KEY,     -- stash / mihomo
  content TEXT NOT NULL,       -- YAML 文本
  updated_at TEXT NOT NULL
);
```

- 建表时 `INSERT OR IGNORE` 写入两份默认文档（**Stash = 官方精简**、**Mihomo = 现状全量**）。
- **加入 `BACKUP_TABLES`**（同时补上此前遗漏的 `snippets`）。

### 2.5 校验

| 规则 | 提示 |
| --- | --- |
| 必须是 YAML 映射（非空） | 「基础配置必须是键值映射」 |
| 禁止键：`proxies` / `proxy-providers` / `proxy-groups` / `rule-providers` / `rules` | 「『rules』由分流规则页维护，基础配置不能覆盖」 |
| `mode` ∈ rule/global/direct；`log-level` ∈ silent/error/warning/info/debug；`allow-lan`/`ipv6` 必须是布尔；`mixed-port` 等端口键必须是 1–65535 整数 | 逐项中文提示 |
| 目标扩展 `extra_yaml` 同样禁止结构键（本次新增） | 「『rules』由分流规则页维护，目标扩展不能覆盖」 |

不做「键是否被客户端支持」的白名单校验（客户端键集会变，硬白名单会卡住用户）；误配由「预览」与「恢复默认」兜底。

### 2.6 API

| 方法 | 路径 | 说明 |

### 2.7 前端

新页面「产物配置」`/admin/artifact`（菜单置于「功能模块」与「发布目标」之间）：

- 引擎切换（Stash / Mihomo）；
- 表单区：模式、日志级别、IPv6、端口类开关（按引擎的 schema 决定显示哪些）、DNS 区（仅 Mihomo 默认展示，Stash 提示「默认由客户端接管 DNS」）；
- 高级 YAML 区：其余任意顶层键（与表单是同一份文档的两个视图）；
- 按钮：恢复默认 / 预览 / 保存 / 保存并构建发布；
- 提示：改完需重新构建并发布才生效（**端到端**：自动构建 ≤1h + 客户端 ≤1h）。

## 3. 四项改进

### D1（改进 A）`builds.snapshot` 加密

- `security.encrypt_payload(text)` → `"enc:v1:" + token`；`decrypt_payload(text)` 前缀识别，历史明文兼容。
- 启动迁移：把历史明文 snapshot 逐条加密回写（幂等）。
- 读取：`_build_public(with_results=True)` 解密。
- 依赖 `data/secret.key`（与 `url_enc`/`token_enc` 同一把钥匙）→ 换机/换 key 前必须备份 key。
- 产物文件仍含本地节点凭据（产品本质），文档保持「仅管理端预览」的告警。

### D2（改进 B + D）更新间隔统一

- 全局 `profile_update_interval`：默认 12 → **1 小时**（含数据迁移 + 前端兜底值）。
- 全局 `auto_build_interval_hours`：默认 12 → **1 小时**（含数据迁移）→ 策略变更最迟 1h 自动构建发布。
- 目标级 `update_interval`：**废弃**（后端保留字段忽略其值、UI 移除输入、snapshot 剔除、发布目标页改文案：扩展 YAML 是「字典递归 + 列表追加」，不是「整键覆盖」）。
- 端到端：策略改动 → ≤1h 自动构建+发布 → ≤1h 客户端拉取 ⇒ ≤2h 收敛；也可手动「保存并构建发布」立即生效。

### D3（改进 C）上游定时更新链路：核实结论与修复

**核实结论**：链路存在且基本正确 —— 节点来源按 `sources.interval`（默认 6h）定时抓取、规则来源按 `rule_providers.interval`（默认 24h）定时抓取、节点来源按 `test_interval`（默认 6h）定时测速；抓取成功且开启「只分发可用节点」的来源在**同一轮**立即补测；上游内容变化**不改变 `policy_sha`**（有意设计），经子资源实时生效。**不是「没实现」的 bug。**

**但审计发现以下真实缺陷，全部修复**：

| 编号 | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| B1 | provider 子资源 ETag 不含测速结果 | 「只分发可用节点」的过滤结果**永远下发不到客户端**（304） | ETag 追加 `test_results` 摘要 |
| B2 | 非 `FetchError`/`TestError` 异常回滚事务 | `last_attempt_at` 丢失 → **每 30 秒重试**打爆上游 + 审计表膨胀 | `updater` 三处改为 `except Exception`，失败状态先落库再抛 |
| B3 | 抓取/测速/构建在**写事务内**做网络与子进程 | 慢上游时设备拉取 500（`database is locked`） | 三段式：短事务写时间戳 → 事务外 IO → 短事务写结果 |
| M1 | 抓取成功清空 `test_results` 但不复测 | 非 filter 来源最长一个 `test_interval` 的「未测速空窗」，过滤退化为全量下发 | 抓取成功后 `test_attempt_at=NULL`（所有来源同轮补测） |
| M2 | `build_error`/`test_skipped` 不写运行历史 | 「为什么不发布/为什么不测速」无痕 | 纳入记录条件，并按文案去重（避免每 30 秒刷屏） |
| M3 | `auto_test=0` 的 filter 来源**永久阻塞**自动发布 | 门禁永远等不到测速 | 该来源不参与门禁，并在摘要中说明 |
| L1 | `interval=0` 未加固 | 历史脏数据可导致每 tick 抓取 | 查询加 `AND interval>0` |
| L2 | inline→remote 未清 `last_attempt_at` | 首次抓取最多延迟一个 interval（24h），期间规则子资源 404 | 切换时一并清空 |
| L4 | `yaml.safe_dump` 未兜底 | 畸形快照让 feed 子资源 500 | `filter_snapshot` 内部捕获并转 `TestError` |
| L5 | 客户端刷新间隔 = 服务端抓取间隔 | 端到端最坏 2×interval（12h / 48h） | 来源与规则来源新增**客户端更新间隔**（可选，默认跟随抓取间隔），生产设为 3600 |

### D4（产物规则修复，见 §1）

- 新建「百度网盘」策略组 + 精确域名规则（置于 `cn` 规则之前）。
- `Google`/`GitHub` 规则来源 `behavior` 由 `classical` 改为 `domain`（同一上游为 geosite domain 格式，官方推荐）。
- 规则来源表单对 `classical` 给出官方提示。

| ID | 用例 | 断言 |
