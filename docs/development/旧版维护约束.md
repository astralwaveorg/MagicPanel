# 旧版维护约束

保留旧文档的编号，方便从测试、代码注释和历史说明反查。此表区分程序必须保证的行为与部署方自行维护的策略；具体线路、节点名单和生产检查记录不作为代码默认值。

| 编号 | 修改时需要保留的行为 |
| --- | --- |
| 1–4 | 禁止配置层覆盖五个结构化键；最终规则在末尾。规则类型符合目标引擎白名单，`(engine, platform)` 唯一。 |
| 5–7 | 引擎与平台层的列表替换，设备层只追加差异。设备换平台时迁移配置键。数据库迁移须可重复执行。 |
| 8–10 | 不提交凭据。引擎默认键对照官方样例；界面统一使用「引擎默认配置／引擎平台配置／设备独立配置」。 |
| 11–14 | 地区分组、测速或故障转移方式和兜底去向由该部署的策略决定。调整前读实际配置；不要把某次部署的偏好固化进渲染器。规则指向可见组，隐藏组可由可见组引用。 |
| 15–19 | 直连域伪键生成置顶规则；引擎默认层参与渲染。组成员可显式引用本地节点；区分不同来源的同名节点。内联节点与 provider 分发的更新方式不同。 |
| 20–22 | 依赖规则仓库与面板源码分开。首个匹配即决定规则去向；重复集合和子集须核对前置规则，避免遮蔽。 |
| 23–26 | 按规则来源的 behavior 处理 `no-resolve`，保留 `cn-ip` 例外。改规则类型或集合格式先核对官方文档。地域、账号与业务分类的分流需求在部署策略中维护。 |
| 27–29 | 不擅改既有组顺序。排序要处理同值与跨方案影响；调整菜单或拖拽交互时同时验证桌面和窄屏。 |
| 30 | 发布已有构建与抓取后创建新构建是不同操作；核对所选构建、环境与事务边界。 |
| 31–32 | 完整 DNS 段由引擎默认层管理，其他层通过允许的伪键追加例外。依赖仓库的 Git 写操作串行，冲突返回明确错误。 |
| 33–34 | 检查域名规则与会触发解析的 IP 规则的顺序，避免 Fake-IP 提前命中。部署的直连和代理 UDP 策略分开验证，不将单一网络实测写成所有客户端的行为。 |
| 35–37 | 已发布产物引用的资源不能随意删除或改名；停用时保留已有资源下发。配置本体和子资源分别记拉取，不能用子资源刷新代替设备回执。来源请求头值按凭据处理。 |
| 38–41 | 面板自己的域名须能解析并刷新订阅；空来源不能卡住构建门禁。只改渲染器后仍需创建新构建才会反映到产物。门户源码预览不得记为实际拉取。 |
| 42–44 | 组、规则及其引用按方案隔离。需要内网解析的服务分别核对系统 DNS、Fake-IP 例外和直连规则；构建校验保留 `cn-ip` 不带 `no-resolve` 的约束。 |

具体字段和验证入口见[配置文档](../配置文档.md)、[多方案设计](../reference/方案设计-多套分流方案.md)和[产物构成](MagicPanel-构建与发布-产物构成.md)。生产变更另读本地运行手册；保留改前快照、恢复条件和设备侧验证。
