## 先理清几个概念

第一次用先把这几个词对上，后面的页面就好理解了。

| 概念 | 一句话 | 在哪维护 |
| --- | --- | --- |
| 节点来源 | 一个机场订阅，或一个手写的本地节点 | 节点来源 |
| 规则来源 | 一份域名/IP 清单（远程抓取或内联维护） | 规则来源 |
| 策略组 | 一组节点的聚合方式（手动选、自动测速、故障转移、负载均衡、链式） | 策略组 |
| 分流规则 | 什么流量走哪个策略组 | 分流规则 |
| 引擎平台 | 引擎（Stash / Mihomo）+ 平台（iOS / macOS / Windows……），一类客户端 | 引擎平台 |
| 功能模块 | 一段可复用的 YAML 片段（磁贴、DNS 策略、TUN、脚本改写） | 功能模块 |
| 产物配置 | 产物里的顶层键（端口、模式、DNS、TUN……） | 产物配置 |
| 设备 | 一台装客户端的机器，一个固定订阅地址 | 设备管理 |

**产物**是编译出来的完整 YAML，也就是客户端真正下载到的那份配置。**构建**把当前所有设置固化成一份产物；**发布**决定哪份产物对外生效。改完设置不发布，客户端拿到的还是老配置。

**引擎平台 = 引擎 + 平台，一对只能有一个。** 想区分不同的人或设备，不要复制引擎平台：策略组和规则可以限定到具体设备，客户端参数用「设备独立配置」。

## 门户页：订阅中心

地址是站点根路径 `/`，比如 `https://magichub.top:8443/`。

- 输 **4 位 PIN** 进入，页面会列出所有设备的订阅地址，点「复制」拿到完整链接。
- 维护者已经登录后台时，**免 PIN** 直接看。
- PIN 跟维护者账号绑定，谁设的谁能在后台撤销；换设备时让对方重新发一个就行。
- 页面还提供导入指引：Stash、Clash for Android 等客户端怎么填订阅地址、怎么更新，按客户端分开写清楚了。
- 门户只读，不改任何配置。

> PIN 不是密码学意义上的强认证，它是「防止订阅地址被随手翻到」的闸门。真正的访问控制在后台账号。

## 登录与账号

后台地址 `/admin`。

- 第一次访问会进入**初始化**页：创建第一位维护者（用户名、密码、显示名）。只有一个人能创建，之后这个入口就关了。
- 同一个 IP 登录失败连着 5 次，会被锁 15 分钟。
- 会话默认保留 7 天（可在「设置」改）。
- 支持多维护者：每人一个账号，共享同一份策略数据。「设置 → 维护者账号」里可以添加、删除其他维护者。

## 系统状态

打开后台第一屏，回答四个问题：现在跑的是哪一版、稳不稳、节点还在不在、测速是不是真的直连。

| 卡片 | 看什么 |
| --- | --- |
| 当前版本 | 当前生产版本、当前测试版本：构建号、发布时间、策略摘要摘要、发布人和备注 |
| 运行状态 | 面板是否正常、数据库剩余空间、最近一次备份时间、测速核心版本 |
| 测速链路 | 面板当前的直连出口 IP 与归属地，检测是不是真的绕过了代理；「重新检测」可刷新 |
| 节点来源 | 每个来源的节点数、可用率、最近抓取时间 |
| 设备最近下载 | 每台设备最近一次拉取订阅的时间与 IP |
| 最近操作 | 最近几条审计记录 |

**测速链路**这张卡值得看一眼：面板自己会检测出站 IP，如果 NAS 上有全局代理而面板没排除掉，测速结果会不准（节点看着好，实际在绕代理）。显示「测速走本机直连」才是对的。

## 节点来源

两个区块：**节点来源**（机场订阅）和**本地节点**（手写节点）。

### 节点来源

| 操作 | 说明 |
| --- | --- |
| 添加订阅 | 填名称、订阅 URL、抓取间隔、测速间隔、User-Agent、节点过滤正则 |
| 一键抓取 / 一键测速 | 立刻跑一轮所有启用的来源 |
| 抓取 / 测速（单行） | 只处理这一条 |
| 复制 URL | 订阅地址加密存储，列表里不铺开，按需复制 |
| 编辑 | 改名称、URL、间隔、过滤条件等 |
| 删除 | 有策略组引用时会被拦下，列出引用来源 |

几个容易踩的点：

- **抓取间隔**单位是秒。填 0 等于关掉自动抓取，这时只用本地快照。
- **测速间隔**填 0 等于关掉自动测速，随时可以手动测。
- **过滤正则**决定哪些节点会被分发，默认 User-Agent 是 `Stash`。
- **只分发可用节点**打开后，抓完会自动补测；自动发布要求来源有可用测速结果才放行。
- 快照是留存的：抓取失败时用上一次成功的快照继续服务。

### 本地节点

自己搭的节点、家宽、落地都放这里。

- 点「添加节点」填：名称、类型（本地 / 自建 / 家宽 / 机房 / 专线 / 中转 / 落地）、协议、服务器、端口、参数。
- **参数表单是动态的**：协议不同要填的字段不一样（hysteria2 要 `auth` 和上下行，trojan 要 `password` 和 `sni`……），以服务端 schema 为准。
- 启用后以 `名称 (类型)` 写进产物，比如 `🇭🇰 香港机房 01 (机房)`。
- 节点默认**不进入任何策略组**，要自己去「策略组」里勾选。
- 凭据加密落盘，列表里不显示明文。

## 规则来源

规则集是分流规则引用的清单，按行为分远程和内联两种。

| 操作 | 说明 |
| --- | --- |
| 添加规则来源 | 名称、URL、行为类型（domain / ipcidr / classical）、格式、间隔 |
| 内容 | 看这个规则集抓到了什么 |
| 抓取 | 立刻更新这一份 |
| 复制 URL | 远程规则集的地址 |
| 编辑 / 删除 | 有分流规则引用时删除会被拦下 |

内联规则集直接在本页编辑内容，格式跟远程的一致。

**规则类型**选错客户端会加载失败：按官方白名单选（Stash 和 Mihomo 支持的类型不一样，面板按引擎分别限制）。

## 策略组

策略组决定流量落到哪些节点上。

| 类型 | 行为 |
| --- | --- |
| select | 手动选，默认第一个 |
| url-test | 自动测速选最快的 |
| fallback | 按顺序挑第一个可用的 |
| load-balance | 多节点分担，分配策略可选一致性哈希 / 轮询 / 粘性会话 |
| relay | 链式转发，把一个组接到另一个组前面 |

组里可以放：

- **节点来源**（勾选后自动聚合该来源的节点，机场更新了组也跟着变；多选里的「包含所有来源」
  表示所有来源，以后新增的来源自动进来，不用回来改）
- **本地节点**（手写节点）
- **其他策略组**（分组套分组）

拖动左侧手柄可以排序，上下箭头是键盘和触屏的替代。空组会在产物里留下占位，避免客户端把空组改写成别的。

## 分流规则

规则从上往下匹配，命中即停。

- 类型可选域名、IP、进程、规则集等；`MATCH` / `FINAL` 是兜底，永远保留。
- **适用引擎平台**：只在选中的引擎平台里出现；多选里的「包含所有」表示全部。
- **适用设备**：只给选中的设备用——这些设备会拿到自己的产物，同平台其他设备不受影响；
  「包含所有」表示所有设备。
- `no-resolve` 修饰符适合 IP 字面量规则，不触发域名解析。
- 规则指向的策略组不适用于同一个平台时，这条规则会被自动剔除，并在构建时给出提示。

**顺序很重要**：把具体的放前面，宽泛的放后面。规则集（`RULE-SET`）通常放在域名规则之后、兜底之前。

## 引擎平台

一类客户端对应一个引擎平台，比如 `Stash-macOS`、`Mihomo-Windows`。

- 名称只能有字母、数字、下划线和短横线（会拼进文件名）。
- **同一「引擎 + 平台」只能有一个**，重复会被拒绝并提示。
- **目标扩展**：这一类客户端专属的 YAML 片段，最后应用、优先级最高。适合放只有某类客户端才认的键。
- 删除时如果还有设备在用，必须先指定迁移目标，设备会一起搬过去。

常用平台：Stash 支持 iOS / macOS / tvOS / Windows / Android；Mihomo 支持 macOS / Windows / Android / Linux。

## 产物配置

产物里的顶层键在这里改，分三层，左侧树状结构选作用域：

```text
引擎默认配置          ← 引擎内置的能力基线（可改）
  Stash 默认
  Mihomo 默认
引擎平台配置          ← 按「引擎 + 平台」
  Stash-iOS
  Mihomo-Windows
设备独立配置          ← 按设备
  Astral-iPhone-Stash
```

**继承链**显示在标题下方，一眼看清当前这层叠在哪几层之上：

```text
继承链：引擎默认配置 · Stash 默认 → 引擎平台配置 · Stash-iOS → 设备独立配置 · Astral-iPhone-Stash
```

右栏上半部分是**生效配置**（键 / 值 / 来源），下半部分是**编辑配置**（改参数、源码编辑、预览产物、保存）。

| 操作 | 说明 |
| --- | --- |
| 新增参数 | 挑一个键名填值，只对当前层生效 |
| 源码编辑 | 直接改这一层的 YAML，保存前做键级校验 |
| 清除改动 | 清掉本层对上层��覆盖，回到继承 |
| 恢复默认 | 引擎默认配置专用：回到程序内置内容 |
| 预览产物 | 按当前生效值渲染一份产物，不产生构建 |
| 保存 | 只保存本层，客户端要等新版本发布才拿到 |
| 保存并构建发布 | 保存 + 构建 + 发布，一步到位 |

### 三层的分工

- **引擎默认配置**：这一类引擎的通用基线，改一次所有平台都受益。
- **引擎平台配置**：只针对「引擎 + 平台」，比如只有桌面端才开某个监听。
- **设备独立配置**：只针对一台设备，比如某台机器要连家里的 NAS、某台要开 MTProto。

### 列表的合并语义

- 引擎默认配置、引擎平台配置：这一层是**完整配置**，列表整体替换。
- 设备独立配置：这一层是**个性化**，只记新增项，下发时追加——所以设备层加一条 DNS 过滤不会把上层的整份列表冲掉。

### 几个内置功能

- **个人直连域名**（`_direct_domains`）：生成置顶的 `DOMAIN-SUFFIX,域名,DIRECT` 规则，保证先生效。
- **Fake-IP 过滤**（`_fake_ip_filter`）：写进 `dns.fake-ip-filter`。
- **MTProto 代理**（Stash 专属）：在「预设」里选「MTProto 代理（Telegram）」，套用时自动生成 32 位十六进制密钥。放在设备独立配置里，哪台设备要用就加一份。密钥在 Telegram 客户端里要连同 `dd` 前缀一起填。Mihomo 内核没有这个能力，不要给 Mihomo 设备加。
- **Stash 的 Google 中国站重定向**：引擎默认配置里带了 MitM 与 `url-rewrite`，把 `google.cn` 导到 `google.com`。HTTPS 重写需要设备信任 Stash 的 CA 证书（Stash 首页 → MitM → CA 证书 → 安装并信任），没信任时这些域名会报证书错误。

### 结构化内容不能在这里改

节点、策略组、规则、规则集、代理集合是**结构化内容**，只能在各自页面维护。任何配置层写这几个键都会被拒绝——这是硬校验，不是提示。

## 功能模块

可复用的 YAML 片段，启用后与产物深度合并（字典递归、列表追加、标量覆盖）。

- 「预设」里有 17 个现成片段：Stash 的磁贴、HTTP 引擎、脚本改写、请求头去跟踪；Mihomo 的 TUN、嗅探、Geo 数据、DNS 策略、泄漏防护等。
- 也可以自己写片段，或用「源码编辑」改。
- 片段要标明适用引擎（Stash / Mihomo / 全部）。
- 片段同样不允许写结构化内容。

预设和引擎默认配置有重叠时，引擎默认配置已经带的能力可以关掉对应模块，产物不变。

## 设备管理

每台设备一行。

- **文件名**决定下载到客户端的配置文件名（`Astral-iPhone-Stash.yaml`），**设备名**只用于后台和门户展示——两者分开，是为了改显示名不影响客户端。
- **订阅地址**是固定的，带令牌；点「复制地址」才显示完整链接。
- **订阅环境**决定这台设备拿生产版还是测试版。
- **轮换令牌**：旧地址立即失效，客户端换成新地址即可；令牌泄露时用。
- 删除设备会一并清掉它的订阅地址和设备独立配置。

新增设备前先在「引擎平台」里准备好对应的平台。

## 构建发布

- **创建构建**：把当前所有设置编译成产物快照，逐目标校验。Mihomo 目标在测速核心已安装时还会跑一次 `mihomo -t`。
- 顶部显示当前生产版本和当前测试版本：构建号、发布时间、策略摘要、发布人、备注。
- 列表每行：构建号、发布状态、校验结果、创建时间、创建人、策略摘要、备注。
- **详情抽屉**列出每个产物（平台产物 + 设备专属产物）的校验状态、大小、摘要和警告；可以预览产物、与上一构建对比。
- **发布至测试** → **发布至生产**：生产与测试环境各至多一条生效版本。
- **回滚至生产**：把某个旧构建重新推上生产。
- **下线**：把不再用的版本撤下。生产版本受保护，只能被新版本替换。
- 只有从未发布过的构建可以删除。

**改完设置要生效，顺序是：改设置 → 创建构建 → 发布。** 「产物配置」里的「保存并构建发布」把前两步合在一起。

## 自动发布

服务端定时任务，按开关工作。

- **抓取与测速**：自动抓取节点来源、规则来源，自动测速。
- **自动构建与发布**：策略变化时自动构建，校验通过后发布到指定环境；构建检查间隔可调。
- **立即手动发布**：忽略到期时间，强制跑一轮抓取、测速和构建检查。
- 页面下方有最近运行记录和最近自动发布记录（各 10 条）。

自动发布的**前提是策略没变**——策略没动就不会重复构建产物。改完配置想让客户端立刻拿到，要么手动构建发布，要么等下一次检查。

## 典型操作流程

### 新增一个机场

1. 节点来源 → 添加订阅 → 填名称、URL → 保存
2. 点「抓取」确认有节点
3. 策略组 → 新建一个组 → 勾选这个来源 → 保存
4. 分流规则 → 改一条规则的指向，或新建一条 → 保存
5. 构建发布 → 创建构建 → 校验通过 → 发布至测试 → 在测试设备上验证 → 发布至生产

### 给某台设备单独加个东西

1. 设备管理 → 复制地址，确认是哪台设备
2. 产物配置 → 左侧树选这台设备的「设备独立配置」
3. 新增参数或用预设，保存
4. 不用重新发布——设备独立配置是在分发时叠加的，客户端下次拉取就带上了

> 例外：改了「引擎默认配置」和「引擎平台配置」必须重新构建发布，因为那两层固化在构建产物里。

### 某台设备要用 MTProto

1. 产物配置 → 选该设备的「设备独立配置」
2. 预设 → 选「MTProto 代理（Telegram）」→ 套用
3. 从生效配置里复制 `mtproto.secret`（32 位十六进制）
4. Telegram 代理设置里选 MTProto，填设备的地址、`5753`、密钥

### 怀疑节点不通

1. 系统状态 → 看「测速链路」是不是本机直连
2. 节点来源 → 对可疑来源点「测速」
3. 必要时在「设置 → 测速核心」重新安装核心

## 常见问题

**客户端拉到的配置还是旧的**
改完设置没发布。引擎默认配置和引擎平台配置要重新构建发布；设备独立配置下次拉取就生效。

**客户端提示配置加载失败**
多半是规则类型超出该引擎的支持范围，或者策略组被引用成了空组。构建详情里会写明原因。

**某台设备收不到规则**
检查这条规则的「适用引擎平台」和「适用设备」——两者是取交集的，任一不匹配都不会生效。

**订阅地址失效了**
令牌被轮换或设备被删除。设备管理里「复制地址」取新的。

**节点测速很慢或者结果不准**
看系统状态的「测速链路」。面板必须走本机直连，NAS 上的全局代理会影响它。

**忘记密码了**
用另一个维护者账号登录后重置；只有一个维护者时，需要在服务器上重置数据库里的账号记录。

**备份恢复不了**
多半是缺 `data/secret.key`。它和备份文件必须一起保管。
