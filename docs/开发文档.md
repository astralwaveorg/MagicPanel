## 一句话认识这个项目

一个自托管的代理订阅配置管理服务。用户维护「节点来源 / 规则来源 / 策略组 / 分流规则 / 引擎平台 / 拓展模块 / 基础配置」，面板把它们编译成 Stash 和 Mihomo 能直接用的 YAML，构建成不可变快照，发布出去，设备按固定订阅地址拉取。

**它不碰流量**：不开发代理内核，不做中转，只负责"把配置编对并分发"。

## 跑起来

### 本地开发

```bash
python3 -m venv .venv && .venv/bin/pip install -r server/requirements.txt
npm install
npm run dev
```

- 前端 <http://127.0.0.1:7100>，API <http://127.0.0.1:8000>，Vite 已把 `/api` 和 `/feed` 代理过去。
- 第一次访问 `/admin` 会引导创建第一位维护者。
- 后端单独跑：`cd server && ../.venv/bin/python -m uvicorn app.main:app --reload --port 8000`。
- 前端产物输出到 `server/app/static`（已在 `.gitignore` 里，不要提交）。

### 环境变量

| 变量 | 作用 |
| --- | --- |
| `MAGICPANEL_DATA_DIR` | 数据目录，默认 `server/../data` |
| `MAGICPANEL_SCHEDULER=0` | 关闭内置定时任务（测试用） |
| `MAGICPANEL_SCHEDULER_TICK` | 调度器心跳间隔秒数，默认 30 |

## 环境与内网地址

仓库和脚本里出现的内网地址都出自 [环境与地址速查](reference/环境与地址.md)。一句话版：

- **面板跑在 NAS 上**（`10.0.1.2`，容器 `magicpanel`），不在开发机上。
- **代理跑在 Mac mini 上**（`10.0.1.8`，Stash 混合端口 `7890`）——开发机就是这台 Mac mini。
- 因此：**面板服务端做的事（抓取订阅、抓规则集）必须用 `http://10.0.1.8:7890`**。
  写 `127.0.0.1` 会连到 NAS 自己，实测 connection refused，订阅与规则集全部抓不到。
- **在本机执行的脚本**（`release.sh` / `fetch_geo_data.sh`）用 `127.0.0.1:7890`
  或 `10.0.1.8:7890` 都行；但 `deploy.sh` 的 `DEPLOY_PROXY` 是注入 NAS 端构建过程的，
  必须用 `10.0.1.8`。

改网络环境（换 IP、换机器）时，先改那份速查文档，再改引用它的地方。

## 数据怎么流动

```text
节点来源(订阅) ──┐
本地节点        ──┤
规则来源(规则集) ──┤
策略组          ──┼──►  collect_snapshot()  ──►  编译 ──►  校验  ──►  构建快照
分流规则        ──┤         (builds.py)          (compiler/)    (compiler/validate)
拓展模块        ──┤
基础配置三层    ──┤
平台扩展        ──┘
                                   │
                                   ├──► 平台产物   builds/<id>/<平台>.yaml
                                   └──► 设备产物   builds/<id>/<设备名>.yaml
                                                │
                                    发布 ───────┤
                                                ▼
                              /feed/<令牌>/config.yaml   （分发时叠加设备独立配置）
```

**关键点：三层配置的作用域不同。**

- 引擎默认配置、引擎平台配置 → 固化在构建快照里，**改了必须重新构建发布**。
- 设备独立配置 → 分发时实时叠加，**改完客户端下次拉取就生效**。

## 数据库

SQLite，WAL 模式，单文件 `data/magicpanel.db`。

| 表 | 存什么 | 关键点 |
| --- | --- | --- |
| `users` | 维护者账号 | 口令散列、门户 PIN 散列、头像 MIME |
| `sessions` | 登录会话 | 默认 7 天过期 |
| `sources` | 节点来源 | URL 加密存储；抓取快照、测速结果、自动抓取/测速开关 |
| `rule_providers` | 规则来源 | URL 加密存储；远程/内联；行为类型 |
| `local_nodes` | 本地单节点 | 参数加密；协议不同字段不同 |
| `proxy_groups` | 策略组 | `targets` / `devices` 是 JSON 数组，`["*"]` = 全部（哨兵 `config.ALL_SCOPE`），`[]` = 不适用任何平台 / 设备 |
| `rules` | 分流规则 | 同上；`no_resolve` 标记；`sort` 决定顺序 |
| `targets` | 引擎平台 | `(engine, platform)` 唯一 |
| `devices` | 设备 | 令牌哈希 + 加密副本；`target_id` 指向引擎平台 |
| `base_configs` | 基础配置三层 | 主键 `(engine, platform, device_id)`；`device_id=0` 是引擎平台配置层，`platform=''` 是引擎默认配置层 |
| `snippets` | 拓展模块 | YAML 片段，标引擎 |
| `builds` | 构建快照 | 产物、校验结果、策略摘要 |
| `releases` | 发布记录 | `testing` / `production` 各至多一条生效 |
| `audit` | 审计日志 | 谁在何时改了什么 |
| `automation_runs` | 自动任务运行记录 | 最近 20 条 |
| `settings` | 键值设置 | 见 `config.SETTINGS_DEFAULTS` |

### 加字段的固定做法

不要手改线上库，也不要改历史数据。**加列 + 写迁移**：

```python
# server/app/db.py
def _ensure_column(conn, table, column, decl) -> bool:
    ...  # 已有

# 在 init_db() 里
_ensure_column(conn, "sources", "new_flag", "new_flag INTEGER NOT NULL DEFAULT 0")

# 需要搬历史数据时，再写一个 _migrate_xxx(conn)，在 init_db() 末尾调用
def _migrate_xxx(conn) -> None:
    conn.execute("UPDATE ... WHERE ...")
```

迁移必须**幂等**（重复执行不报错、不重复改数据），因为每次启动都会跑。

## 后端约定

- **数据库访问**只用 `server/app/db.py` 的助手：
  - `with db.tx() as conn:` 写事务
  - `db.one(conn, sql, args)` / `db.all_(conn, sql, args)` 查
  - `db.get_setting(conn, key, default)` / `db.set_setting(conn, key, value)`
  - `db.paged(conn, table, where, args, order)` 分页
  - `db.reorder_subset(conn, table, ids)` 排序（只改 subset 内的顺序）
  - `db.insert_unique(conn, sql, args, message)` 唯一冲突转成友好报错
  - 注意 `one`/`all_` 的参数是**元组**，不是散参。
- **接口**：`@router.get/post/put/delete`，依赖用 `CurrentUser`，写操作靠 `deps.py` 的 CSRF 校验。返回 JSON，错误用 `HTTPException`。
- **列表接口**：一律分页（`db.paged`）。要加搜索/筛选就在同一接口上加查询参数，
  把条件拼进 `where` 与 `args`；返回值额外带上未筛选时的总数（`total_all`），
  界面据此写"筛选出 N 条，共 M 条"。
- **抓取失败要留旧数据**：抓取失败只更新 `last_status` / `last_error`，
  绝不覆盖 `content`（上一次抓到的内容）。构建与分发照旧用旧内容，
  客户端不会突然少规则。定时抓取的失败重试在
  `services/scheduler.py` 的 `_fetch_with_retry()`（默认 3 次）。
- **加密**：敏感值（订阅 URL、节点参数、令牌、备份密码）用 `security.encrypt_payload` 存密文，需要展示时再解密；口令用 `security.hash_password`。
- **审计**：写操作后调 `security.audit(conn, actor, action, object_type, object_id, detail)`。
- **命名**：层级的名字只有三个——**引擎默认配置 / 引擎平台配置 / 设备独立配置**，代码、注释、界面、文档都要一致。

### 基础配置的比较基线

三层各自只存"相对基线的差异"，基线怎么算决定了差异怎么算：

- 引擎默认配置层没有上层可比，**基线 = 程序内置的默认值**（`base_config_service.default_doc(engine)`）。
- 引擎平台配置 / 设备独立配置的基线 = 上层合并后的生效值。
- 基线由 `routers/base_config.py` 的 `_baseline()` 给出；`GET /api/v1/base-config`、`PUT /api/v1/base-config`、`POST /api/v1/base-config/reset` 三个接口都返回 **`inherited`** 字段（= 本层的比较基线）。
- `PUT /api/v1/base-config` 与 `POST /api/v1/base-config/apply` 都按这个基线求差异，所以「保存并构建发布」只会把改动过的键写进覆盖记录，没改的键不落库。

## 前端约定

- Vue 3 `<script setup>` + Element Plus，Vite 构建，产物进 `server/app/static`。
- 一个页面对应 `src/views/` 下的一个文件；共用组件放 `src/components/`。
- **按钮配色有统一约定**，新增按钮照着来：

| 语义 | 写法 |
| --- | --- |
| 新建 / 保存 | `type="primary"`（实心蓝） |
| 触发一次动作 | `type="primary" plain` |
| 检测 / 校验 | `type="success" plain` |
| 发布 | `type="success"` |
| 查看 | `type="info" plain` |
| 撤销 / 警告 | `type="warning" plain` |
| 删除 | `type="danger" plain` |
| 中性（编辑、排序、取消、批量修改） | 不写 `type` |

- 窄屏适配用 `useMobile()` 判断；表格在窄屏要固定操作列、隐藏次要列，别让按钮挤成竖排。
- 抽屉里的标题行不要把名字和按钮塞进同一个不换行的 flex——名字加 `white-space: nowrap`，按钮窄屏独占一行。
- 基础配置页以颜色区分本层改动：**蓝色 = 本层新增**（基线里没有这个键），**橙色 = 本层覆盖**（基线里有该键但值不同）。基线 = 上层生效值；引擎默认配置层的基线是程序内置默认值（`GET /api/v1/base-config` 返回的 `inherited` 字段）。改动直接标在表里，页面没有单独的「当前层级改动」小节。
- 改完前端记得 `npm run build`，产物在 `server/app/static`。

## 改完怎么验证

```bash
cd server && ../.venv/bin/python -m pytest tests -q    # 后端测试，应全绿
npm run build                                          # 前端能构建
.venv/bin/python scripts/check_secrets.py              # 凭据扫描
.venv/bin/python scripts/check_engine_defaults.py      # 引擎默认配置与官方文档对账
```

线上数据的自检在部署脚本里自动跑（`scripts/check_data_consistency.py`），也可以手动对线上库跑：

```bash
scp scripts/check_data_consistency.py archon@10.0.1.2:/tmp/check_data.py
ssh archon@10.0.1.2 "docker cp /tmp/check_data.py magicpanel:/tmp/check_data.py && \
  docker exec magicpanel python3 /tmp/check_data.py /app/data/magicpanel.db"
```

## 怎么发到线上

```bash
DEPLOY_PROXY=http://10.0.1.8:7890 bash scripts/deploy.sh          # 带测试
DEPLOY_PROXY=http://10.0.1.8:7890 bash scripts/deploy.sh --fast   # 只改前端时跳过测试
```

`DEPLOY_PROXY` 指向 Mac mini 上的 Stash 混合端口（见[环境与地址速查](reference/环境与地址.md)）。
它是通过 ssh 注入到 **NAS 端 `docker compose build`** 的（构建时要拉 npm/pip 包），
所以必须写 Mac mini 的内网地址 `10.0.1.8`——写 `127.0.0.1` 会让 NAS 连自己、拉包失败。

脚本依次做：跑后端测试 → 同步工作区到 NAS → 重建容器 → 等健康检查 → **跑数据自检** → 验域名。任何一步不过就停。

发完还要发一版订阅：

```bash
# 后台「构建发布 → 创建构建 → 发布至测试 → 发布至生产」
# 或用接口
curl -X POST https://magichub.top:8443/api/v1/builds -H 'Content-Type: application/json' \
  -H "Cookie: mp_session=..." -H "X-CSRF-Token: ..." \
  -d '{"note":"说明这次改了什么"}'
```

验证线上：

```bash
curl -s https://magichub.top:8443/api/v1/setup/status      # 面板活着
ssh archon@10.0.1.2 "docker logs magicpanel --tail 50"      # 看日志
```

**回滚**：面板「构建发布」里「回滚至生产」；代码问题用 `git revert` + 重新部署。

```bash
./scripts/package.sh              # dist/magicpanel-<时间戳>.tar.gz

```

## 硬性约束

这几条是设计决定，破坏它们会直接让客户端加载失败。完整清单见仓库根目录的 [AGENTS.md](../AGENTS.md)，最关键的四条：

1. **结构化内容不能被配置层覆盖。** `proxies` / `proxy-providers` / `proxy-groups` / `rule-providers` / `rules` 这五个键，引擎默认配置 / 引擎平台配置 / 设备独立配置、平台扩展、拓展模块都不许写。服务端硬校验，不是提示。
2. **兜底规则（`MATCH` / `FINAL`）永远在最后。** 规则按 `sort` 排序，兜底之后不能有规则。
3. **列表的合并语义分两种**：引擎默认配置 / 引擎平台配置 = 整体替换；设备独立配置 = 追加。差异计算、层级合并、分发叠加三处必须一致。
4. **设备独立配置的键跟着设备的引擎平台走。** 设备换平台、平台改引擎时要自动换键，否则配置静默失效。

## 常见改动配方

### 加一个新的产物顶层键

1. `server/app/services/base_config.py` 的 `SCHEMA` 里加字段（类型、说明、分组、默认值）。
2. 需要默认开启的，加进 `_COMMON_DEFAULTS` 或引擎专属的 `STASH_*` / `MIHOMO_*`。
3. 跑 `scripts/check_engine_defaults.py`——每个默认键都要能在 `official-example/` 里找到出处。
4. 界面自动出现该参数（表单是 schema 驱动的）。

### 加一个拓展模块预设

1. `src/snippetPresets.js` 的 `SNIPPET_PRESETS` 里加一条（key / name / category / engine / note / content）。
2. 预设内容不许出现结构化内容键。

> 基础配置的预设是另一套，在 `server/app/services/base_config.py` 的 `PRESETS`，不要混。

### 加一条数据自检规则

`scripts/check_data_consistency.py` 里加一段：查出问题写 `problems`（阻断部署），只是提示写 `notes`（不阻断）。规则集合、策略组、规则、设备的引用完整性、命名、冗余覆盖都从这里管。

### 加一个页面

1. `src/views/Xxx.vue`。
2. `src/router.js` 加路由，`src/App.vue` 加菜单项。
3. 后端接口放 `server/app/routers/` 下合适的文件。
4. 窄屏用 `useMobile()` 处理表格与操作列。

### 改产物结构（合并顺序、渲染逻辑）

`server/app/compiler/render.py`。改完必须跑构建并**逐个目标比对产物**，Mihomo 目标还会跑 `mihomo -t` 校验。

## 遇到问题先看哪里

| 现象 | 先看 |
| --- | --- |
| 客户端加载失败 | 构建详情里的校验错误；`server/app/compiler/validate.py` |
| 产物内容不对 | 构建详情的「预览产物」；`render.py` 的合并顺序 |
| 订阅 404 | 令牌被轮换或设备被删；`server/app/routers/feed.py` |
| 测速结果不准 | 系统状态页的「测速链路」；容器代理变量 |
| 端口占用 / 启动失败 | `docker logs magicpanel --tail 50` |
| 定时任务没跑 | 自动构建发布页的开关与运行记录；`scheduler.py` |
