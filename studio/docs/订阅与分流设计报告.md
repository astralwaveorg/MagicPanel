# MagicPanel v2：一份平台模板，多套线路，一个订阅入口

维护者日常只需要回答三件事：哪些域名或地址走哪条策略、当前网络优先走哪些节点、这台设备使用哪个客户端。规则、线路和平台分开存，发布时才组合。用同一组节点服务电信与移动，不需要复制规则库；增加一个 Android 模板，也不需要为三家运营商再做三份。

## 数据如何变成配置

1. 在规则与节点里维护共享规则、策略组、节点和来源；规则按顺序匹配。添加节点时可粘贴链接或 YAML，先在内网转换，预览后保存。可用 MiniMax 起草域名规则、建议节点分组、解释校验结果或提议删除完全重复项；模型不直接发布。
2. 平台模板固定起点为 Windows、macOS、Apple TV、iOS、Android。面板允许从模板复制或粘贴完整客户端 YAML 另建模板。平台不是引擎：Windows/Android 提供 Mihomo 与 Stash，macOS 另提供 Surge 6 和 Surge 5 兼容输出；iOS 提供 Stash、Mihomo、Surge 6、Surge 5 兼容输出与 Shadowrocket，tvOS 提供 Stash 与 Mihomo。Linux 和 OpenWrt 提供 Mihomo 兼容输出。兼容性最终受设备上安装的客户端版本约束。
3. 线路方案独立维护。默认、电信、移动、联通开箱可选，三个运营商先继承默认值。管理员根据该运营商的实际表现，设置某策略组的优先成员、故障切换/手选/测速、规则提前或排除，以及某条规则的去向。可新建方案；基于另一个非默认方案创建时复制其当时的差异，不建立多级继承。平台没有的候选成员不下发。修改前可查看合成的组序与 YAML。
4. 自动或手动发布时，服务器对所有已发布目标的组合编译，检查组循环、无效目标、缺资源和兜底规则；Mihomo 另过部署核心离线校验。只有全部通过，才一次切换到新版本。读取订阅时仅选择该发布里的产物，再应用允许的输出开关；不在请求时抓远程订阅或调用模型。一份平台模板对应多个冻结产物，维护者不必管理这些文件。

## 统一订阅参数

基础地址形如 `/sub/<密钥>`，登录面板后在「订阅地址」复制。默认模板按 `platforms.py` 建立基础适配，`delivery.py` 再生成客户端兼容产物；具体组合能否下载取决于发布内容和目标格式校验，不以固定组合数量作为可用承诺。不为每台设备创建记录，也不会从来访 IP 猜运营商。已发给旧原型的设备地址保留独立兼容通道。

| 参数 | 建议和行为 |
| --- | --- |
| platform | 操作系统：windows、macos、ios、tvos、android；linux、openwrt 提供共享策略的兼容输出；win、mac、appletv 等别名也接受。自定义模板用 template 指定面板标识，页面自动填。 |
| type | 支持 mihomo、stash、surge（或 surge6）、surge5、shadowrocket；组合取决于平台。兼容 type=mac，解释为 macOS 的默认引擎 Stash；macOS 装 Mihomo 时显式传 platform=macos&type=mihomo。 |
| arch | 接受 aarch64、arm64、amd64、x86_64 等 CPU 名，仅作兼容；相同平台/引擎/线路的 YAML 不因 CPU 不同而改变。兼容老写法 arch=win；有矛盾的参数直接报错。 |
| network | 默认 default；内置 telecom、mobile、unicom，也可选管理员新建的方案。名称和 CPU 均不参与选路。 |
| name | 推荐用设备名。只影响下载文件名，不改变节点、更不构成身份或权限。 |
| list | true 只输出 proxies 节点清单；false／省略输出完整配置。不将外部节点提供者伪装成静态清单。 |
| sort | true 按节点名称排序；不改规则顺序、组成员顺序或故障切换优先级。false／省略保留发布顺序。 |
| scv、skip-cert-verify | 两者同义；省略保留节点设置，false 在适用节点启用校验，true 跳过验证，降低 TLS 身份校验强度。只改支持的 TLS 节点，不覆盖 Reality 或指纹固定的节点。 |
| tfo | 仅在 Mihomo 适用 TCP 节点上设置 TCP Fast Open。Stash 的部分 QUIC 协议拥有名称相近但语义不同的选项，不作映射。 |

规范示例（下列仅展示参数；密钥由面板给出）：

- Windows，电信，Clash Verge/Mihomo：`?platform=windows&type=mihomo&network=telecom&name=Office-PC`。
- 同一台 Mac mini 使用移动线路：`?platform=macos&type=stash&network=mobile&name=Macmini`。
- 兼容写法：`?type=mihomo&arch=win&name=Office-PC`；`?type=mac&arch=aarch64&name=Desktop-Mac`。

不接受 emoji、fdn、expand。改名牵涉节点名、组引用和过滤条件；上游 fdn 会过滤已弃用节点，可能影响管理员为某运营商指定的候选；expand 会展开规则集，本版保留版本化资源引用，尤其不能把 MRS 当作文本直接拼入 YAML。未支持、矛盾、重复或非法的参数返回 422，不以“返回了文件”冒充生效。空查询返回 Windows/Mihomo 默认线路。sort 仅影响清单，不能用来测速。共享密钥授权读取全部已发布配置；不要把它当作每用户隔离机制。轮换会使所有统一订阅及其资源地址同时失效。

## 转换器分工与部署

SubConverter-Extended 的 GET /sub 接口已有 target、url 和 config，不需要自动操作网页。发送真实订阅到公共实例等于交给该实例处理；日常构建在 v2 独立 Compose 栈内通过服务名调用转换器，无宿主端口。转换器解析节点，面板负责共享规则、平台模板、运营商差异、发布记录与订阅权限。面板的公开 /sub 不接受任意 url/config，不是公共转换代理。模板导入入口接受最终客户端 YAML 或复制模板；不把任意远程 INI/脚本自动纳入发布。

两个引擎各自生成 YAML。例：Hy2 认证在 Stash 用 auth，Mihomo 用 password；Apple 移动端 Stash 不套用桌面进程规则。不能把同一份 Stash 输出改个文件名就发给 Mihomo。Mihomo 核心测试、Stash 结构检查与真机导入是三个不同层级；服务器无法证明三家运营商上哪台节点最快。
