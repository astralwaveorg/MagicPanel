# 产品定案：以平台模板交付配置

用户 2026-11-28 明确选择五份起始模板：Windows、macOS、Apple TV、iOS、Android。五份模板与使用者无关。这是产品的初始模型，不从旧数据库的设备数或产物数推导。

同平台多个用户默认共享配置；订阅入口共用密钥，名称只用于显示，不作为认证身份。选择平台后，仅在支持多种引擎时选择客户端。引擎差异属于输出适配器，不生成新的业务模板。管理员可从任一模板创建自己的模板、命名并调整规则或分组。自定义模板与系统模板使用相同编辑和发布流程。

日常操作从任务开始。添加规则先写“匹配什么、去哪里”，默认作用于共用方案；例外才指定平台。新增节点先粘贴输入，选择策略组并预览；保持目标引擎各自的节点认证字段。获取配置只需选平台、客户端和线路并复制订阅地址。发布页面关注影响范围、错误位置和能否恢复；维护者无需理解内部适配器编号。

首页采用五张平台卡、生效版本和明显的添加操作。窄屏以单列操作和底部导航为主；高级 YAML、原始资源及诊断信息按需展开。前端改为 Svelte + TypeScript + Vite，组件承担模板卡、表单、筛选、预览及确认，代替原型中的字符串拼装。浏览器仍只接收静态资产，线上无需运行 Node。后端按方案、平台模板、引擎适配器、节点库、设备订阅、不可变发布分工。

## 线路方案与平台模板正交

初始提供默认、电信、移动、联通四个线路选项。三家运营商初始继承默认线路，不宣称某个节点一定更快。管理员在一套线路方案中调整某组的优先候选、手动/故障转移/测速方式、优先命中规则或排除规则。未修改的部分继续继承共用设置。用户可以创建更多自定义线路。模板数量仍是五份，管理界面不得把五个平台乘以四种线路列成二十份模板。

例如，同一个“美国自建”组可在电信设为 A→B，在移动设为 B→A。两台设备都选 iOS 模板，在同一基础地址后指定不同线路，发布时得到不同组序。也可以在同一台手机上保存两个参数组合（例如“家中 Wi-Fi”和“移动数据”），按网络切换；系统不通过 NAS 出口 IP 猜设备所在运营商。改移动方案时，电信与默认方案的配置内容不应改变。变更先保存到草稿，自动或手动校验通过后发布。
