# 客户端适配与协议字段

订阅页提供：选设备，选已安装的应用，复制订阅或打开应用。记住上次的选择，只在本机保存平台、应用和线路，不保存带密钥的地址。首次使用优先识别当前设备。模板、线路、规则、发布记录保留独立入口。

当前各平台的一键导入协议及新增入口见[界面与规则管理验收](界面与规则管理验收.md)。

## 客户端调查

| 应用 | 依据和交付方式 |
| --- | --- |
| Clash Verge Rev、FlClash、Clash Meta for Android | 使用 Mihomo YAML。分别核对 [Verge 注册信息](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src-tauri/tauri.conf.json)、[FlClash Android 注册信息](https://github.com/Vialibrex/FlClash/blob/main/android/app/src/main/AndroidManifest.xml) 和 [CMFA](https://github.com/MetaCubeX/ClashMetaForAndroid/blob/main/app/src/main/AndroidManifest.xml)。已确认的平台使用应用专属的 install-config，其他平台允许手动粘贴。 |
| Clash Mi、ClashX.Meta、Clash Nyanpasu、Clash Party | 从相应项目选择 Mihomo 配置。不借用另一款应用的 URI。参考 [Clash Mi](https://github.com/KaringX/clashmi)、[ClashX.Meta](https://github.com/MetaCubeX/ClashX.Meta)、[Nyanpasu](https://github.com/libnyanpasu/clash-nyanpasu)、[Clash Party](https://github.com/mihomo-party-org/clash-party)。 |
| Stash | 保留 Stash YAML，平台以[官网下载](https://stash.ws/download)为准。macOS 安装包注册了 stash 和 clash scheme；这本身不能证明所有端都能处理同一个导入动作。对未证实的入口提供复制与操作说明。 |
| Shadowrocket | 目标为 iOS/iPadOS。提供含代理、组和规则的 .conf；使用配置导入而非把整个配置当节点订阅。[开发者商店说明](https://apps.apple.com/us/app/shadowrocket/id932747118)、[配置维护手册的协议、组、规则与 URL Scheme 示例](https://github.com/LOWERTOP/Shadowrocket)。 |
| Surge | iOS 和 macOS，使用有更新地址的托管 .conf。保留 Surge 5 兼容输出。Surge 6 的 VLESS 明确要求 iOS 6.0+ 或 Mac 6.12+；更早 Mac 6 可选兼容格式。[托管配置](https://manual.nssurge.com/profile/managed-profile.html)、[URL scheme](https://manual.nssurge.com/tools/url-scheme.html)、[VLESS](https://manual.nssurge.com/policies/vless.html)、[域名匹配](https://manual.nssurge.com/rules/domain.html)。 |

Sub-Store 是订阅管理工具；OpenClash 和 Nikki 归入「其他平台 → OpenWrt」，提供路由器专用的复制入口。应用评分、价格和星数与能否导入无关，不进入页面。

## 配置边界

保留一个基础地址、五份可维护模板和运营商选择。Linux 的兼容输出复用桌面共享策略。原地址和发布记录继续可读。Apple 专用配置从已冻结的平台产物生成；不直接分发 Stash YAML。MRS 在本地使用 [Mihomo 自带的转换命令](https://github.com/MetaCubeX/mihomo/blob/Meta/rules/provider/mrs_converter.go)解为域名或 CIDR，再生成文本规则集。远程规则链接绑定当次发布和密钥。不支持的节点从候选中移除，显示数量；空组拒绝连接，不隐式直连。无法表达的分流规则应阻止对应输出。DNS、MITM、脚本与客户端专属设置不从其他内核照搬。

## 页面设计

暗色为初始主题，浅色为手动选项。首屏突出选择与导入，选项区、主按钮和手动导入说明按任务排序。桌面使用侧栏，手机保留底部导航。用暖白文字、石墨底色和青绿色强调操作；边框、文字、焦点和状态色共用主题变量。原生下拉保留键盘和系统弹层，箭头统一内缩。对话框、按钮和切页使用短动效，遵从系统减少动态效果设置。移除个人示例、宣传用语、重复的英文栏目名。开关说明交代作用范围，地址重置前说明旧链接会失效。

## 认证字段与验证层次

| 协议或能力 | 差异与处理 |
| --- | --- |
| Hysteria2 认证 | 同一条测试 URI 经过私有容器，clash 给 password，stash 给 auth。面板将两种来源认成同一凭据，再按目标输出。值不能缺失；两者都存在时必须完全相同。原值保留，不修剪口令。Surge 的文本配置写 password，Shadowrocket 文本配置写 auth。 |
| 带宽、证书 | Stash 的 up-speed/down-speed 用整数 Mbps；Mihomo 的 up/down 可带单位。转换时核对别名冲突；不将非整数近似成另一档速率。SHA-256 证书固定按引擎选择 fingerprint 或 server-cert-fingerprint；它和模拟浏览器握手的 client-fingerprint 不同。跳过验证开关不覆盖固定证书或 Reality。 |
| Hysteria v1、TUIC | v1 的 auth 可以表示 Base64 字节，auth-str 表示文本，不能套用 Hy2 改名。TUIC v4 使用 token，v5 使用 uuid 和 password；版本或字段矛盾会被拒绝。 |
| VLESS Reality、传输与证书 | 不把要求额外握手能力的节点转成普通 TLS。Surge 5 兼容格式排除 VLESS；无法确认的 Shadowrocket 内联 Reality、证书固定、插件及传输组合也不会入选。当前映射没有覆盖客户端本身支持的所有功能。 |
| 平台设置 | 手机和电视不继承桌面的监听、系统代理和控制端口。OpenWrt 提供独立的 Mihomo 输出，路由器插件负责 TUN、DNS、监听和防火墙。选择 OpenClash 或 Nikki 只生成地址，不应用到设备。 |
| 分流规则 | 保留顺序与最终兜底。转换为 Apple 文本规则集时先解码，绝不把二进制地址当文本。 |

验收分三层：字段和值一致；目标程序能加载；实际认证后能读取指定响应。转换器和源码导入需要核对字段和值。Mihomo 使用部署核心做配置检查。部署脚本在无外网容器内启动两端 Mihomo，用临时证书和随机口令跑 Hy2：正确口令通过隧道读取随机响应，错误口令不能读取。失败则不切换新镜像。这证明特定组合的真实认证，不等同于所有存量节点或设备验收。

Surge 和 Shadowrocket 输出应分别验证配置语法与真实设备行为。格式转换可能过滤目标客户端不支持的节点；页面展示实际保留数和空组数。需要单独导入 Shadowrocket 节点时，可选转换工具里的「Shadowrocket 节点订阅」。
