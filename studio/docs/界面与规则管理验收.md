# 客户端导入与规则管理

## 客户端导入依据

每个按钮按目标应用重新构造订阅参数；只有已发布且可用的目标才可导入。浏览器直接调用本机协议，不经过第三方跳转网站。仅节点列表保留复制和二维码。

| 客户端 | 调用与适用范围 |
| --- | --- |
| Clash Verge Rev、FlClash、Clash Nyanpasu、Clash Mi | 分别用 clash-verge、flclash、clash-nyanpasu、clashmi 的 install-config。依据：[Verge](https://github.com/clash-verge-rev/clash-verge-rev/blob/055dbf5d357cf15b70cb542962a0e232c276a6dc/src-tauri/src/utils/resolve/scheme.rs)、[FlClash](https://github.com/chen08209/FlClash/blob/deba70d80d2af509171f9c6465de9d14719f0399/README.md)、[Nyanpasu](https://github.com/libnyanpasu/clash-nyanpasu/blob/1dde81b8bceec9310ec80b2be286312aa286d986/frontend/nyanpasu/src/utils/deep-link.ts)、[Clash Mi](https://github.com/KaringX/clashmi/blob/b4cec63703c3ff736af235fcde0d44fa74b2e160/lib/screens/scheme_handler.dart)。 |
| ClashX.Meta、Clash Party、Clash Meta for Android | 分别用 clashx、mihomo、clashmeta 的 install-config。[ClashX.Meta](https://github.com/MetaCubeX/ClashX.Meta/blob/471b3e04153655374516b8589cacdb6db373d913/ClashX/AppDelegate.swift)、[Party](https://github.com/mihomo-party-org/clash-party/blob/1458f9626ad4b223424260bf083435b26b435d73/src/main/deeplink.ts)、[CMFA](https://github.com/MetaCubeX/ClashMetaForAndroid/blob/6e635124cc72f8c102b7e76d849c384deba28b3f/README.md)。部分协议也会被其他应用注册，最终接收者由系统决定。 |
| Stash | [官方协议](https://stash.wiki/faq/url-schema)要求把订阅地址整体编码后放入 url 参数。Windows 官方安装包 0.1.47-b51 的注册信息包含 stash 协议，主程序含 install-config；另支持 macOS、iOS。Android 未取得注册证据，使用复制；Apple TV 从电视端添加。 |
| Shadowrocket、Surge | iOS 小火箭使用 config/add 地址后缀；[Surge 文档](https://manual.nssurge.com/tools/url-scheme.html)规定三个斜杠，Mac 旧版入口使用 surgeconfig。新旧 Surge 配置分别指定引擎。 |

## 从仓库维护规则

在「规则与节点 → magic-sets」选择文件。打开的正文绑定到一个 Git blob SHA。修改后先预览差异，再填写提交说明和仅限该仓库的写入令牌，确认后由服务器调用 GitHub Contents API。令牌不存储。其他人若先修改了同一文件，面板要求重新打开；新文件也不能覆盖同名文件。提交历史可在 GitHub 查看。读取和提交都限定在 main 的 rule/ 目录。GitHub REST 达到匿名请求额度时，目录和文件改从同一仓库的公开归档、原始文件读取；写入仍须走带 SHA 校验的 GitHub API。

「应用到草稿」使用 GitHub 当前版本：确认文件摘要、草稿版本、规则类型和目标模板，然后更新同一资源在各模板中的引用。不改运营商方案，不自动插入新的分流匹配条件。新文件须在「规则」中添加 RULE-SET 去向才会匹配流量。来自仓库的文件在仓库页维护，避免本地编辑与 GitHub 出现两份正文。自动发布开启时，合格的草稿会生效。

## 检查最终规则

「规则与节点 → 客户端规则」从生效版本读取匹配顺序和引用的规则集。基础模板维护共享规则；手机上的 Surge、Shadowrocket 可另存仅供该客户端使用的规则，macOS 的 Surge 也可单独维护。专属规则优先于共享规则，不能覆盖其他平台。预览只读规则，不显示节点认证信息。MRS 保留二进制；在 Apple 输出中查看相应文本规则集。

| 规则意图 | Mihomo / Stash 基础输入 | Surge 输出 | Shadowrocket 输出 |
| --- | --- | --- | --- |
| 目的端口 | DST-PORT,443,… | DEST-PORT,443,… | DST-PORT,443,… |
| 所有其他流量 | MATCH,… | FINAL,… | FINAL,… |
| 桌面进程 | PROCESS-NAME,… | Mac 保留，iOS 不分发 | iOS 不分发未证实可用的桌面进程条件 |
| 外部规则集 | YAML payload 或 MRS | 从冻结资源生成不带策略名的文本；配置内的 RULE-SET 指定去向 | 独立转换混合规则中的端口等条件，分发对应文本 |
| 独立的 UDP 条件 | NETWORK,udp,… | PROTOCOL,UDP,… | 顶层 PROTOCOL 未获支持，拒绝生成；逻辑子条件另行转换 |

依据：[Surge 进程规则](https://manual.nssurge.com/rules/process.html)、[协议规则](https://manual.nssurge.com/rules/protocol-and-network.html)、[端口](https://manual.nssurge.com/rules/source-and-port.html)、[规则集](https://manual.nssurge.com/rules/ruleset.html)、[Shadowrocket 配置维护手册](https://github.com/LOWERTOP/Shadowrocket)。编辑器只接受能验证的语法子集。新草稿若使既有客户端输出从可用变为失败，会中止这次发布。历史发布的内容保持不变。

## 验证与预览

验证需要覆盖窄屏布局、键盘操作、认证、并发冲突、跨平台规则隔离、配置下载和发布回退。链接解析及下载验证不能替代真机导入。相关测试见 `studio/tests/` 和 `studio/client/`，命令见 [开发与交付](delivery.md)。

部署使用 STUDIO_DEPLOY_SCOPE=studio。升级规则产物时，先确认生效版本与草稿一致，再运行 studio.promote_rules 并传入预期版本、修订号。它在同一事务中检查基础配置逐字节不变、已有客户端未失效，保留上一个发布供恢复。
